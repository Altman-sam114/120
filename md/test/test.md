# 测试规范

本文指导 Agent B 和 Agent C 为 Rustwar RTS Prototype 选择测试层级、命令和验证范围。

## 固定前缀 / 环境要求

- 项目无构建步骤、无包管理器、无后端、无数据库、无容器依赖。
- 推荐环境：能运行本地浏览器和 Node.js。
- 运行目录：仓库根目录 `/Users/a114514/Desktop/codex/Rustwar`。
- 默认无需启动服务；直接打开 `index.html` 即可运行。
- 如果需要本地 HTTP 访问，可临时使用静态服务器，但不要把服务依赖写入项目运行前提。

## 测试分层

### 1. Probe / Fast

最快发现主链路断点。

触发条件：

- 每次修改 `app.js`。
- 每次修改 HTML 元素 id、脚本引用或入口结构。
- 每次文档-only 修改结束前至少跑 `git diff --check`。

命令：

```sh
node --check app.js
git diff --check
```

当前基线：

- `node --check app.js` 应通过。
- `git diff --check` 应无尾随空白、冲突标记或补丁格式问题。

### 2. Smoke

验证主要集成路径。

触发条件：

- 修改 `index.html`、`styles.css`、输入事件、主循环、渲染、UI 面板、模式切换、保存读取。
- 新增单位、建筑、地图、模式、命令按钮或沙盒功能。

命令 / 操作：

```sh
node --check app.js
git diff --check
```

手动浏览器验证：

- 打开 `index.html`。
- 默认遭遇战进入后 Canvas 有画面。
- 顶部资源、收入、人口和敌军信息刷新。
- 左键可选择单位或建筑。
- 右键可移动或攻击。
- 至少检查一个生产或建造按钮。
- 控制台无明显运行时错误。

当前基线：

- 默认 `skirmish` 模式可进入。
- 主画布、迷你地图、命令面板和顶部栏应显示。

### 3. Stage Regression

覆盖当前阶段核心模块。

触发条件：

- 修改战斗、AI、寻路/移动、战争迷雾、雷达、生产队列、升级、运输、核弹/反核、沙盒导入导出、存档兼容。

命令 / 操作：

```sh
node --check app.js
git diff --check
```

手动浏览器验证按改动模块选择：

- 模式：`index.html?mode=campaign`、`?mode=survival`、`?mode=challenge`、`?mode=sandbox`。
- 地图：`index.html?map=islands`、`?map=lava`。
- 存档：保存后读取，确认状态恢复且无报错。
- 沙盒：放置、删除、冻结/运行、导出 JSON、导入 JSON。
- AI：观察红方生产、扩张或进攻是否仍发生。
- 战斗：投射物、伤害、残骸、护盾、维修或反核按改动点验证。

当前基线：

- README 所列模式和操作应保持可用。
- 战争迷雾下敌方完整外形只在真实视野内显示；雷达只显示信号点。

### 4. Full

全量人工回归。

触发条件：

- 大规模重构。
- 改动 `state` 结构、存档格式、主循环、实体模型、输入体系、渲染顺序。
- 发布正式版本或准备人工验收。

命令 / 操作：

```sh
node --check app.js
git diff --check
```

手动验证：

- 遭遇战、战役、生存、挑战、沙盒全部进入一次。
- 三张地图全部切换一次。
- 选择、框选、双击同类、控制编队、攻击移动、巡逻、护航、停止、回收、运输、核弹、闪现至少按相关可用单位验证。
- 保存/读取和沙盒导入/导出各验证一次。
- 观察 AI 在至少一个普通局中建造或进攻。

当前基线：

- 尚无自动化 Full 测试；必须明确记录手动验证范围和未覆盖项。

## 静态检查

固定命令：

```sh
node --check app.js
git diff --check
```

可选检查：

- 若后续引入 Markdown lint，再补充具体命令。
- 若后续引入格式化、类型检查、端到端测试或截图检查，必须更新本文件基线。

## 规则

- 每次实现前先读本文件。
- 默认从最小测试开始，根据改动范围扩大测试。
- 文档-only 修改可只跑静态检查，但必须说明未跑完整业务测试的原因。
- 不得伪造测试结果。
- 不得把“未发现问题”写成“完整通过”。
- 最终回复必须列出具体命令和结果。
