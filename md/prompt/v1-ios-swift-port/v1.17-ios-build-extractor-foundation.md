# v1.17 / iOS native build Extractor foundation

## Agent B 任务

把 Web 版工程单位在资源点建造 Extractor 的核心语义，小步迁移到原生 Swift/iOS 地基。目标是让原生 iOS 中的己方 Builder 可以点选空闲资源点，扣除金属、创建未完成 Extractor，并由 Builder 靠近后推进建造，形成 `RustwarCore`、SwiftUI HUD、SpriteKit 战场渲染和 Swift tests 都可验收的最小闭环。

## 背景依据

Web `app.js` 的当前行为：

- `buildingTypes.extractor`：`cost=260`、`time=10`、`hp=560`、`size=48`、`income=9`、`vision=240`、`requiresNode=true`。
- `buildMenu` 包含 `extractor`，工程单位通过建造按钮进入放置模式。
- `validatePlacement()` 要求 Extractor 放在资源点附近，拒绝没有资源点、己方已有采集器或敌方占据的资源点。
- `placeBuilding()` 扣除金属、创建未完成建筑，并给当前工程单位写入 `build` 订单。
- `updateBuildings()` 会推进未完成建筑，完成后让 Extractor 认领资源点并开始贡献收入。
- `updateUnits()` 中 `build` 订单会让工程单位靠近未完成建筑并补充建造进度。

原生 v1.16 当前状态：

- `RustwarCore` 已有 `BuildingSnapshot.buildProgress`、`nodeID`、`ResourceNode.claimedBy`、完成建筑收入/人口计算、Builder Repair/Reclaim、Stop、攻击/死亡残骸、生产、AI、Save/Load。
- `GameState` 初始 Extractor 会立刻设置资源点占用；`GameStateEconomy` 只统计 `buildProgress >= 1` 的建筑收入。
- iOS HUD 已有 Move / Attack Move / Patrol / Guard / Repair / Reclaim / Stop / Attack / Rally / Save / Load 等按钮与互斥等待态。
- 还没有 Swift 原生 Build 订单、资源点点选 helper、建造命令按钮或未完成建筑的建造进度推进。

## 目标

1. 在 `RustwarCore` 增加 Extractor 建造定义所需数据：
   - 给 `BuildingDefinition` 增加 `buildTime`，默认值兼容既有定义。
   - Extractor 使用 Web 语义：`metalCost=260`、`buildTime=10`、`hitPoints=560`、`size=48`、`income=9`、`vision=240`。
2. 增加资源点点选/命中 helper：
   - `GameState.resourceTarget(at:maxDistance:)` 或等价方法，返回最近资源点。
   - 只命中合理距离内的资源点，便于 iOS Build Extractor 等待态使用。
3. 增加 `UnitOrder.build(targetID:)` 和 `GameEngine.issueBuildExtractor(on nodeID:)`：
   - 无选择返回 `.noSelection`。
   - 只有当前选中己方 Builder 可建造，其他选择返回专用不可建造结果。
   - 目标资源点必须存在，且不能已有存活 Extractor 或 `claimedBy != nil`。
   - 玩家金属不足时返回专用资源不足结果。
   - 成功时立刻扣除 260 金属，创建己方未完成 Extractor，位置为资源点位置，`nodeID` 为资源点 ID，`buildProgress` 从 0 开始或接近 0，HP 至少为最大 HP 的 10%。
   - 成功时可以立即把资源点 `claimedBy` 设为 `.player`，防止重复下令；收入仍必须等 `buildProgress >= 1` 后才产生。
   - 成功时保持当前 Builder 选择并给它写入 `.build(targetID:)`。
4. `GameEngine.update` 推进 Build 订单：
   - 目标缺失、死亡、非己方或已完成时清除订单。
   - Builder 距离未完成建筑超过约 125 时向目标移动。
   - 进入范围后按可测试速率推进 `buildProgress`；本轮建议单 Builder 使用 `buildProgress += deltaTime / buildTime`，让 Extractor 约 10 秒完成。
   - 未完成建筑 HP 随进度至少维持在最大 HP 的 10%，完成后 `hitPoints = maxHitPoints`、`buildProgress = 1`，资源点保持 `.player`。
   - Stop 必须清除 Build 订单。
   - 未完成 Extractor 被摧毁时必须释放资源点占用，沿用 v1.16 的残骸生成语义。
5. iOS 侧增加 Build Extractor 控制：
   - HUD 在选中己方 Builder 或等待建造资源点时显示 Build Extractor 按钮。
   - Build Extractor 等待态与 Move / Attack Move / Patrol / Guard / Repair / Reclaim / Attack / Rally 互斥。
   - Stop、Load、Restart 和地图切换必须清除 Build Extractor 等待态。
   - Build Extractor 等待态下 tap 主战场资源点，调用 `GameEngine.issueBuildExtractor(on:)`；tap 非资源点给出简短状态提示。
6. SpriteKit 战场渲染：
   - 未完成建筑能看出建造进度，建议在建筑下方或上方增加独立进度条。
   - 对 Build 订单绘制独立命令线和 `B` 或类似建造标记。
7. 如范围可控，原生战术小地图继续用现有资源点/建筑状态自然展示；本轮不要求小地图下达建造命令。
8. 更新 README、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md`、`update_log.md`。

## 非目标

- 不迁移完整 Web 建筑菜单，只做 Builder 建 Extractor。
- 不迁移任意地块建筑放置、建造幽灵、建造范围预览或连续放置。
- 不迁移多 Builder 协同建造、Shift 队列、右键协助未完成建筑、战术小地图下达建造、AI 扩张建造。
- 不迁移其它建筑类型、升级、维修平台、雷达、防御塔或海军/空军/实验工厂建造。
- 不迁移沙盒建筑摆放、战争迷雾、正式粒子/音效或完整 Web build parity。
- 不引入第三方依赖，不使用 `WKWebView` 包装 Web 版。
- 不改变 Web `index.html` / `app.js` 的直接浏览器运行链路；除非确有必要，本轮不改 Web 代码。

## 测试要求

Swift tests 至少覆盖：

- `UnitOrder.build` JSON 往返。
- `issueBuildExtractor` 拒绝无选择、敌方/非 Builder/建筑选择、缺失资源点、已占资源点和金属不足。
- 成功下令会扣除 260 金属，创建未完成己方 Extractor，写入 `nodeID`，认领资源点，并给选中 Builder 写入 Build 订单且保持选择。
- 未完成 Extractor 不贡献收入，完成后才增加玩家收入。
- Builder 对远处 Extractor 下令后先靠近并保持订单。
- Builder 在范围内推进建造进度，完成后 `buildProgress == 1`、HP 回满、订单清除。
- Stop 清除 Build 订单。
- 未完成 Extractor 被摧毁后释放资源点并生成残骸。
- `GameState` JSON 往返保留 Build 订单和未完成 Extractor 状态。
