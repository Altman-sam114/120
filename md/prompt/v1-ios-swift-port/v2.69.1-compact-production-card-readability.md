- 上一轮 Agent C 结论：v2.69 commit `5db992a3325aca239ff5061fffc1f4ccc28c9602` 对应 Actions run `32463246451` / attempt `1` / job `96714367250` 的 artifact `rustwar-ci-v1.2-main-5db992a-run32463246451-attempt1` 自动 CI 全部成功，但人工视觉验收不通过。

## 背景与失败证据

v2.69 artifact 的 manifest、分支、完整 SHA、run id、attempt、JUnit、Xcode 26.5、Swift Core、双架构 iOS build、production/combat 双启动、横屏归一化和 PNG probe 均通过；JUnit 为 `8 tests / 0 failures / 1 skipped`。这些自动结果只能证明构建、启动和基础像素门槛，不能替代内容可读性验收。

Agent C 人工查看该 artifact 的 `ios-home.png` 后确认三列卡片过窄：`Scout` 被显示为 `Sco...`，`Hover`、`Arty` 等名称被压缩为 `H...`、`A...`，锁定原因 `NEED` 也被截断为 `NEED 1...`。因此 v2.69 不能验收通过。`ios-combat.png` 未发现明显回退，Quick Orders、单位模型、弹道、爆点、Tactical Map 和状态栏保持正常。

## 目标

1. 保留 compact、普通 Dynamic Type 下的三列生产网格，但把每张 dense production card 改为清晰的纵向信息栈：单位图标、完整视觉短名称、费用/人口/时间指标、不可用状态。
2. 三列卡必须完整显示现有视觉短名称：`Build`、`Scout`、`Light`、`Hover`、`Arty`、`AA`、`Heavy`、`Boat`；不得以省略号、错误断词或只剩首字母作为正常布局结果。
3. 不可用状态使用固定短标签：金属不足为 `NEED`，人口不足为 `POP`，其它不可用为 `LOCK`。三者必须完整显示，不把金额、人口数字或完整原因继续塞入窄视觉 badge。
4. 完整不可用原因继续由现有 `ProductionAvailability.accessibilityValue` 与 `accessibilityHint` 提供；生产按钮的 VoiceOver label 继续朗读完整单位名、金属、人口和建造时间。视觉短标签不得降低 VoiceOver 信息量。
5. 每张卡继续通过既有 `tacticalControl()` 保持至少 `44pt` 触控目标；按钮 action、disabled 状态和键盘快捷键保持不变。

## 实现要求

- 只调整 `TacticalProductionButtonLabel` 的 dense compact presentation；优先复用现有 `productionIcon`、`denseDisplayName`、`denseMetrics`、`ProductionAvailability` 和 theme token。

  1. icon；
  2. 完整单行短名称；
