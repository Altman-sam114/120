# v1.51 / iOS double-tap same-type selection

## 目标

把 Web 版“快速双击单位选择附近同类型单位”的控制语义迁移到原生 iOS：玩家在主战场连续点按同一个存活己方单位时，原生 iOS 版选择该单位附近一定半径内的存活己方同类型单位，并复用现有多选集合。

本轮目标是补齐触摸选择 parity 的一个小切片，不做完整 Web 选择系统重写。

## 非目标

- 不实现 Shift 追加/反选。
- 不实现控制编队、队形保持、混编建筑框选或攻击姿态切换。
- 不改变 Web `app.js` 行为。
- 不用 `WKWebView` 包装 Web 版。
- 不新增第三方依赖、后端、构建工具或网络依赖。
- 不把双击手势接到战术小地图。

## 实现边界

- Core owns selection semantics；iOS 只负责识别双击并把锚点单位交给 core。
- 新增 core API 应基于单位 ID 或命中结果锚点选择附近同类型己方单位，不直接从 SwiftUI 层改 `selectedEntityIDs`。
- 双击只在主战场普通选择状态生效；当 Move / Attack / Attack Move / Patrol / Guard / Repair / Reclaim / Build Extractor / Turret / Factory / Rally / Select Area 等待态存在时，tap 继续执行原有命令或提示，不触发双击同类选择。
- 双击锚点必须是存活己方单位；点到敌方、建筑、残骸、资源点、空地或已死亡单位时不触发同类选择。
- 选择范围使用 Web 当前双击半径的原生等价：以锚点单位位置为圆心，默认半径 `760` world units。
- 结果只包含存活己方同类型单位，按 `state.units` 顺序写入 `selectedEntityIDs`，`selectedEntityID = ids.first`；空结果清空选择。
- 双击选择不改变任何单位订单；后续 Move / Attack / Attack Move / Patrol / Guard / Stop 等继续复用多选集合。
- 单击选择、拖拽平移、捏合缩放、Select Area 拖拽框选、战术小地图点按和所有待选命令必须保持旧行为。

## 建议改动

- `swift/RustwarCore/Sources/RustwarCore/GameStateSelection.swift`
  - 增加按类型与圆形半径返回 `SelectionTarget` 的 helper，例如 `playerUnitSelectionTargets(matching:near:radius:)`。
- `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`
  - 增加 `selectPlayerUnitsMatching(unitID:within:) -> [String]` 或同等命名 API。
  - API 校验锚点单位必须存在、存活、team 为 `.player`，否则清空选择并返回 `[]`。
- `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift`
  - 覆盖范围内同类型选择、排除范围外同类型/敌方/死亡/不同类型、无效锚点清空、结果顺序、双击选择后复用现有多单位 Move。
- `ios/RustwarIOS/RustwarIOS/GameController.swift`
  - 增加主战场双击检测状态，建议使用时间阈值约 `0.32s` 和屏幕距离阈值约 `44pt`。
  - 在 `handleBattlefieldTap(screenPoint:viewportSize:)` 普通选择路径中识别双击；等待命令或命令目标处理路径不参与双击检测。
  - 双击成功时调用 core API，设置类似 `3 Scouts selected nearby` 的 `commandStatus`，并递增 `renderRevision`。
- `ios/RustwarIOS/RustwarIOS/BattlefieldView.swift`
  - 尽量保留现有单个 `SpatialTapGesture`，不要叠加会与单击竞争的第二个 SwiftUI tap recognizer，除非实现已验证不触发单击副作用。
- 文档同步：
  - `README.md` 写入 iOS 双击同类选择操作。
  - `md/flow/flow.md`、`md/flow/flowchart.md` 写入 core API 和 iOS 输入链路。
  - `md/test/test.md` 写入测试基线。
  - `update_log.md` 追加 v1.51 记录。
