# v2.12 iOS Multi-Touch Box Selection

## 角色与目标

本轮按 Agent A -> Agent B -> Agent C 的职责边界推进，由主线程直接执行，不调用子 Agent。

目标是在原生 iOS 战场增加接近触屏 RTS 的双指框选：两根手指近似同向拖动时显示选择框，抬起后复用现有世界矩形选择；双指明显改变间距时继续捏合缩放。该入口必须让玩家无需先点 `Select Area`，同时保护 v2.11 直接 tap、单指平移、长按上下文和所有 pending 命令。

## 已有事实

- `BattlefieldView` 已有 `SpatialTapGesture`、单指 `DragGesture`、`MagnifyGesture`、长按和显式 `Select Area` 选择框。
- `GameController.handleBattlefieldAreaSelection` 已把屏幕端点转换成 `WorldRect`，再调用 Core 的 `playerAreaSelectionTargets` / `selectPlayerEntities`。
- Core 已实现单位优先、无单位时建筑 bounds fallback，以及 Replace / Add mutation。
- 工程 deployment target 为 iOS 26；SwiftUI `SpatialEventGesture` / `SpatialEventCollection` 可原生提供 touch id、位置和 active/ended/cancelled phase，不需要 UIKit。
- v2.11 已通过 commit `54094955f009396a206e9238bac8b492c3abfaf6` 对应 run `29220827156` / attempt `1` / artifact `rustwar-ci-v1.2-main-5409495-run29220827156-attempt1` 验收。
- 工作区存在用户自己的 `project.pbxproj` 修改和 `.wp`，禁止触碰、覆盖或暂存。

## 实现范围

### `BattlefieldView.swift`

1. 用原生 `SpatialEventGesture` 跟踪恰好两根 touch 的稳定 id、起点和当前位置。
2. 意图未明确前不移动相机、不缩放、不显示框。
3. 两指都移动超过小阈值、方向点积表现为近似同向、两指间距变化受控且质心明显平移时，锁定为框选。
4. 框选区域取两指起点和当前位置四点的屏幕包围矩形，复用 `SelectionBoxOverlay`。
5. 两指间距明显变化、方向明显相反时判为 pinch，并让既有 `MagnifyGesture` 继续负责 zoom；框选不得执行。
6. 两指识别开始后停止继续消费单指 pan；双指序列产生的后续 tap 和 long press 必须被抑制，避免误发 v2.11 Attack / Attack Move 或上下文命令。
7. 第三指、touch cancellation、地图重开/切换或其它拒绝态必须清空预览和追踪状态，不产生选择。
8. pending 命令优先：任意 `isAwaitingTargetCommand` 为 true 时不得锁定无等待态双指框选。显式 `Select Area` 仍由原单指 drag 完成。

### `GameController.swift`

1. 抽出显式框选和双指框选共用的私有区域选择实现。
2. 保留屏幕到世界坐标、Core unit-first/building-fallback、Replace/Add、status、selection/warning feedback 和单次 render revision。
3. 新增无等待态双指入口，并以 `!isAwaitingTargetCommand` 为 controller 侧最终门控。
4. 成功框选时清理旧双击候选，避免下一次 tap 误判为同类双击。
5. 不新增 Core 状态、存档字段、UIKit recognizer、timer、第三方依赖或第二套选择真源。

## 非目标

- 不修改 Core 选择算法、命令订单、战斗、AI、经济、存档或 Web。
- 不调整 HUD hierarchy；建筑 Production / Build & Upgrade 前置留给下一轮。

- 不把双指框选改成双指相机平移。
- 不声称固定暂停首屏截图能证明多指交互。

## 风险与约束

- `SpatialEventGesture` 和 `MagnifyGesture` 同时识别，必须用明确的 intent gate 避免同一序列同时选择和缩放。
- `DragGesture` 可能先收到第一根手指；第二根触点出现后至少要停止后续 pan delta，并重置累计 translation。
- `SpatialTapGesture` 可能在多指结束后发出 tap；抑制窗口必须能挡住同一序列的多个 tap，而不是只消费一次。
- 选择框必须 `allowsHitTesting(false)` 并保持 VoiceOver 隐藏；现有 overlay 已满足。
- 默认云端 screenshot 不驱动触摸，交互验收只能依赖代码路径、双架构 build 和既有 Core suite，并保留真机手势风险。
