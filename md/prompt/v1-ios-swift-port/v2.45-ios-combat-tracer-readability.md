# v2.45 iOS combat tracer readability

## 版本分配依据

- `v2.45` 开启 v2.44 输入收敛后的下一 presentation 小轮次；最新 v2.44.4 已通过云端 gesture 修复和最终文档复验，本轮只优化固定战斗截图中弹道/能量束的视觉层级。

## 背景

- 最新 cloud combat PNG 已证明战斗模型、弹道、爆点和 HUD 可见，但 Hover 白色 beam 与 Heavy/Tank/Artillery/Gunboat 尾迹在密集场景中略抢过单位轮廓。
- `BattlefieldScene` 已有 bounded effect/decal 上限、Reduce Motion 分支和 frozen combat fixture；应沿用现有 path 参数，避免新增瞬态状态或改变 Core 事件时序。

## 目标

- 将 Hover beam 的 glow 从 `width * 3` 收到 `width * 2.5`，glow alpha 从 0.36 收到 0.30，Hover `beamWidth` 从 3 收到 2.5；白色 core 保持 0.92 和原生命周期，保留青色武器识别。
- 将 Tank / Heavy Tank / Artillery / Gunboat 的 projectile trailLength 分别从 12 / 21 / 18 / 14 收到 10 / 16 / 14 / 11，保留不同炮种的长度层级、vapor/main trail 结构和 `addBoundedEffect` lifetime 0.5。
- 不改炮口 flash、爆点 z 层级、impact/destruction lifetime、effect/decal cap、Reduce Motion、命中时序、Core、战斗数值、选择、HUD、存档或 fixture 状态。

## 非目标与边界

- 只修改 `ios/RustwarIOS/RustwarIOS/BattlefieldScene.swift`、本提示词及本轮必要文档；不修改 `RustwarCore`、`GameController`、`BattlefieldView` 或战斗数据。
- 不新增 SpriteKit 节点、计时器、随机数、纹理、第三方依赖或新的模型字段；不重排 impact/destruction 的现有层级。
- 不运行本地测试、格式检查、Swift/Xcode build、Simulator、Preview、截图或 `git diff --check`；唯一验证来源是 GitHub Actions artifact。

## 当前架构依据

- `spawnUnitFireEffect` 只为单位选择确定性的 color/radius/trail/beam 参数，`spawnFireEffect` 负责现有 muzzle、projectile 或 beam presentation。
- `addProjectileEffect` 和 `addBeamEffect` 只创建 bounded visual nodes，不修改 Core cooldown、HP、目标或伤害。
- 固定 combat visual smoke 使用同一 `BattlefieldScene` presentation helper；Home PNG 不应变化。

## 实现步骤

1. 在 `spawnUnitFireEffect` 仅调整四类单位的 `trailLength` 和 Hover `beamWidth` 常量。
2. 在 `addBeamEffect` 仅调整 glow alpha/line width 比例，保持 white core、line cap、fade duration 和容器上限不变。
3. 复查 `spawnImpactEffect` / `spawnDestructionEffect` 层级和 lifetime 不变；不为了本轮目标加入爆点 alpha 变更。
4. 让 Agent C 用最新 combat PNG 与前一轮 SHA/metrics 对照，确认 beam/tracer 变细但仍可辨，Home PNG 与战斗逻辑无回退。
