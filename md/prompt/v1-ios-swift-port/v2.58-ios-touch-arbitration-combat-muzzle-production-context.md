# v2.58 Tactical Map arbitration, combat muzzle anchors, and production context

## 版本与轮次

- 版本：`v2.58`
- 主题：修正 Tactical Map 长按串发、对齐战斗炮口反馈、恢复生产上下文条
- 目标分支：`main`
- 实现提交信息：`v2.58: refine touch arbitration combat muzzle and production context`
- 前置：v2.57 pending Extractor 资源点命中区已在最新 `origin/main` 完成云端验收。

## 本轮目标

1. Tactical Map 长按上下文命令成功识别后，释放阶段不得再次被同一 `DragGesture` 当作普通 tap，避免上下文命令与居中/点位命令串发；普通 tap、相机拖动、等待态 target tap、可见性和 accessibility 语义保持。
2. 原生 SpriteKit 弹道从模型化炮口附近开始：重坦、火炮、Gunboat 使用按单位类型缩放的 muzzle distance，Turret 对齐现有炮管末端；炮口闪光、tracer/beam 和终点反馈继续共享同一 origin。
3. 选中己方生产建筑时，在 Production section 标题下直接显示既有只读 `NOW / QUEUE / UPGRADE` focus summary，再显示 Factory Tech、生产入口、队列和管理按钮；不改生产命令、队列、升级、快捷键或存档。

## 非目标与架构边界

- 不修改 `RustwarCore`、GameState、UnitOrder、命中/伤害/冷却/AI、JSON/save schema 或 Web 版。
- 不引入 UIKit、第三方框架、纹理资源、随机数、定时器或新的 projectile event model。
- 不改变 Tactical Map 普通点按居中、拖动相机、pending target 命中半径、TouchSequenceOwner 或 Battlefield 主战场手势。
- 不让生产 focus summary 成为可操作的第二套命令入口；所有按钮继续调用既有 controller action。
- 保留未跟踪 `.wp`，不提交、不删除。

## 实现契约

- `TacticalMapView` 以触摸起点和 `@GestureState` 生命周期记录长按已识别状态；`mapGesture.onEnded` 在该状态下只清理，不调用 `handleTap`，长按成功后也不得继续拖动 Tactical Map 相机，手势取消必须清除起点/flag；下一次独立触摸必须恢复普通 tap。
- `BattlefieldScene` 的 muzzle 修正只作用于 `spawnUnitFireEffect` / `spawnBuildingFireEffect` 的 presentation 参数：重坦 `1.44r`、Artillery `1.22r`、Gunboat `1.04r`，Gunboat 可见炮管延伸到船体前缘并带炮口 collar，Turret 使用炮管末端比例，并扣除同帧 weapon/turret recoil；`addProjectileEffect`、终点层、Reduce Motion、bounded effect 上限和雾层顺序保持。
- `TacticalProductionSectionView` 仅在单一己方 `productionFocusBuildingName` 有值时挂载 `TacticalProductionFocusSummaryView`，复用 `GameController` 的 producer-generic 派生值；单位/建筑混选不得显示生产操作，Command Center 不得伪装成 Factory Tech，且不重复生成 Build 列表或写入状态。
