# v1.23 / iOS tactical map pending command feedback

## Agent B 任务

在 v1.20-v1.22 战术小地图命令入口基础上，补齐等待命令的可见反馈：当 iOS 正在等待 Move / Attack Move / Patrol / Rally 点位、Reclaim / Build Extractor Builder 目标，或 Attack / Guard / Repair 实体目标时，战术小地图必须清楚显示当前待命令状态，并向 VoiceOver 暴露同一语义。

## 背景依据

- v1.20 已支持小地图 Move / Attack Move / Patrol / Rally 点位命令。
- v1.21 已支持小地图 Reclaim / Build Extractor Builder 目标命令。
- v1.22 已支持小地图 Attack / Guard / Repair 实体目标命令。
- 当前小地图只有静态 accessibility hint，玩家无法从小地图本身确认正在等待哪类目标。

## 目标

1. 在 `GameController` 暴露只读派生文案，描述当前战术小地图 pending 命令：
   - 无 pending：小地图点按用于居中相机。
   - 点位命令：Move / Attack Move / Patrol / Rally。
   - Builder 目标命令：Reclaim / Build Extractor。
   - 实体目标命令：Attack / Guard / Repair。
2. 在 `TacticalMapView` 显示紧凑的 pending 命令反馈：
   - pending 时用明显边框或角标提示小地图处于下令状态。
   - pending 时显示短标签或符号，避免遮挡小地图实体。
   - 无 pending 时保持旧小地图视觉。
3. 更新小地图 accessibility：
   - 无 pending 时说明点按会居中相机。
   - pending 时说明点按会下达当前命令，并写清目标类型。
   - Canvas 内视觉反馈不得成为唯一语义来源。
4. 不修改 `RustwarCore` 命令、命中半径、目标合法性、战斗、建造、回收或经济规则。
5. 更新 README、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和 `update_log.md`。

## 非目标

- 不新增小地图放大镜、目标吸附、目标确认弹窗或拖选框。
- 不新增多单位命令、队形命令、右键上下文命令或队列/Shift 命令。
- 不新增 iOS UI 自动化测试 target。
- 不改变 Web `index.html` / `app.js` 直接浏览器运行链路。
- 不引入第三方依赖，不使用 `WKWebView`。
