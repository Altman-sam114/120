# v1.43 / iOS native multi-unit Repair

## Agent A 目标

把原生 iOS 迁移地基中的 Repair 命令从 primary selection 单 Builder 语义升级为多 Builder 选择语义，使它与 v1.39 Move / Stop、v1.40 Attack-Move、v1.41 Patrol 和 v1.42 Guard 的多选命令行为保持一致。

本轮只推进 Repair parity，不改 Web 原型，不引入新架构，不扩大到 Reclaim / Build / Attack / drag-box selection 等其它命令。

## 背景

当前 `GameEngine.issueRepair(targetID:)` 只读取 `state.selectedEntityID`，因此 Idle Builders 批量选择后只能让 primary Builder 维修目标。v1.38 已提供 `selectedEntityIDs` 多选集合，v1.39 到 v1.42 已验证 `selectedCommandEntityIDs()` 和选择过滤 helper，本轮应沿用这些模式。

Repair 与 Guard 一样是实体目标命令，但目标必须是受损友方单位或建筑。多选时应让所有选中己方 Builder 维修同一受损友方目标；若目标本身也在 Builder 选择集合中，目标自身不能维修自己，应被跳过，其它选中 Builder 仍可维修该目标。

## 实现范围

### Swift Core

修改 `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`：

- `issueRepair(targetID:)` 必须先使用 `selectedCommandEntityIDs()` 判断是否存在可用选择，保持无选择时返回 `.noSelection`。
- 新增或复用 helper 过滤当前选择中的己方 Builder。
- 选择集合存在但没有己方 Builder 时返回 `.selectedEntityCannotRepair`。
- 目标必须是存活、受损、友方单位或建筑；敌方、缺失目标、满血目标仍返回 `.invalidRepairTarget`。
- 多选时，对所有选中己方 Builder 写入 `.repair(targetID:)`，目标 id 相同。
- 若目标单位本身也在选择集合中，跳过该 Builder，避免自我维修；若跳过后没有任何 Builder 可下令，返回 `.invalidRepairTarget`。
- 不改变 `UnitOrder.repair` 数据结构、Repair 推进逻辑、125 范围、18 HP/s 维修速率、目标消失清理、JSON 存档形状或红方 AI Repair。

### iOS App

修改 `ios/RustwarIOS/RustwarIOS/GameController.swift`：

- `canIssueRepair` 改为使用当前多选集合中的己方 Builder。
- 增加 `selectedPlayerBuilders` helper，语义与 `selectedPlayerUnits` 一致，只过滤 `.builder`。
- `toggleRepairCommand()` 的等待态文案在多选时显示 Builder 数量，例如 `Repair target for 3 builders`。
- `statusText(forRepair:)` 在 `.issued` 时根据当前选中己方 Builder 数量返回单/多单位反馈，例如 `Repair order issued to 3 builders`。
- 主战场 tap 和战术小地图实体命中继续复用现有 `handleSelectionTargetCommand(at:)` 和 `engine.issueRepair(targetID:)`，不新增 UI 分支。

### Tests

修改 `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift`：

- 增加多选 Builder group 下达 Repair 后，所有选中己方 Builder 均获得 `.repair(targetID:)` 的测试。
- 覆盖混合选择中包含不存在 ID、敌方 ID、非 Builder 单位或建筑 ID 时，只命令有效己方 Builder 并返回 `.issued`。
- 覆盖选择集合存在但没有己方 Builder 时返回 `.selectedEntityCannotRepair`。
- 覆盖多选中包含维修目标自身时跳过自我维修，但其它选中 Builder 仍获得 Repair。
- 覆盖仅选中目标 Builder 自身时返回 `.invalidRepairTarget`。
- 补充 Stop 对多选 Repair 的清理测试，确保 `issueStop()` 只清除选中 Builder 的 Repair 订单，不影响未选中单位。
- 保持既有单 Builder Repair、Repair 目标推进、满血清理、毁灭清理和 JSON 往返测试通过。
