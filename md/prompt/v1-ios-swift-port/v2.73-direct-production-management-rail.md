# v2.73 Direct production management rail

## 版本与轮次

- 版本：`v2.73`
- 总目标 X：持续把原生 iOS RTS 的操作、UI、模型和战斗视觉迭代到比 Rusted Warfare 更直接、更清晰且更精细。
- 当前轮次：减少生产建筑管理动作的滚动和重复点击，把 Repeat 改为直接目标选择，并把管理动作提升到完整队列之前。
- 上一轮基线：v2.72 最终文档 commit `fe13e1b8cfd25ba20a26c4d9989e4c67619a9cd1` 对应 Actions run `32636336647` / attempt `1` 的 artifact 已通过；本轮不得复用该旧 artifact 作为实现证据。

## 背景与问题

当前 `TacticalProductionSectionView` 按 `summary -> Factory Tech -> production options -> full queue -> Cancel/Repeat/Rally` 排列。队列较长时，三个 producer 管理动作被推到更深处；Repeat 又以单按钮循环 `Off -> unit 1 -> unit 2 -> ... -> Off`，切换到明确单位需要多次点击，和 Rusted Warfare 的直接生产管理手感仍有差距。

Core 已有 `GameEngine.setRepeatProduction(_:)`，`BuildingSnapshot.repeatUnitType` 也已进入既有 Codable 状态。v2.73 应复用这些权威状态与结果，不新增第二套选择状态、存档字段或生产规则。

## 目标

1. 将 producer 管理层级改为 `Production header -> management rail -> summary -> Factory Tech -> production options -> queue`，让 Cancel、Repeat、Rally 无需滚过单位卡或完整队列即可直接触达。
2. Repeat 改为显式 `Menu`：提供 Off 与当前生产建筑全部合法 `productionOptions`，一击选择目标，当前项具有 checkmark/filled repeat 等非颜色状态线索。
3. compact、普通 Dynamic Type 下把 Cancel / Repeat / Rally 收敛为三列紧凑 rail；regular 沿现有命令列数布局，accessibility Dynamic Type 使用单列自然换行。
4. 三个控件都严格保持至少 44pt；Cancel 无队列时保留稳定位置但 disabled；Rally 等待目标时继续显示 Cancel 与 active 状态。
5. 保留 Shift+C、Shift+P、Shift+R：Shift+P 现在聚焦/打开直接 Repeat menu，不再暗中循环目标；Shift+1-9 的生产顺序与入口不变。
6. 为 Repeat menu、Cancel 和 Rally 提供完整 VoiceOver label/value/hint；可见 compact 文案允许短化，但 VoiceOver 必须朗读完整单位名和当前/等待状态，当前 Repeat 菜单项还必须带 selected trait/value。

## 实现要求

### `GameController.swift`

- 新增直接 presentation action，例如 `setRepeatProduction(_ unitType: UnitType?)`，只调用既有 `engine.setRepeatProduction`，并沿用 `statusText`、command feedback 和 `renderRevision`。
- 保留既有 `cycleRepeatProduction()` 作为兼容入口或将其改为调用新的直接 action；不得复制 Core 校验、修改生产顺序或绕过 `ProductionRepeatResult`。
- `productionOptions`、`repeatProductionUnit`、完整 accessibility value 和既有 save/load 状态继续是单一事实来源。

### `TacticalProductionManagementRail.swift`

- 新建独立 SwiftUI `View`，不要把新的 rail 继续塞进已经较长的 production section body。
- Repeat 使用 `Menu` 而不是在 view body 中构造 `Binding(get:set:)` 的 Picker；菜单包含 Off、分隔线和 `controller.productionOptions`，每项调用直接 set action。
- 当前 repeat 目标必须同时有文字/图标状态，不得只靠颜色；Menu trigger 显示 `Repeat` 与当前短值，VoiceOver 朗读完整值和“选择重复生产目标”的提示。
- compact 普通字号使用三列；accessibility Dynamic Type 单列；其它布局沿调用方列数，所有控件复用 theme/tactical control 并保持至少 44pt。
- Cancel 始终显示、无队列时 disabled；Rally 等待时复用 `toggleRallyCommand` 取消，视觉 active/Cancel 与 VoiceOver value/hint 同步。
- Button/Menu action 提取为方法或直接 method reference，避免在 `body` 混入非必要业务逻辑；不引入 UIKit、第三方依赖或新状态对象。

### `TacticalProductionSectionView.swift`

- 删除原末尾的内联 Cancel/Repeat/Rally grid，改为紧随 Production section header、在 summary 与 production options 前挂载 `TacticalProductionManagementRail`。
- 三列生产卡、Factory Tech 条件、queue item 顺序、availability disabled、Shift+1-9、44pt 与 regular/accessibility 标签路径不变。

### Xcode project

- 把新 Swift 文件加入 RustwarIOS group 与 Sources build phase；只做确定性的最小 project 条目修改。
