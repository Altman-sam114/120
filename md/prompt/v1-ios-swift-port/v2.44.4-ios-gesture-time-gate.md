# v2.44.4 iOS gesture time gate and true multitouch suppression

## 版本分配依据

- `v2.44.4` 延续 v2.44 的 iOS 输入精修小版本；上一轮 `v2.44.3` 已完成 pan/tap 持久取消和触摸序列世代保护，本轮只收敛其剩余的多指结束误判与迟到 context 回调。

## 背景

- `SpatialEventGesture` 会同时观察普通单指触摸。其 `onEnded` 不能被默认当成多指结束，否则快速普通 tap 可能被无条件建立的 0.32 秒 suppression 吞掉。
- SwiftUI `DragGesture.Value.time` 是可用的 `Date` 事件时间。当前 context `onChanged` / `onEnded` 没有时间门控，地图 reset、双指结束或新触摸开始后，迟到的旧回调仍可能覆盖新 context 状态。
- v2.44.3 已用 `SpatialEventCollection.Event.ID` 派生 `battlefieldTouchSequence`，但 CI 没有 XCUITest，无法证明所有触摸取消和回调顺序。

## 目标

- 只有存在真实双指/多指序列时，才建立多指 tap suppression；普通单指 `SpatialEventGesture` 结束不得无理由吞 tap。
- 继续为每次 Spatial touch finish 推进 `battlefieldTouchSequence`，让 context 手势可以从上一段触摸中重新播种。
- 为 context `onChanged` / `onEnded` 增加基于 `DragGesture.Value.time` 的迟到事件门控：旧时间戳不能清理、覆盖或重新激活较新的 context 手势。
- 地图 reset 发生在活动手势期间时记录取消时间；取消前产生的旧 context 回调必须被丢弃，新触摸在触摸序列世代变化后可以恢复 tap/long-press。
- 保持单指 tap、单指 pan、长按上下文命令、Select Area、双指框选、捏合缩放、pending target command、Replace/Add、建筑生产 dock、控制编队和既有 Core/存档合同不变。

## 非目标与边界

- 只修改 `ios/RustwarIOS/RustwarIOS/BattlefieldView.swift` 与本提示词；不修改 `RustwarCore`、`GameController`、`BattlefieldScene`、模型、HUD、命令数值、生产/升级或存档格式。
- 不新增 UIKit recognizer、timer、Task、随机数、第三方依赖或业务状态；只使用现有 SwiftUI gesture value、`Date` 和触摸代际状态。
- 不按时间戳伪造触点 ID。若 `SpatialEventGesture` 完整 finish 丢失且旧手指与新手指无法由 SwiftUI 暴露的 ID 区分，保守拦截旧取消序列，并在日志记录这是静态 CI 无法证明的残余边界。
- 本轮禁止本机测试、格式检查、Swift/Xcode build、Simulator、Preview、截图或 `git diff --check`；只通过 GitHub Actions 云端验证。

## 当前架构依据

- `BattlefieldView` 是 SwiftUI 手势入口；`tapGesture`、`contextLocationGesture`、`dragGesture`、`magnifyGesture` 和 `SpatialEventGesture` 通过现有 `@State` 协调，不直接修改 Core。
- `battlefieldTouchSequence` 是触摸世代；`contextGestureTouchSequence`、`contextGestureGeneration`、`contextGestureCancelled` 和 `cancelledContextTouchSequence` 用于拒绝 reset 后的旧 context 回调。
- `finishMultitouchSelection` 负责 Spatial touch finish 的预览结算、选择派发、触摸 ID 清理和下一段世代推进。

## 实现步骤

1. 在 `finishMultitouchSelection` 结算并保存 `hadMultitouchSequence`，来源应包括活动多指状态、至少两个已跟踪触点或结束事件中的至少两个唯一 touch ID。
2. 无论是否多指，清理 Spatial touch 状态并递增 `battlefieldTouchSequence`；仅在 `hadMultitouchSequence` 为真时调用 `suppressTapAfterMultitouch()`。
3. 新增 context 事件时间状态：当前手势开始时间、最近一次事件时间、活动 reset 的取消时间。`onChanged` 和 `onEnded` 入口先拒绝早于最近事件、早于当前手势开始或不晚于取消时间的回调。
4. 新 context 序列接受第一个合法时间戳后更新开始时间并清除取消哨兵；合法 `onEnded` 只清理仍处于活动状态且未被更晚事件覆盖的 context。
5. `cancelSelectionGestures` 在活动手势 reset 时设置取消时间并保留取消序列；无活动 reset 不建立 tap suppression，也不阻塞下一次合法 tap。
6. 保持既有多指 intent classifier、目标等待态和地图 reset 语义；不把时间值当作唯一 gesture ID。
