# v1.70 / iOS native visibility fog foundation

## 角色

你是 Agent B，负责在 `main` 上实现本轮 v1.70。开始前必须阅读 `README.md`、`AGENTS.md`、`update_log.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和本提示词，并先执行 `git fetch origin`、`git switch main`、`git pull --ff-only origin main`、`git status --short --branch`。

## 目标

为原生 Swift/iOS 迁移地基补上玩家当前视野和战场雾层的第一步：`RustwarCore` 根据已有单位/建筑 `vision` 字段计算玩家可见 tile，iOS SpriteKit 战场在不可见 tile 上绘制轻量暗色雾层。

- 复用 `UnitDefinition.vision` 和 `BuildingDefinition.vision`，不新增存档字段。
- 存活己方单位提供当前视野；存活、完成状态的己方建筑提供当前视野；未完成建筑不提供视野。
- 视野按 `TerrainGrid` tile 计算，只要 tile 中心落入任一视野圆就视为可见。
- iOS 主战场绘制不可见 tile 的半透明暗色 overlay，当前可见区域保持现有地形、资源、单位、建筑、残骸和命令线可读。
- 该轮先不隐藏敌军实体和小地图目标，只建立可见 tile 计算和主战场视觉反馈。

## 非目标

- 不修改 Web `app.js`。
- 不实现已探索/战争迷雾记忆、雷达远距信号、敌方目标隐藏、选择/命中限制、AI 情报限制、战术小地图雾层或存档中的 explored grid。
- 不新增 build tool、网络依赖、资源文件或 iOS UI 按钮。
- 不改变移动、攻击、生产、建造、存档、AI、选择、多选、控制编队或现有命令语义。
- 不用 `WKWebView` 或网页包装。

## 实现建议

- `swift/RustwarCore/Sources/RustwarCore/VisibilitySnapshot.swift`
  - 新增轻量 `public struct VisibilitySnapshot: Equatable, Sendable`，保存 `columns`、`rows` 和内部可见 tile 索引集合。
  - 提供 `isVisible(column:row:)`、`isVisible(at:)`、`visibleTileCount` 等只读 API。
- `swift/RustwarCore/Sources/RustwarCore/GameStateVisibility.swift`
  - 新增 `public extension GameState { func visibility(for team: Team) -> VisibilitySnapshot }`。
  - 收集该 team 的存活单位和存活且 `buildProgress >= 1` 的建筑作为 vision sources。
  - 对每个 source 只扫描其 vision 半径覆盖的 tile bounding box，再用 tile 中心到 source center 的距离判断可见，避免全图全 source 暴力乘积。
  - 空 source 时返回全不可见 snapshot；越界查询返回 false。
- `ios/RustwarIOS/RustwarIOS/BattlefieldScene.swift`
  - 增加 `fogNode`，放在资源/实体之上。
  - `renderNow()` 在 `drawEntities(state)` 后调用 `drawFog(state.visibility(for: .player))`。
  - 用单个 `CGMutablePath` 聚合不可见 tile rect，再创建一个半透明黑色 `SKShapeNode`；不要每个 tile 创建一个 node。
  - overlay alpha 控制在能看出雾层但不破坏当前调试可读性的范围，例如 0.42-0.55。
