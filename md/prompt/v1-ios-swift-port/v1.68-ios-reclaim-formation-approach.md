# v1.68 / iOS native reclaim formation approach

## 角色

你是 Agent B，负责在 `main` 上实现本轮 v1.68。开始前必须阅读 `README.md`、`AGENTS.md`、`update_log.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和本提示词，并先执行 `git fetch origin`、`git switch main`、`git pull --ff-only origin main`、`git status --short --branch`。

## 目标

把 v1.67 的“多 Builder 围绕目标分散接近”继续扩展到原生 Swift core 的多 Builder Reclaim 执行阶段：多个 Builder 回收同一个有效残骸且仍在回收范围外时，应分散靠近残骸周边，而不是全部朝残骸中心叠在一起。

- 保持 `UnitOrder.reclaim(wreckID:)` 存档形状和 `GameEngine.issueReclaim(wreckID:)` 对外 API 不变。
- 单 Builder Reclaim 保持原行为：距离超过回收范围时朝残骸中心靠近，进入范围后转移金属。
- 多 Builder Reclaim 同一残骸时，在 `updateReclaimOrder` 中动态计算每个 Builder 围绕残骸的稳定接近点；Builder 进入回收范围后仍按既有速率共同回收同一残骸。
- 接近点应按 Builder 当前状态中的稳定顺序生成，围绕残骸中心分散，并 clamp 到地图内。
- iOS 现有 Reclaim 按钮、主战场 tap、长按残骸、战术小地图残骸目标和外接键盘入口都应自然复用，不新增 UI。

## 非目标

- 不修改 Web `app.js`。
- 不修改 `UnitOrder.reclaim` 的 Codable 形状，不新增存档字段或命令类型。
- 不改变 Reclaim 合法性、回收范围、回收速率、金属转移、TTL 保活、残骸耗尽/过期/消失清理、多 Builder 是否可同时回收同一残骸等既有语义。
- 不实现 Repair/Build 之外其它队形、完整寻路、碰撞避让、动态阵型朝向、Shift 队列、右键上下文 parity、沙盒残骸编辑或 UI 自动化。
- 不用 `WKWebView` 或网页包装。

## 实现建议

- `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`
  - 保留 `issueReclaim(wreckID:)` 和 `UnitOrder.reclaim(wreckID:)` 不变。
  - 增加 private helper，例如 `reclaimApproachPoint(for:wreck:)`，或抽出能被 Repair / Reclaim 复用的 support formation helper；只在真实降低重复且不扩大范围时抽象。
  - helper 在更新时查找所有当前正在 `.reclaim(wreckID:)` 且可回收同一残骸的存活 Builder。只有 1 个 Builder 时返回残骸中心以保持旧行为。
  - 多个 Builder 时，复用或仿照 `formationTargets(for:around:)` 的排序/间距，生成残骸周边分散点；点位应至少位于残骸边缘外，并在 `builderReclaimRange` 内，使 Builder 到位后可以执行回收。
  - `updateReclaimOrder` 距离判断仍以 Builder 到残骸中心是否超过 `builderReclaimRange` 为准；超过时向该 Builder 的分散接近点移动，进入范围后执行原金属转移逻辑。
- `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift`
  - 增加测试覆盖：多 Builder Reclaim 同一有效残骸时，远距更新后多个 Builder 的位置不再完全相同。
  - 保留或补充单 Builder Reclaim 仍朝残骸中心靠近的断言。
  - 旧语义仍应通过：非法/空/过期目标拒绝、残骸耗尽不超额计入金属、目标消失清理、Stop 清除、多选混入无效对象等。

## 验收标准

- 选择多个己方 Builder 回收同一个有效残骸时，远距 Builder 不再全部朝同一个残骸中心点移动。
- 单 Builder Reclaim、无选择、非 Builder、敌方或建筑选择、空残骸、过期残骸、残骸耗尽清理等旧结果保持不变。
- 不改变 `GameState` JSON / `UnitOrder` Codable 兼容性。
- iOS 现有 Reclaim 入口无需新增按钮即可复用新 core 行为。
