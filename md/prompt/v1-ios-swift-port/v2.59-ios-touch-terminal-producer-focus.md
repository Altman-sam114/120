# v2.59 iOS touch terminal safety, combat spark spread, and compact producer focus

## 版本与轮次

- 版本：`v2.59`
- 主题：多指结束安全收尾、战斗受击火花完整分布、compact 生产上下文首屏压缩
- 目标分支：`main`
- 实现提交信息：`v2.59: stabilize touch terminal and producer focus`
- 前置：v2.58.1 源码修复已提交，但待最新 `origin/main` Actions artifact 验收。

## 本轮目标

1. 多指 `SpatialEventGesture.onEnded` 无法同步当前事件帧时，避免遗留多指 owner 吞掉下一次单指点选；迟到旧 callback 不得清理新鲜单指序列。
2. 受击火花从半圆修正为确定性的完整 360° 分布；残骸本体和 salvage bar 随同一 TTL alpha 淡出，提升战斗场景层级一致性。
3. compact producer focus 在不改变 action 或 VoiceOver 完整语义的前提下，以 `ViewThatFits` 优先显示 NOW / QUEUE / UPGRADE 两行三列摘要，让 Factory Tech、首排生产入口和升级更早可见。

## 非目标与架构边界

- 不修改 `RustwarCore`、`TouchSequenceOwner`、GameState、UnitOrder、命中/伤害/冷却、AI、JSON/save schema 或 Web 版。
- 不引入 UIKit、第三方框架、随机数、定时器、纹理资源或新的 projectile event model。
- 不改变有效双指框选、pinch、pan、context、tap、camera、fog、visibility、生产队列、升级、快捷键或存档行为。
- 不以扩大 hit radius 或放宽可见性门控掩盖输入生命周期问题。
- 保留未跟踪 `.wp`，不提交、不删除。

## 实现契约

- `BattlefieldView.finishMultitouchSelection` 的 `synchronizeTouchOwner(...)=false` 分支只有在 `multitouchLease` 或 `pinchLease` 的 `sequence` 仍等于当前 `touchOwner.sequence` 且 owner 仍有多指 claim 时调用既有 `cancelMultitouchSequence()`；该路径完成 `cancel()` 与 `finishCancelledMultitouch()` 收尾。无 current lease 的迟到 callback 只忽略；取消路径清除 lease、selection preview、context/pan/pinch callback 和 suppression，下一次 fresh seed 可恢复单指。
- `BattlefieldScene.addImpactSparks` 使用稳定索引的 `2π / sparkCount`，不读时间、不用 `Hasher`/随机源；Reduce Motion 下仍为零飞散火花。`drawWreck` 的 salvage bars 使用与 wreck node 相同的 TTL alpha，不改变金属比例或回收命中。
- `TacticalProductionFocusSummaryView` 增加 compact presentation 参数；默认字号且 compact 宽度可容纳时显示 NOW / QUEUE / UPGRADE 短摘要，`ViewThatFits` 不足或 accessibility Dynamic Type 时回退原完整行。父级 accessibility value 仍包含完整当前项目、队列、Build summary 和 Upgrade summary。
