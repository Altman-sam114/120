# v2.44 iOS input/building context and model finish

## 背景

用户希望原生 iOS 操作更接近 Rusted Warfare：点单位后点地移动并自动接敌，点可见敌人直接攻击，多指框选单位，点建筑立即进入生产/升级上下文。上一轮审查还发现 Hover/Gunboat 在远景机械细节偏少，以及单指镜头拖动可能触发长按命令。

## 目标

1. BattlefieldView 的单指拖动在跨过 8pt 后标记为镜头平移，持续抑制 tap，并阻止长按上下文命令；结束或地图重置时清理状态，地图重置递增 gesture generation 以取消仍按住的旧长按。
2. 多指框选继续与捏合互斥；触点 ID 更换时拒绝当前序列，避免用旧坐标误选。
3. 直接点存活己方建筑（包括 Add 选择模式和重复点按循环）使用 Replace 语义，让 dock 主上下文显示该建筑的生产/升级。
4. Hover 与 Gunboat 增加少量确定性静态 compound SpriteKit 机械层，保持现有轮廓、炮塔 heading、recoilMount、命中和战斗语义。
5. 紧凑 dock 的生产选项使用两列而不是三列，保留至少 44pt 控件高度与既有快捷键/VoiceOver。

## 交互合同

- 无 pending 命令时，点存活己方单位按 Replace/Add 选择；已有己方单位选择时点可见敌人直接 `Attack`，点空地复用既有 `Attack-Move`，由 Core 在视野/姿态范围内自动接敌并在攻击范围内开火。
- pending Move / Attack / Attack-Move / Patrol / Guard / Repair / Reclaim / Build 命令优先消费 tap；长按上下文只在静止 tap 上触发。
- 多指同向扫框或静置取框进入区域选择，张合/反向移动进入缩放；第三指、取消和触点替换拒绝本次序列。
- 直接点己方建筑聚焦生产/升级 action context；不改变 Core selection API、队列、升级、控制编队或存档合同。

## 非目标

- 不修改 `RustwarCore` 的单位数值、攻击范围、AI、订单、JSON 或存档格式。
- 不新增动画、随机数、texture、shader、timer 或第三方依赖。
- 不运行本地测试、格式检查、Swift/Xcode build、Simulator、Preview、截图或 `git diff --check`。

## 云端交付

- 当前分支必须是 `main`，只提交本轮相关文件并直接 push `origin/main`。
- GitHub Actions `Rustwar CI Results` 是唯一验证来源。Agent C 下载精确实现 SHA 的 artifact 到 `/private/tmp/rustwar-c-review-<run_id>/`，核对 manifest 的 branch/SHA/run/attempt、JUnit 8/0/1、至少 327 Core tests、Xcode 26.5 / iOS 26.5、arm64/x86_64 build、Home/Combat 双 launch/orientation/pixel probe。
- 代码审查必须确认单指 pan 不会误发长按/短 tap，多指 touch ID 更换会拒绝，建筑 tap 在 Replace/Add 下都能显示生产/升级；Home/Combat PNG 需确认 Hover/Gunboat、履带单位、弹道、爆点、HUD、建筑和 Tactical Map 无回退。
- 固定 PNG 和 smoke 不能证明真实触摸节奏、VoiceOver、Dynamic Type、真机帧率或最小 zoom，需保留为风险。
