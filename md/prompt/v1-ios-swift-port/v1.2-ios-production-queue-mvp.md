# v1.2 / iOS native production queue MVP

## 1. Version

- Version: `v1.2`
- Stage: iOS / Swift migration, production loop.
- Reason: v1.1 proved native touch commands can mutate Swift game state and render over time. The next smallest RTS loop is unit production from an existing land factory.

## 2. Agent X Round Context

- Total goal X: keep improving Rustwar toward a native Swift/iOS RTS while preserving the playable Web Canvas prototype.
- Previous accepted round: v1.1 latest `origin/main` commit `0e4b00db7019986535e655cea42303626180fd38`, run `28682632872`, attempt `1`, artifact passed Agent C review.
- Current round goal: implement a minimal native production queue loop for player land factories.
- Remaining goals after this round: rally control, multi-select commands, combat, AI, fog, save/sandbox parity, and richer iOS command panels.

## 3. Background

Current native baseline:

- `BuildingSnapshot` already has `rally`, but no production queue.
- `UnitDefinition` has speed, HP and supply, but no cost/build time.
- `BuildingDefinition` has supply/income, but no produced unit list.
- iOS renders `state.units`, so newly produced units will appear if `RustwarCore` appends them.
- HUD currently exposes economy, Reset and Move for selected player units.

## 4. Goals

Agent B should implement:

1. Core production data.
   - Add minimal unit production cost and build time for the few existing units needed this round, preferably on `UnitDefinition`.
   - Add a produced unit list for land factory, preferably on `BuildingDefinition`.
   - Keep definitions simple and static; do not port the full Web production table.

2. Core production state and API.
   - Add a small `ProductionQueueItem` or equivalent value type.
   - Store a production queue on `BuildingSnapshot`.
   - Add `GameEngine.queueUnit(_:)` or equivalent API that works only for the selected player land factory.
   - Check metal, supply cap and whether the selected building can produce the requested unit.
   - Deduct metal when queueing succeeds.
   - Return a useful `ProductionCommandResult` or equivalent result enum.

3. Core production simulation.
   - Extend `GameEngine.update(deltaTime:)` to advance the first queue item on each building.
   - Spawn the completed unit near the building rally point, using existing definitions and deterministic IDs.
   - Clear completed queue items and preserve remaining queue items.
   - Keep this as a simple MVP: no blocked spawn resolution, no formation, no pathfinding.

4. iOS production UI.
   - When a player land factory is selected, show compact buttons for at least Scout and Light Tank.
   - Show enough queue/status feedback to know a unit is building.
   - Keep the current Move command behavior for selected units.
   - Do not create a large command panel or marketing UI.

5. Documentation.
   - Update `README.md`, `md/flow/flow.md`, `md/flow/flowchart.md`, `md/test/test.md` if needed, and `update_log.md`.

## 5. Non-goals

- No complete Web production parity.
- No upgrades, repeat build, cancel/refund, rally reassignment or build menus for every factory.
- No build placement.
- No combat, weapons, damage, AI or fog.
- No save/sandbox migration.
- No `WKWebView`, third-party engine or package dependency.
- Do not touch Web `index.html`, `styles.css` or `app.js` unless required by validation.
