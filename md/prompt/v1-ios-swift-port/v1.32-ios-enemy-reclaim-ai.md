# v1.32 / iOS native enemy reclaim AI

## 角色

本提示词交给 Agent B 执行。Agent B 必须遵守 `AGENTS.md` 的 main 直推、轻量本地检查、GitHub Actions artifact 和 Agent C 复判流程。

## 背景

v1.16 已让玩家 Builder 可以回收残骸；`UnitOrder.reclaim`、`updateReclaimOrder()` 和残骸金属转移逻辑已集中在 `RustwarCore`。v1.31 已让红方 Builder 自动维修受损友军单位或建筑。Web 版红方 AI 会用 Builder 回收附近残骸换取金属，原生迁移应先补一个小范围、可测试的红方回收 MVP。

## 目标

- 在 `RustwarCore` 的红方 AI 中新增 enemy Builder 自动回收残骸 MVP。
- 当红方有空闲 Builder，且基地附近存在有效残骸时，AI 应给该 Builder 写入 `.reclaim(wreckID:)`。
- 有效残骸必须满足 `metal > 0`、`ttl > 0`，并位于红方 Builder 附近的小范围内，避免 Builder 远离基地穿越战场。
- 回收执行必须复用现有 `updateReclaimOrder()`：远距离移动到 92 范围，范围内按现有速率把残骸金属转入红方金属，残骸耗尽后清除订单。
- 不得改变玩家当前选择。
- 保持红方缺少 Land Factory 补建、维修受损友军、资源扩张、建厂和建塔的优先级高于回收；回收只使用仍然空闲的 Builder。
- 同步 README、flow、flowchart、test 和 update_log。

## 非目标

- 不新增玩家 UI、SwiftUI HUD 按钮、SpriteKit 视觉或战术小地图交互。
- 不修改 Web `index.html` / `styles.css` / `app.js`。
- 不新增难度倍率、回收冷却计时器、多 Builder 协同、危险评估、路径规划或完整 Web AI parity。
- 不改变现有 `issueReclaim(wreckID:)` 的玩家选择语义。
- 不引入新框架、后端、网络依赖或 WKWebView。

## 建议实现

- 修改 `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`。
- 在 `updateEnemyAI()` 中建议顺序：
  1. 缺少 Land Factory 时优先补建。
  2. 维修受损友军。
  3. 资源扩张、第二工厂、炮塔建设。
  4. 对仍空闲的 Builder 尝试回收附近残骸。
  5. 生产和攻击。
- 新增私有 helper，例如：
  - `updateEnemyReclaim()`
  - `enemyReclaimTarget(for builder: UnitSnapshot) -> WreckSnapshot?`
- 候选残骸选择必须确定性，不使用随机数；建议限制最大搜索距离为 560，并在距离相近时优先 metal 更多或 ttl 更高的残骸。
- 不要扣金属；回收收益只由 `updateReclaimOrder()` 转入红方金属。

## 测试要求

在 `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift` 增加 Swift tests，至少覆盖：

- enemy AI 在有空闲 enemy Builder 和附近有效残骸时写入 `.reclaim(wreckID:)`，并不改变玩家选择。
- enemy reclaim order 推进后能把残骸金属转入红方金属，残骸耗尽后清除订单。
- enemy AI 不回收无金属、过期或过远残骸。
- enemy AI 不覆盖忙碌 Builder 的既有订单。
- enemy AI 在有受损友军或需要关键建造时，不让回收抢占更高优先级 Builder。

- README、flow、flowchart、test、update_log 与真实行为一致。
