# v2.61 iOS Tactical Map accessibility actions

## 轮次目标

在 v2.60 触控生命周期和生产首屏已经通过云端验收后，补齐 Tactical Map 的 VoiceOver 操作闭环。当前 `TacticalMapView` 通过 `.accessibilityAddTraits(.isButton)` 暴露地图，但没有默认 accessibility action；VoiceOver 用户只能读到可点按/拖动提示，无法从该元素直接执行安全的相机操作，也不能在等待目标时直接取消当前命令。

## 允许修改

- `ios/RustwarIOS/RustwarIOS/TacticalMapView.swift`
- `ios/RustwarIOS/RustwarIOS/GameController.swift`
- `README.md`
- `md/flow/flow.md`
- `md/flow/flowchart.md`
- `md/test/test.md`
- `update_log.md`
- 本提示词文件

不得修改 `swift/RustwarCore/`、`BattlefieldScene.swift`、战斗数值、命令模型、存档/JSON、Web 版、CI workflow 或 `.wp`。

## 实现要求

### 1. Tactical Map 默认 VoiceOver action

- `TacticalMapView` 保留现有 `.accessibilityLabel`、动态 value、pending hint、`.isButton` trait、可视手势、fog/radar 和 map hit-area 语义。
- 非等待目标状态下，地图的默认 accessibility action 聚焦玩家 Command Center；增加显式 `Reset Camera` custom action。
- 等待任意 target/area command 时，地图的默认 accessibility action 取消当前等待命令；增加可读的动态 action name，不得派发坐标命令或清除 selection。
- 这些 action 必须通过现有 `GameController` action，不能在 View 里直接改 pending state、Core state 或存档。

### 2. Controller 取消入口

- 在 `GameController` 增加一个单一 `cancelPendingTargetCommand()` presentation/controller action，按当前等待状态调用既有对应 toggle action（Move、Attack、Attack Move、Patrol、Guard、Repair、Reclaim、Build Extractor/Turret/Factory/Radar、Rally、Select Area）。
- 没有等待命令时该入口安全 no-op；已有 `commandStatus`、selection/command feedback、render revision 和 pending cleanup 语义保持。
- 不新增状态字段、Core API、命令类型、JSON 字段或存档字段。

### 3. 可访问性文案

- 正常地图 hint 说明默认 action 会聚焦 Command Center，仍保留地图 tap/drag 的说明。
- 等待态 hint 说明当前仍可在地图上选目标，并可通过默认/取消 action 退出等待态。
- 不用 `onTapGesture`、UIKit、固定屏幕尺寸、无值 animation、`AnyView` 或颜色单一表达；保持 44pt 相关现有控件和 Dynamic Type/Reduce Motion 行为。

## 非目标与风险边界

- 不改变地图普通 tap 居中、拖动相机、长按 context、pending target 命中半径、TouchSequenceOwner、生产、战斗、AI、Core、存档/JSON 或 Web。
- 本轮不新增 XCUITest；Actions 的静态 smoke 不能证明 VoiceOver rotor/action 顺序、真实触摸注入或真机手感。
- 保留 `.wp` 未跟踪文件，不加入提交。

## 本地与云端验证

- 当前项目制度强制云端唯一验证：不运行本地 SwiftPM test、Swift typecheck、Xcode build/list、Simulator、Preview、浏览器、截图或 `git diff --check`。
- 实现前确认 `main` 与 `origin/main` 已同步、工作区只有本轮改动和未跟踪 `.wp`；提交范围不得包含 `.wp`。
- 完成后使用以 `v2.61` 开头的提交信息，直接 `git push origin main`。
- Agent C 只验收最新 `origin/main` SHA 对应的 `Rustwar CI Results` artifact，下载至 `/private/tmp/rustwar-c-review-<run_id>/`，核对 manifest、JUnit、主日志、失败摘要、repo/toolchain/simulator info、双架构 build、production/combat 双启动、横屏归一化和两份 PNG probe。
- 人工代码复核必须确认地图默认 action 与等待态取消 action 均走 Controller 既有 toggle/聚焦路径，正常 map tap/drag/context 和 v2.60 生产首屏、战斗 PNG 无回退；并明确 VoiceOver 真实 action 仍未由 CI 自动化证明。
