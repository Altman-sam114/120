## 实现要求

### 单位模型

- 保持 7 类 `UnitType`、Core radius、命中范围、朝向和阵营语义不变。
- 履带单位增加内外履带、轮/齿分段或装甲裙板；Tank、AA Tank、Artillery 的炮塔、炮管和底盘必须有不同轮廓。
- Scout、Builder、Hover、Gunboat 保持各自楔形、工程臂、悬浮舱和船体身份，并增加少量结构高光、传感器或推进细节。
- 不使用实体字母区分单位；阵营仍同时使用颜色与不同几何标识。
- 控制每单位常驻节点数量，不新增 texture、粒子文件、timer、随机源或第三方依赖。

### 战斗特效

- 保持 v1.91 cooldown/HP diff 驱动、可见性 gate、64 effect / 32 decal 上限、fog 层级和 map reset 行为。
- 炮口焰应有白热核心、武器色外焰与沿射击方向的锥形/十字 flare；AA 双联、Hover beam、Artillery 重炮仍可区分。
- projectile 使用亮核心、武器色外壳和渐弱尾迹；impact 增加方向无关的分层火球、冲击环、确定性碎屑、烟尘和灼痕。
- Reduce Motion 继续禁止跨屏 projectile、扩张冲击波、火花飞散和移动烟尘，只保留短 opacity 反馈与静态短寿命灼痕。
- 视觉改动只读 Core 状态，不改变伤害、射速、目标选择、AI、命令或存档。

### 独立云端战斗场景

- 保留 `--rustwar-ci-visual-smoke` 的 Land Factory / Production 首屏和 `ios-home.png`。
- 新增 `--rustwar-ci-combat-visual-smoke`，只在该参数存在时构造固定、暂停、无 AI 的展示状态：双方多类单位在同一玩家视野内对峙，固定镜头，己方装甲单位被选中。
- Scene 在该专用场景中绘制一帧冻结的炮口焰、炮弹/光束、命中、烟尘和灼痕，保证截图时刻可复现；普通运行绝不能显示冻结 tableau。
- workflow 在同一固定 iPhone 17 Pro / iOS 26.5 Simulator 上第二次 launch，输出 `ios-combat.png`、`ios-combat-screenshot-metrics.txt`，并把 launch/process/screenshot/orientation/probe 全部纳入现有 Simulator check 成败。
- manifest 增加 combat launch argument、outcome 和路径字段；artifact schema 可保持 v1.2，但字段必须与真实结果一致。
