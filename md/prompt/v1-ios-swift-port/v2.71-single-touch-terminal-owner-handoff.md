# v2.71 Single-touch terminal owner handoff

## 版本与轮次

- 版本：`v2.71`
- 总目标 X：持续改善原生 iOS RTS 触控，使主战场连续单指点按、拖动和多指仲裁达到成熟移动 RTS 的稳定、直接和可预期手感。
- 当前轮次：修复 SpatialEventGesture 单指 terminal 已清空 active ID、但 `TouchSequenceOwner` 仍停留 `.possible` 时，下一枚全新触点被误判为 replacement 的生命周期缺口。
- 建议提交：`fix(ios): v2.71 hand off terminal touches`

## 背景与问题

`BattlefieldView.finishMultitouchSelection` 会把单指 Spatial terminal frame 交给 `synchronizeTouchOwner`。`TouchSequenceOwner.observe` 在收到当前 primary touch 的 ended event 后，会把该 ID 加入 `cancelledIDs` 并把 `activeIDs` 清空，但为等待 `SpatialTapGesture` / context drag terminal 提交，仍保持 `phase == .possible`。

正常情况下，后续 tap/context terminal 会调用 `finish` 或 `cancel` 收口；但 SwiftUI 并不保证所有并行 gesture callback 的顺序与到达。如果该 terminal callback 缺失、迟到或被 generation gate 丢弃，owner 会长期保持 `.possible + activeIDs.isEmpty`。下一枚使用全新 ID 的真实触点到达时，View 因 owner 不是 `.idle/.cancelled` 不会 fresh seed，`observe` 又会把它视为 primary replacement 并取消，造成下一次点按、拖动或长按被无故吞掉。

该状态已经拥有明确 terminal 证据：旧 accepted touch 不再 active。它应在下一枚未隔离 fresh active ID 到达时让位，同时继续保留旧 ID quarantine 和 stale callback gate。

## 目标

1. `TouchSequenceOwner.beginFreshSequence(with:)` 允许 `.possible && activeIDs.isEmpty` 且至少一个 accepted ID 已被 terminal 隔离的 owner 原子让位给新的、未在 `cancelledIDs` 中的 ID。
2. 让位时先关闭旧 sequence，隔离旧 accepted ID，再递增 sequence 并播种新 primary；旧 lease 必须立即失效。
3. `.possible` 仍有 active ID 时不得被新 ID 抢占；`.pan`、`.areaSelection`、`.longPress`、`.multitouch`、`.pinch` 等已 claim owner 也不得被替换。
4. `BattlefieldView.synchronizeTouchOwner` 在 fresh active frame 到达且当前 owner 为 terminal possible 时，先清理旧 preview/context lease，并使旧 context、pan、pinch callback generation 失效，再调用同一 `beginFreshSequence` 入口播种新触点。
5. 新触点播种后继续沿用现有 tap、long press、pan、pinch、双指框选、pending 命令和反馈路径，不新增第二套 owner 或触控命令。
6. 用 RustwarCore Swift Testing 覆盖 terminal possible owner 的让位、旧 lease 失效、旧 ID 继续隔离和 active owner 不可抢占。

## 实现范围与要求

### `swift/RustwarCore/Sources/RustwarCore/TouchSequenceOwner.swift`

- 新增只读 predicate `canYieldTerminalPossibleSequence`，要求 `phase == .possible`、`activeIDs.isEmpty`，且 `acceptedIDs` 与 `cancelledIDs` 有交集，集中表达 accepted-ended terminal 证据。
- 扩展 `beginFreshSequence(with:)` 的合法前态：
  - 既有 `.idle`；
  - 既有 `.cancelled`；
  - 新增 `canYieldTerminalPossibleSequence == true`。
- 新增前态只能表示已收到 accepted touch terminal 的未 claim 单指 sequence。不得仅按 `acceptedIDs`、调用时间或 unknown ID 猜测终止。
- 传入 ID 若位于 `cancelledIDs` 仍必须返回 `nil`，包括系统复用刚结束旧 ID 的情况；本轮不以清空 quarantine 冒充绝对区分新旧触点。
- 当从 terminal possible 让位时，先执行与 `closeCurrentSequence` 等价的关闭：旧 `acceptedIDs` 进入 `cancelledIDs`，旧 accepted/active/primary 清空，phase/claim 重置；随后只递增一次 sequence 并播种新 ID。
- 新 lease 的 source 继续为 `.context`；不要新增 phase、source、持久化字段或平台类型依赖。
- `.possible` 且 `activeIDs` 非空、任何已 claim phase，以及被隔离 ID都必须继续返回 `nil`。
- `observe` 的第二指接纳、replacement rejection、third finger、cancel、finish、reset、multitouch commit 和 stale lease 语义保持。

### `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift`

- 新增 focused tests，至少证明：
  1. sequence 从单一 primary 开始，`observe(activeIDs: [], endedIDs: [primary])` 后保持 `.possible` 且 `activeIDs.isEmpty`；
  2. 刚结束并进入 `cancelledIDs` 的旧 ID 不能重新播种；
  3. 一个未隔离的新 ID 可以调用 `beginFreshSequence`，sequence 只递增一次，成为唯一 accepted/active/primary；
  4. 旧 lease 不再被接受，也不能 finish 新 owner；
  5. `.possible` 仍有 active primary 时，另一 ID 不能通过 `beginFreshSequence` 抢占。
- 额外覆盖 `observe(activeIDs: [])` 但没有 accepted ended/cancelled event 的空帧：即使 active IDs 暂为空，也不得满足让位 predicate 或播种新 ID。
- 保留现有全部 TouchSequenceOwner 和 MultitouchIntentClassifier 测试；不弱化 replacement/third-finger/cancellation 断言。

### `ios/RustwarIOS/RustwarIOS/BattlefieldView.swift`

- `synchronizeTouchOwner(with:allowFreshSeed:)` 只读取 Core 的单一 predicate：

  ```swift
  touchOwner.canYieldTerminalPossibleSequence
  ```

- fresh seed 条件从 `.idle || .cancelled` 扩展为再包含该条件，但仍要求 `allowFreshSeed == true`，且 events 中存在 `.active`、未被 `cancelledIDs` 隔离的 touch。
- 在 terminal possible owner 让位前，必须按旧 sequence：
  - 清理 presentation touch preview；
  - reset context gesture state，使旧 tap/context/long-press generation 与 lease 失效；
  - invalidate pan 与 pinch callback generation；
  - 清空 pan lease/start、pinch lease/magnification、multitouch presentation state 等可能引用旧 sequence 的 View state。
- 不要在当前 Spatial onChanged 内无条件失效 `multitouchGestureCallbackGeneration`；新触点的当前 Spatial frame仍需继续完成 fresh seed 和 observation。旧 Spatial ID 已由 owner quarantine 过滤。
- fresh seed 后继续设置新的 context lease、seed sequence/location、context press location，并把 `battlefieldPanOccurredForCurrentTouch` 恢复为 `false`。
- `finishMultitouchSelection` 的单指 terminal 不得立即 `finish` owner，因为并行的有效 `SpatialTapGesture` / context terminal 仍可能随后提交这次真实 tap；本轮只在“下一枚 fresh active ID 到达”时让位。
- 不新增延时器、DispatchQueue、Task sleep、UIKit recognizer 或第二套 touch token。

## 必须保持的行为

- 单指 tap 仍按既有 pending 优先、友方选择、可见敌方 Attack、空地 Attack Move 路由；44pt 主战场实体命中和双击同类保持。
- 长按仍在 0.45s / 18pt 条件下复用上下文命令，并受当前 context lease、generation、owner phase、多指 candidate、pan 与 suppression gate 约束。
- 12pt 单指 pan、Select Area、pinch、双指静置/同向框选、第三指拒绝、触点 replacement、cancel、地图 reset 和序列抑制保持。
- Spatial 已观察到第二指后，`multitouchCandidateSequence` 仍会阻止单指 tap/long press 抢先提交；candidate 仍按 sequence 作用域化。
- 旧 accepted/cancelled ID 继续隔离；若平台立刻复用同一 touch ID，仍可能无法安全区分，这是必须保留并如实记录的边界。
- `TouchSequenceOwner` 仍是值类型纯状态机，不依赖 SwiftUI/UIKit；GameController、GameState、CameraState、命令、Core 模拟、存档/JSON 和 Web 版不变。
- VoiceOver、Differentiate Without Color、Reduce Motion、HUD、Tactical Map v2.70 marker 半径、模型与战斗视觉不变。

## 非目标与禁止项

- 不声称解决第二指 Spatial evidence 到达前，系统已先触发 long-press callback 的不可见窗口；没有统一 touch token 时不能绝对判断尚未上报的第二指。
- 不允许为了避免上述窗口而全局延迟所有 tap/long press、增加输入延迟或破坏单指响应。
- 不清空 `cancelledIDs` 来接纳同 ID，不把旧/新触点复用猜测成确定事实。
- 不重构 Tactical Map、GameController 命令派发、CameraState、SpriteKit rendering、HUD、生产、模型、战斗、AI 或 Web。
- 不新增第三方依赖、UIKit recognizer、XCUITest target、持久化字段或网络服务。
- 不删除任何文件。未跟踪 `.wp` 属于用户资源，必须保持未跟踪；不得删除、编辑、暂存或提交。
- 本轮禁止任何本地测试或验证命令：不得运行 SwiftPM test/typecheck、Swift parse/typecheck、Xcode build/list、Simulator、Preview、浏览器 smoke、截图、Node、测试脚本或 `git diff --check`。
- 本地只允许读取源码与文档、`git status`、普通 `git diff` / `git diff --stat`、提交范围检查、编辑、暂存本轮相关文件、commit 与 push；这些不得表述为测试通过。

## 证据边界与已知风险

- Core 云端单元测试可证明状态机让位合同；固定 Simulator smoke 不会注入所需 callback 顺序，不能证明 SwiftUI 在真实设备上一定复现或完全消除吞触。
- 旧 ID 继续 quarantine，因此系统立即复用同一 touch ID 时仍无法安全播种；SwiftUI 没有统一 touch token，不能宣称绝对区分。
- 第二指 evidence 尚未到达 SpatialEventGesture 前，long press callback仍可能抢先；本轮不通过全局延迟牺牲单指响应。
- 固定 PNG 只能证明静态 UI 无回退，不能证明真实点击、长按、双指、VoiceOver、Dynamic Type、动画时序或真机性能。
- 总目标 X 不因本轮通过而完成；只有最新实现 SHA artifact、源码合同和最终文档 SHA artifact 都通过后，v2.71 才结束。
