# v2.65.1 Combat Quick Command Rail readability

## 版本背景

- 版本：`v2.65.1`。
- v2.65 已把 Move、Attack Move、Attack、Stop 固定到选中单位后的 Quick Orders rail；最新云端 combat PNG 暴露出两个 presentation 问题：header 的 `Quick Orders` 被截断，`Attack Move` 在紧凑两列中被错误拆成三行。
- 本轮只修正 rail 的紧凑视觉与 accessibility 语义，不重写命令路径。

## 目标

1. Quick Orders header 在 compact trailing dock 中保持完整单行可读，并保留 header trait。
2. Attack Move 的紧凑视觉标签使用 `A-Move` 单行展示，避免 `At- / tack / Move` 断词；VoiceOver label/value/hint 仍朗读完整 `Attack Move` 与 Ready/Waiting 状态。
3. Move、Attack、Stop 和等待态 Cancel 的 action、图标、44pt 最小触控区、A/S keyboard shortcut、Dynamic Type 单列 fallback 和 secondary command rail 保持。
4. 继续复用 `GameController` 既有 toggle/action；不新增 Core mutation、订单、存档字段或输入 owner。

## 允许修改范围

- `ios/RustwarIOS/RustwarIOS/TacticalQuickCommandRail.swift`
- 如需同步记录：`README.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md`、`update_log.md`

## 非目标与不变量

- 不修改 `BattlefieldView`、`TacticalMapView`、`TouchSequenceOwner`、`GameController` 命令语义、RustwarCore、命中半径、框选、生产、战斗数值、AI、存档/JSON 或 Web 版。
- 不以缩小按钮命中区、删除完整 VoiceOver 语义或隐藏 Dynamic Type 内容换取布局通过。
- `.wp` 必须保持未跟踪，不得进入提交。

## 云端唯一验证

- 本轮禁止本地测试、Swift typecheck、Xcode build/list、Simulator、Preview、浏览器、截图和 `git diff --check`；只做只读源码/状态范围复核。
- 在 `main` 上只提交本轮相关文件并 `git push origin main`，使用 `Altman-sam114` 账号上下文。
- Agent C 只验收最新 `origin/main` commit 对应的 Actions artifact，下载到 `/private/tmp/rustwar-c-review-<run_id>/`，核对 manifest 的 branch、完整 SHA、run id、attempt、schema、Xcode/iOS SDK、JUnit、双架构 build、production/combat 双启动和 PNG probe。
- 人工查看最新 `ios-combat.png`：Quick Orders 不截断；Move、`A-Move`、Attack/Cancel、Stop 不裁切、不重叠且保持至少 44pt；战场主体、炮口、弹道、爆点、Tactical Map 和状态栏无回退。静态 PNG 不能证明真实点击、键盘焦点、VoiceOver 执行、Dynamic Type 全档位或真机手感，最终验收需保留该风险。
