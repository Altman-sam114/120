# v1.60 / iOS native area selection building fallback

## 角色

你是 Agent B，负责在 `main` 上实现本轮 v1.60。开始前必须阅读 `README.md`、`AGENTS.md`、`update_log.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和本提示词，并先执行 `git fetch origin`、`git switch main`、`git pull --ff-only origin main`、`git status --short --branch`。

## 目标

补齐 iOS 原生 `Select Area` 的 Web 框选 fallback 语义：

- Web `getEntitiesInRect()` 会先选择框内单位；如果没有单位，再选择框内建筑。
- iOS `Select Area` 目前只选择框内己方单位。
- 本轮让 iOS `Select Area` 在框内没有己方单位时，fallback 选择框内己方存活建筑。

## 非目标

- 不修改 Web `app.js`。
- 不改变普通 tap 选择、Screen Combat、Combat Units、Same Type、双击附近同类或控制编队语义。
- 不实现混合框选；框内有单位时仍只选单位，不同时选建筑。
- 不支持敌方建筑框选；iOS 只选择己方有效实体。
- 不引入新的 HUD 按钮、快捷键、框选建筑外观或命令系统。

## 实现建议

- `GameStateSelection.swift`
  - 新增 `playerBuildingSelectionTargets(in:)`，用建筑中心和 `GameDefinitions.building(type).size / 2` 判断建筑矩形是否与 `WorldRect` 相交。
  - 新增 `playerAreaSelectionTargets(in:)`：先取 `playerUnitSelectionTargets(in:)`；若非空直接返回；否则返回 `playerBuildingSelectionTargets(in:)`。
- `GameEngine.swift`
  - 新增 `selectPlayerEntities(in:mutation:)` 或语义等价 API，复用 `applySelection`。
  - 保留现有 `selectPlayerUnits(in:)` 语义，避免破坏已有测试和调用点。
- `GameController.swift`
  - `handleBattlefieldAreaSelection` 改用新 area selection API。
  - 状态文案区分单位和建筑，例如 Replace 下 `No entities in area`、`2 units selected`、`1 building selected`；Add 下空框仍保留旧选择并提示未添加。
- Swift tests
  - 框内有单位和建筑时只选择单位。
  - 框内无单位但有己方建筑时选择建筑。
  - 敌方建筑和框外建筑不被选中。
  - Add 模式下建筑 fallback 追加到现有选择并去重。
  - 空框在 Replace 下清空，在 Add 下保留旧选择。
