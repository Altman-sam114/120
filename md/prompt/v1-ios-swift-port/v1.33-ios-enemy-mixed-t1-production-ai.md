# v1.33 / iOS native enemy mixed T1 production AI

## 角色

本提示词交给 Agent B 执行。Agent B 必须遵守 `AGENTS.md` 的 main 直推、轻量本地检查、GitHub Actions artifact 和 Agent C 复判流程。

## 背景

v1.28 已把原生 Land Factory 的 T1 生产列表扩展为 Scout / Light Tank / Hover Tank / Artillery / AA Tank。玩家生产、取消、Repeat 和 Rally 已复用这份列表。红方生产 AI 仍只在 Scout 和 Light Tank 之间做最小选择，导致红方战斗编成落后于已经迁移的生产能力。

## 目标

- 在 `RustwarCore` 的红方生产 AI 中使用完整 Land Factory T1 列表。
- 当完成状态 enemy Land Factory 空队列、资源和人口允许时，AI 可按确定性策略排队 Scout / Light Tank / Hover Tank / Artillery / AA Tank。
- 生产执行必须继续复用现有 `enqueueUnit(_:at:)`，保留资源、人口、完成度和队列规则。
- 策略必须可测试、无随机数、无难度依赖，并不改变玩家当前选择。
- 同步 README、flow、flowchart、test 和 update_log。

## 非目标

- 不新增玩家 UI、SwiftUI HUD 按钮、SpriteKit 视觉或战术小地图交互。
- 不修改 Web `index.html` / `styles.css` / `app.js`。
- 不新增 T2 升级、重型单位、空军/海军/实验工厂、难度倍率、战术阵型或完整 Web AI parity。
- 不改变公开 `queueUnit(_:)` 的玩家选择语义。
- 不引入新框架、后端、网络依赖或 WKWebView。

## 建议实现

- 修改 `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`。
- 保持 `updateEnemyProduction()` 只处理完成状态、存活、空队列 enemy 生产建筑。
- 将 `enemyProductionChoice(for:)` 从 Scout / Light Tank 二选一扩展到完整 `GameDefinitions.building(building.type).produces` 列表。
- 推荐确定性策略：
  - 根据 enemy 现有单位和生产队列统计各 `UnitType` 数量。
  - 优先补当前数量低的单位，让 Scout / Light Tank / Hover Tank / Artillery / AA Tank 编成逐步均衡。
  - 只考虑当前建筑 `produces` 中存在、且 `canEnqueueUnit(_:for:)` 允许的单位。
  - 数量相同按 `produces` 顺序打平，保持 Web T1 顺序。
- 不要绕过 `enqueueUnit` 直接扣资源或写队列。

## 测试要求

在 `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift` 增加或更新 Swift tests，至少覆盖：

- enemy AI 在默认开局仍能排队生产，并不改变玩家选择。
- enemy AI 会在已有 Scout / Light Tank 较多时选择 Hover Tank / Artillery / AA Tank 中的欠缺单位。
- enemy AI 对候选单位遵守资源和人口限制，无法负担高成本单位时会回退到可生产单位。
- enemy AI 不给未完成、队列非空、非生产建筑或 supply blocked 工厂追加队列。
- 现有玩家 `queueUnit`、Repeat、Rally、生产完成和红方进攻测试不退化。
