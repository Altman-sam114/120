# v1.44 / iOS native multi-unit Reclaim

## Agent A 目标

把原生 iOS 迁移地基中的 Reclaim 命令从 primary selection 单 Builder 语义升级为多 Builder 选择语义，使它与 v1.43 Repair 的多 Builder 命令行为保持一致。

本轮只推进 Reclaim parity，不改 Web 原型，不引入新架构，不扩大到 Build Extractor / Build Turret / Build Land Factory / Attack / drag-box selection 等其它命令。

## 背景

当前 `GameEngine.issueReclaim(wreckID:)` 只读取 `state.selectedEntityID`，因此 Idle Builders 批量选择后只能让 primary Builder 回收残骸。v1.38 已提供 `selectedEntityIDs` 多选集合，v1.43 已提供 `selectedPlayerBuilderIndices()` 给多 Builder 命令复用，本轮应沿用这些 helper。

Reclaim 的目标是战斗残骸，不存在 self-target 跳过问题。多选时应让所有选中己方 Builder 回收同一个有效残骸；残骸耗尽或消失时现有 `updateReclaimOrder` 和目标清理逻辑会自然清除各 Builder 的订单。

## 实现范围

### Swift Core

修改 `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`：

- `issueReclaim(wreckID:)` 必须先使用 `selectedCommandEntityIDs()` 判断是否存在可用选择，保持无选择时返回 `.noSelection`。
- 使用 `selectedPlayerBuilderIndices()` 过滤当前选择中的己方 Builder。
- 选择集合存在但没有己方 Builder 时返回 `.selectedEntityCannotReclaim`。
- 目标必须是有效残骸，即现有 `activeWreck(id:) != nil`；缺失、空金属或过期残骸仍返回 `.invalidReclaimTarget`。
- 多选时，对所有选中己方 Builder 写入 `.reclaim(wreckID:)`，目标 id 相同。
- 不改变 `UnitOrder.reclaim` 数据结构、Reclaim 推进逻辑、92 范围、回收速率、残骸金属转移、目标消失清理、JSON 存档形状或红方 AI Reclaim。

### iOS App

修改 `ios/RustwarIOS/RustwarIOS/GameController.swift`：

- `canIssueReclaim` 改为使用当前多选集合中的己方 Builder。
- `toggleReclaimCommand()` 的等待态文案在多选时显示 Builder 数量，例如 `Reclaim target for 3 builders`。
- `statusText(forReclaim:)` 在 `.issued` 时根据实际收到 `.reclaim(wreckID:)` 的选中己方 Builder 数量返回单/多 Builder 反馈，例如 `Reclaim order issued to 3 builders`。
- 主战场 tap 和战术小地图残骸命中继续复用现有 `handleBuilderTargetCommand(at:)` 和 `engine.issueReclaim(wreckID:)`，不新增 UI 分支。

### Tests

修改 `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift`：

- 增加多选 Builder group 下达 Reclaim 后，所有选中己方 Builder 均获得 `.reclaim(wreckID:)` 的测试。
- 覆盖混合选择中包含不存在 ID、敌方 ID、非 Builder 单位或建筑 ID 时，只命令有效己方 Builder 并返回 `.issued`。
- 覆盖选择集合存在但没有己方 Builder 时返回 `.selectedEntityCannotReclaim`。
- 补充 Stop 对多选 Reclaim 的清理测试，确保 `issueStop()` 只清除选中 Builder 的 Reclaim 订单，不影响未选中 Builder。
- 保持既有单 Builder Reclaim、Reclaim 目标推进、残骸金属转移、残骸耗尽清理、目标缺失清理和 JSON 往返测试通过。
