# v1.9 / iOS native factory rally command

## Agent A brief

Version: `v1.9`

Goal: add a native iOS factory rally command so the SwiftUI/SpriteKit app can change a selected player factory's production rally point through `RustwarCore`, and produced units spawn at the new point.

## Background

- `BuildingSnapshot` already stores `rally`.
- `GameEngine.updateProduction(deltaTime:)` already spawns completed units at `building.rally`.
- The native iOS app can select a player land factory and queue Scout / Light Tank, but the rally point is fixed to the map preset.
- Web Rustwar supports factory rally points through right-click context commands. This round migrates only the minimal native iOS rally placement loop.

## Functional requirements

1. Add a public `GameEngine.setRally(to:)` command that:
   - requires an active selection;
   - only succeeds for selected player buildings that can produce units;
   - writes `destination.clampedToMap()` into the selected building's `rally`;
   - leaves `state.selectedEntityID` unchanged;
   - does not enqueue, cancel, refund, or move existing units.
2. Add a dedicated `RallyCommandResult` enum rather than adding building rally cases to `UnitCommandResult`.
3. Add Swift tests covering:
   - no selection rejection;
   - selected player unit rejection;
   - selected non-producer building rejection;
   - selected enemy producer rejection;
   - successful rally update with selection preserved;
   - out-of-bounds rally point clamping;
   - production completed after rally change spawns at the new rally point.
4. Add native iOS controller support:
   - expose whether Rally can currently be issued;
   - add a Rally target mode that is mutually exclusive with Move and Attack target modes;
   - battlefield tap in Rally mode calls `engine.setRally(to:)`;
   - Rally mode cancel should clear only the pending Rally mode and status;
   - Stop should clear pending Move / Attack / Rally modes;
   - map switch and restart should clear pending Rally mode;
   - status text must be concise and not claim full Web parity.
5. Add a native HUD Rally button for selected player producers with a text label and system image, preserving 44 pt minimum tap target.
6. Add SpriteKit rally visualization:
   - selected producer shows a line from the factory to its rally point;
   - selected producer shows a small rally marker at the rally point;
   - the marker should disappear when a non-producer or another entity is selected.
7. Preserve existing Move, Attack, Stop, production, enemy AI, map switch/restart, pause/speed, tactical minimap, and camera controls.

## Non-goals

- No Web behavior change.
- No `WKWebView`.
- No multi-selection rally commands.
- No queued command chains.
- No rally setting from tactical minimap.
- No production cancel/refund, repeat production, attack-move, patrol, guard, fog, save/load, or sandbox.
- No new third-party dependency or build system.
- No manual browser regression unless the human asks.

## SwiftUI guidance

- Keep shared state in `@MainActor @Observable GameController`.
- Use text-labeled SwiftUI buttons such as `Button("Rally", systemImage: "flag.checkered", action: controller.toggleRallyCommand)`.
- Keep command logic in `GameController` / `RustwarCore`, not inline in `GameHUDView.body`.
- Keep 44 pt hit targets and accessible text labels.
- Avoid introducing UIKit or non-native web wrappers.
