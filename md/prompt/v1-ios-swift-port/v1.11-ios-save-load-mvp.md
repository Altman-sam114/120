# v1.11 / iOS native save and load MVP

## Agent A brief

Version: `v1.11`

Goal: add a native iOS save/load MVP so the SwiftUI/SpriteKit app can persist the current RustwarCore battle state, camera, map, pause state and simulation speed locally, then restore and continue the same native simulation.

## Background

- Web Rustwar already supports save/load through `localStorage`.
- Native iOS currently resets when the app/controller is recreated and has no save/load entry.
- `GameState` and most shared core snapshots are already `Codable`.
- `GameEngine` currently only initializes from a map preset; loading a decoded `GameState` needs a safe public initializer or restore method.
- `CameraState` is iOS-only and currently not `Codable`.

## Functional requirements

1. Add a public way to construct or restore `GameEngine` from an existing `GameState` while preserving the existing `enemyAIEnabled` behavior.
2. Add Swift tests proving that:
   - a state with selected entity, production queue, movement/attack orders, metal and elapsed time can be JSON encoded and decoded without loss;
   - a `GameEngine` restored from a decoded state can continue updating production/movement/combat instead of becoming inert;
   - the restored engine preserves `enemyAIEnabled` when requested.
3. Make `CameraState` `Codable` and restore camera center/zoom from saved data.
4. Add an iOS-native save payload inside the app layer that stores:
   - schema version;
   - `GameState`;
   - `CameraState`;
   - current `MapID`;
   - `isPaused`;
   - `simulationSpeed`.
5. Store the payload locally with `UserDefaults` using `JSONEncoder`/`JSONDecoder`.
6. Add `saveGame()` and `loadGame()` actions on `GameController`:
   - Save writes the current payload and sets concise status text.
   - Load decodes the payload, restores engine/camera/map/pause/speed, clears pending Move/Attack/Rally modes, increments `mapRenderRevision` and `renderRevision`, and sets concise status text.
   - Load fails gracefully with status text when no save exists or decoding fails.
   - Loading should not trigger an unintended map reset through the `currentMapID` didSet path.
7. Add native HUD buttons for Save and Load near the existing Restart/Reset controls with 44 pt minimum tap targets and accessibility labels.
8. Preserve existing Move, Attack, Stop, Rally, production, production cancel, enemy AI, map switch/restart, pause/speed, tactical minimap and camera controls.

## Non-goals

- No Web behavior change.
- No `WKWebView`.
- No iCloud, document browser, file export/import or cross-device sync.
- No multiple save slots.
- No screenshot thumbnails.
- No compatibility migration beyond a simple schema version.
- No full Web save parity, sandbox save, fog, multi-select or replay system.
- No new third-party dependency or build system.

## SwiftUI guidance

- Keep persistence commands in `GameController`; do not put encoding/decoding logic in `GameHUDView.body`.
- Keep the save payload app-private unless tests require shared core coverage.
- Use text-labeled SwiftUI buttons, for example `Button("Save", systemImage: "square.and.arrow.down", action: controller.saveGame)`.
- Keep controls compact and avoid crowding the existing command row.
