# v2.72 iOS weapon-specific combat profiles

## 版本背景

- v2.71 已闭环单指 terminal owner handoff；当前原生战场的 Core 战斗、武器朝向、后坐、命中/摧毁分层和固定 combat visual smoke 均有稳定云端基线。
- 现有单位已经按类型选择颜色、尺寸、尾迹和速度，但所有实体炮弹仍走同一条直线，AA 两发会从分离炮口汇聚到同一终点，履带单位的通用椭圆阴影也不随 hull heading 旋转。
- 本轮只提高武器和履带载具的瞬时辨识度，不改变任何命中、伤害、射程、装填、目标或移动规则。

## 目标

1. 保持 Tank 为短琥珀动能 tracer，Heavy Tank 使用更宽、更热且终点反馈更重的炮弹层级。
2. Artillery 使用确定性的抬升弧线 presentation：炮弹沿直线地面投影前进，自身产生屏幕纵向抬升，配套独立地面影子与少量烟珠；固定 combat fixture 能静态展示同一结构。
3. AA 的两发 tracer 从双炮口到双终点保持相同横向间距，不再向同一点汇聚。
4. Tank / Heavy Tank / AA / Artillery 的复合接地阴影与 hull heading 同步旋转，并保持单个 `SKShapeNode`，避免按履带额外增加节点数。
5. 保留 64 effect / 32 decal 上限、fog/visibility、Reduce Motion 透明度退化和现有 frozen fixture 边界。

## 实现要求

- 在既有 `spawnUnitFireEffect` 参数派生中加入最小的轨迹/终点 profile 参数；不把视觉字段写入 `RustwarCore`、`GameState`、快照或存档。
- `spawnFireEffect` 对多发武器同时偏移 origin 与 target，确保双线平行；两个 AA projectile 共用一次居中的 volley terminal feedback，避免把一次 Core damage 画成两次重爆；单发武器的几何保持。
- Tank / Heavy / AA / Artillery / Gunboat 的 muzzle distance 应分别与当前模型炮管端点对齐，不能让 flash 留在炮管内部。
- 直射弹继续复用既有 `addProjectileEffect`。Artillery 单独复用同一 projectile 构型并增加 ballistic presentation helper：
  - ground shadow 沿 origin→target 线性移动；
  - projectile 按 `sin(pi * progress)` 抬升，终点仍精确落到目标视觉坐标；
  - 烟珠位置和延迟确定，不使用随机数；
  - frozen 路径固定在中段并显示弧线高度、影子和烟珠；
  - Reduce Motion 的实时路径继续只显示终点透明度反馈，不执行轨迹运动。
- Heavy Tank 只通过既有 projectile/terminal 参数形成更重层级，不新增独立 effect root 或命中事件。
- 履带阴影使用一个 compound `CGPath`/`SKShapeNode` 表达车体核心和双履带接触，挂在按 hull heading 旋转的 shadow mount 下；其它单位保留既有通用阴影外观。
- 固定 combat smoke 继续只调用真实 presentation helper，不伪造 Core 开火、伤害或死亡。
