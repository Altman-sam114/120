# v1.80 / iOS enemy AI Radar Station construction MVP

## Agent A 提示词

本轮目标：在原生 Swift/iOS 迁移地基中，让红方 AI 在基础经济、工厂和炮塔成型后，能用空闲 Builder 自动建造 1 座 Radar Station。此轮推进 Web radar parity 的 AI 侧闭环，但保持范围小、可测试、可回滚。

## 背景

v1.78 已新增雷达 contact snapshot，v1.79 已新增玩家可建 Radar Station，且完成状态 Radar Station 才提供雷达范围，Command Center 不再作为雷达来源。当前遗留点仍包括 Radar Station 升级、AI 建造雷达、雷达范围 HUD 圈、雾内敌方残影、雷达目标记忆和完整 Web radar parity。

## 必须修改

- `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`
  - 在红方 AI 构建流程中加入 Radar Station 建造决策。
  - 建议新增 `enemyRadarLimit = 1`，并在 `updateEnemyAI()` 中把 radar construction 放在 Land Factory / Turret 成型之后、Reclaim / Production / Attack 之前。
  - 条件建议：敌方至少有完成或存活 Land Factory、Extractor 数量达到 `enemyExtractorCountBeforeAdditionalFactory`、Turret 数量达到当前防御基础阈值、存活 Radar Station 数量小于限制、金属足够、存在空闲敌方 Builder、能找到合法陆地点。
  - 复用 `startPointBuildingBuild(.radar, builderIndex:position:)`，不得绕过现有建筑扣费、未完成建筑和 Builder build order 体系。
  - 新增 radar build position helper，优先围绕 enemy base / command / rally / builder 找点，避免与资源、单位和建筑重叠。
  - 更新 `updateEnemyExpansion()` 的“高级建筑优先”判断，避免 AI 正准备建工厂/炮塔/雷达时又抢先扩张 Extractor。
- `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift`
  - 增加红方 AI 建造 Radar Station 的测试：在足够经济、工厂、炮塔和空闲 Builder 条件下，`update(deltaTime: 1)` 后新增未完成敌方 Radar Station、扣除金属、Builder 获得 `.build(targetID:)`，且不改变玩家选择。
  - 增加三张原生地图都能找到 Radar Station 合法建造点的测试。
  - 增加等待条件测试：金属不足、Builder 忙、已达到 Radar Station 限制或前置防御/经济未达标时不新建雷达。
  - 增加完成后能给敌方产生 radar contact 的测试，证明 AI 建造的 Radar Station 接入既有 `GameState.radarContacts(for:)`。
- 文档同步：
  - `README.md`
  - `md/flow/flow.md`
  - `md/flow/flowchart.md`
  - `md/test/test.md`
  - `update_log.md`

## 非目标

- 不修改 Web `app.js`。
- 不新增 WKWebView 或任何网页包装。
- 不实现 Radar Station 升级。
- 不实现雷达范围 HUD 圈。
- 不实现雾内敌方残影、雷达目标记忆或 AI 情报限制。
- 不改玩家 Radar 建造按钮、快捷键或战术小地图交互，除非编译需要。
- 不引入第三方依赖、后端或新的构建工具。

## 保持不变

- Web 版直接打开 `index.html` 仍可运行。
- 玩家 Radar Station 建造语义保持 v1.79 行为。
- 雷达 contact 仍只包含 kind 和 position，不写入 visible tiles 或 explored 记忆，不放宽实体目标命中。
- 红方 AI 现有优先级不得被破坏：缺工厂时先补工厂；维修、扩张、炮塔、回收、生产和攻击的既有测试应继续通过。

## 本地轻量检查

按 `md/test/test.md`：

```sh
git diff --check
swift test --package-path swift/RustwarCore
```

若本机 SwiftPM / PackageDescription / Swift SDK 阻塞，必须记录真实错误，并至少尝试：

```sh
swiftc -module-cache-path /private/tmp/rustwar-swift-module-cache-v180 -typecheck swift/RustwarCore/Sources/RustwarCore/*.swift
swiftc -parse swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift
```

本轮不修改 `ios/RustwarIOS/` 时可不跑本地 `xcodebuild`，但 GitHub Actions 仍会跑 iOS build。若修改 iOS App，则必须尝试 `xcodebuild -list` 和 iOS build，或记录完整 Xcode 阻塞。

## main 直推与 Agent C 验收

Agent B 必须：

```sh
git fetch origin

git status --short --branch
```

确认只提交本轮相关文件后：

```sh
git add 相关文件
git commit -m "v1.80: add enemy AI radar construction"
git push origin main
```

Agent C 必须只验收最新 `origin/main` commit 对应的 `Rustwar CI Results` run，下载 artifact 到 `/private/tmp/rustwar-c-review-<run_id>/`，核对：

- manifest 的 `branch=main`
- manifest 的 `commitSha` 等于 `origin/main` 最新 commit
- run id / run attempt 与下载结果一致
- JUnit、`ci-failure-summary.md` 和 `build.log` 一致
- `build.log` 真实包含 `git diff --check`、`node --check app.js`、`swift test --package-path swift/RustwarCore`、`xcodebuild -list` 和 iOS build 输出

若失败，不得确认通过；退回 Agent B 追加修复 commit。
