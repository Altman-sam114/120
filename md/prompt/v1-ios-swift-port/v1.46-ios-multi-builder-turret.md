# v1.46 / iOS native multi-Builder Build Turret

## Agent A prompt for Agent B

### Goal

Move native iOS Turret construction from primary Builder semantics to selected Builder group semantics, matching the v1.45 Build Extractor behavior:

- If at least one selected player Builder is present, `issueBuildTurret(at:)` must accept the command even when the primary selected entity is a building, enemy, missing id, or non-Builder unit.
- The command must create exactly one incomplete Turret, deduct the Turret metal cost exactly once, and assign every selected player Builder the same `.build(targetID:)` order.
- Multiple selected Builders must cooperatively advance that one Turret's build progress faster, and completion must clear all Builders that were assigned to the completed target.
- iOS HUD availability and status text must reflect selected Builder groups.

### Non-goals

- Do not modify Web runtime files (`index.html`, `styles.css`, `app.js`) except for required syntax checks.
- Do not change Land Factory build semantics in this round.
- Do not add new dependencies, build tools, backends, UIKit wrappers, or `WKWebView`.
- Do not change Turret placement, cost, build time, range, damage, AI Turret construction, save schema, or terrain/overlap validation.

### Implementation notes

- In `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`, use the v1.45 `issueBuildExtractor(on:)` pattern:
  - Guard `!selectedCommandEntityIDs().isEmpty`.
  - Gather `selectedPlayerBuilderIndices()`.
  - Reject with `.selectedEntityCannotBuild` if no selected player Builder exists.
  - Validate `canPlaceBuilding(.turret, at:)` and metal before mutating state.
  - Start exactly one Turret build from the first valid Builder, then assign `.build(targetID:)` to every selected player Builder.
- Prefer returning the new building id from `startTurretBuild` / `startPointBuildingBuild` with `@discardableResult` so existing enemy AI and Factory build callers continue to work.
- Keep `clearBuildOrders(targetID:)` as the completion cleanup mechanism.
- In `ios/RustwarIOS/RustwarIOS/GameController.swift`:
  - Change `canIssueBuildTurret` to use `!selectedPlayerBuilders.isEmpty`.
  - Mirror Extractor multi-Builder pending text style: `Turret position for N builders` when N > 1.
  - On success, report `Turret build started by N builders` when more than one selected Builder actually received a Turret build order.
  - Add a small helper if needed to count selected Builders whose current `.build(targetID:)` points at a player Turret near the issued placement.
- `GameHUDView.swift` should only need changes if the existing `controller.canIssueBuildTurret` binding is insufficient.

### Tests

Update `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift` with focused coverage:

- Multi-Builder Turret command creates one Turret, deducts one Turret cost, and gives both selected Builders the same target id.
- Mixed invalid selection with one selected player Builder succeeds and only that Builder receives the order.
- Selection without any player Builder returns `.selectedEntityCannotBuild`.
- Multiple Builders near the Turret progress build faster than one Builder and all shared build orders clear on completion.
- Stop only clears selected Builders in a shared Turret build order and leaves an unselected Builder's order intact.
- Invalid placement or insufficient metal does not overwrite an existing selected Builder order.
