# v2.42 iOS intent-aware touch targets

## 背景

v2.29 将 iOS 主战场实体触控目标扩展到至少 44pt，v2.31 又允许密集候选按稳定顺序循环。当前候选仍只按距离排序，不理解玩家正在选择、Attack、Guard 或 Repair；因此靠得更近的错误阵营实体可能遮住实际点中的目标，并让显式命令先命中非法目标后退出等待态。

## 目标

1. Core 单点与候选列表选择 API 增加可选 `targetTeam`，默认 `nil` 时保持旧行为；指定队伍时只返回该队单位或建筑。
2. 队伍过滤不得改变距离排序、units-first 稳定顺序、玩家视野过滤或 radar-only 敌军不可精确命中的规则。
3. 无等待态且已有己方单位选择时，先用实体原生几何半径寻找可见敌军；命中则优先 Attack。没有精确敌军时继续使用既有 44pt 最近候选，保持己方选择、敌方 Attack 和空地 Attack Move。
4. 显式 Attack 只选择最近可见敌军；Guard 只选择至少能由一个非目标自身的选中己方单位护航的己方目标；Repair 只选择受损且至少能由一个非目标自身的选中 Builder 维修的己方目标。
5. Core 新增测试覆盖跨队距离干扰、同队稳定排序和雾区/radar-only 敌军拒绝。

## 非目标

- 不改 44pt 触控尺寸、重复点按循环、双击同类、双指框选、pinch、pan、相机或 Tactical Map 世界半径。
- 不改长按上下文命令、Core 命令结果、阵型、战斗数值、AI、存档或 Web。
- 不改变无效显式目标后退出 pending 的既有行为；Engine 继续做最终合法性校验。
- 不新增 XCUITest、第三方依赖或 UIKit 路径。

## 实现边界

- `targetTeam == nil` 必须保持 `includeEnemies` 的全部旧调用兼容性；显式 `targetTeam` 只约束候选阵营。
- 普通 tap 的敌军优先只使用 `minimumHitRadius: 0`，随后才回退既有 `22pt / camera.zoom` 世界半径候选。
- Attack / Guard / Repair 继续经过 `selectionTarget(s)VisibleToPlayer`，不得穿透 fog 或把 radar contact 当成实体。
- Guard / Repair 在 Controller 只做意图候选筛选，Engine 仍是最终命令合法性的唯一裁决者。
- 保留 `.wp`，只提交本轮明确相关文件。
