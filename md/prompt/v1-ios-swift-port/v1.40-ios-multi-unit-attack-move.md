# v1.40 / iOS native multi-unit Attack Move

## 角色

本提示词交给 Agent B 执行。Agent B 必须遵守 `AGENTS.md` 的 main 直推、轻量本地检查、GitHub Actions artifact 和 Agent C 复判流程。

## 背景

v1.38 建立了原生多选集合和 Idle Builders / Combat Units 批量选择入口，v1.39 已把 Move / Stop 扩展到多选集合。Web 版 RTS 的基础战斗操作还依赖多单位 Attack Move：选中一组战斗单位后点目标区域，整组单位向目标推进并沿途自动攻击视野内敌人。本轮在不引入队形、寻路或其它复杂命令的前提下，把原生 Attack Move 扩展到多选集合。

## 目标

- `GameEngine.issueAttackMove(to:)` 在 `selectedEntityIDs` 包含多个己方单位时，给所有选中己方单位写入 `.attackMove(destination:)`。
- 单选行为保持兼容：只有 `selectedEntityID` 或 `selectedEntityIDs` 单元素时，结果与 v1.39 之前一致。
- 如果多选集合混入建筑、敌方单位或不存在 id，应忽略无效 id；只要至少一个己方单位可执行，就返回 `.issued`。
- 如果没有任何选中 id，仍返回 `.noSelection`；如果有选择但没有可执行己方单位，返回现有 `.selectedEntityCannotAttack`。
- iOS 现有 Attack Move 按钮、主战场 tap 和战术小地图 Attack Move 点位命令复用新 core 语义；可更新状态文案为复数，但不新增 UI 面板。
- 同步 README、flow、flowchart、test 和 update_log。

## 非目标

- 不修改 Web `index.html` / `styles.css` / `app.js`。
- 不实现多单位 Attack、Patrol、Guard、Repair、Reclaim、Build、Rally 或生产命令。
- 不实现队形保持、自动方阵整理、路径规划、碰撞避让或 Shift 追加队列。
- 不改变 `selectedEntityIDs` Codable schema，不新增存档版本迁移。
- 不改变 Attack Move 的临时索敌、伤害、抵达清除或视野逻辑。
- 不用 `WKWebView` 或网页包装。

## 建议实现

- 修改 `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`：
  - 复用 v1.39 的 `selectedCommandEntityIDs()` 和 `selectedPlayerUnitIndices()` helper。
  - `issueAttackMove(to:)` 先区分无选择和有选择但没有己方单位。
  - 对所有选中己方单位写入同一个 `destination.clampedToMap()`。
  - 保持 `issueAttack(to:)`、`issuePatrol(to:)`、`issueGuard(targetID:)` 等其它 API primary-only。

- 修改 `ios/RustwarIOS/RustwarIOS/GameController.swift`：
  - `canIssueAttackMove` 应在多选集合中有任意己方单位时为 true。
  - Attack Move 等待态和成功文案可包含单位数量，例如 `Attack-move target for N units`、`Attack-move order issued to N units`。
  - 不要把 SwiftUI view 变成规则层。

## 测试要求

在 `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift` 增加 Swift tests，至少覆盖：

- 多选 Combat Units 后 `issueAttackMove(to:)` 给所有选中己方非 Builder 单位写入 `.attackMove`。
- 多选集合里混入敌方、建筑、缺失 id 时，`issueAttackMove(to:)` 只作用于有效己方单位且返回 `.issued`。
- 多选集合只有敌方或建筑时，Attack Move 返回 `.selectedEntityCannotAttack`。
- 单选 Attack Move 既有测试继续通过。
