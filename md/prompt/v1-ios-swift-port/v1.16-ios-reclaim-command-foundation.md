# v1.16 / iOS native reclaim command foundation

## Agent B 任务

把 Web 版工程单位回收残骸的核心语义，小步迁移到原生 Swift/iOS 地基。目标是让原生 iOS 中的己方 Builder 可以点选战场残骸并回收金属，使 `RustwarCore`、SwiftUI HUD、SpriteKit 战场渲染和 Swift tests 都具备可验收的最小闭环。

## 背景依据

Web `app.js` 的当前行为：

- 单位或建筑死亡时生成 `state.wrecks`，残骸保存 `id`、位置、尺寸、队伍、剩余金属和 TTL。
- `issueReclaim(units, wreck)` 只给具备建造能力的单位下达 `{ type: "reclaim", wreckId }`。
- `updateUnits()` 推进 `reclaim`：目标残骸缺失时清除订单；距离超过约 92 时靠近；进入范围后按建造/维修能力持续减少残骸金属并增加单位所属队伍金属；金属耗尽后移除残骸并清除订单。
- 主地图主动 Reclaim 模式和右键残骸上下文都可以触发回收。

原生 v1.15 当前状态：

- `RustwarCore` 已有 `UnitOrder.repair(targetID:)`、Builder Repair、Stop、攻击/死亡清理、生产、AI、Save/Load。
- iOS HUD 已有 Move / Attack Move / Patrol / Guard / Repair / Stop / Attack / Rally / Save / Load 等按钮与互斥等待态。
- 还没有 Swift 原生残骸状态、残骸生成、残骸点选或 Reclaim 命令。

## 目标

1. 在 `RustwarCore` 增加小型 `WreckSnapshot` 状态模型，并把它接入 `GameState`、Codable 往返和旧存档默认值。
2. 单位或建筑因 `removeDestroyedEntities()` 被清理时生成残骸：
   - 残骸位置来自被摧毁实体。
   - 残骸 `metal` 和 `maxMetal` 使用 Web 语义的近似值：单位按 `metalCost * 0.24` 且最低 18；建筑可给 `BuildingDefinition` 增加 `metalCost` 后同样按 24% 计算。
   - 残骸大小分别来自单位半径或建筑尺寸。
   - 初始 TTL 可使用 58 秒；本轮可以只在 core 内随 update 衰减并删除过期或空残骸。
3. 增加 `UnitOrder.reclaim(wreckID:)` 和 `GameEngine.issueReclaim(wreckID:)`：
   - 无选择返回 `.noSelection`。
   - 只有当前选中己方 Builder 可回收，其他选择返回专用不可回收结果。
   - 目标必须是存在、未过期且 `metal > 0` 的残骸，否则返回专用非法目标结果。
   - 下令后保持当前选择并写入 Reclaim 订单。
4. `GameEngine.update` 推进 Reclaim：
   - 目标残骸无效、过期或金属耗尽时清除订单。
   - Builder 距离残骸超过约 92 时向残骸移动。
   - 进入范围后按可测试常量回收金属，建议使用 Builder 约 `34 * 0.58 = 19.72 metal/s`，减少残骸 `metal` 并增加 Builder 所属队伍金属。
   - 回收期间把残骸 TTL 至少维持到 8 秒。
   - 残骸金属耗尽后删除或标记为 0 并清除订单。
   - Stop 必须能清除 Reclaim 订单。
5. iOS 侧增加 Reclaim 控制：
   - HUD 在选中己方 Builder 或等待回收目标时显示 Reclaim 按钮。
   - Reclaim 等待态与 Move / Attack Move / Patrol / Guard / Repair / Attack / Rally 互斥。
   - Stop、Load、Restart 和地图切换必须清除 Reclaim 等待态。
   - Reclaim 等待态下 tap 主战场残骸，调用 `GameEngine.issueReclaim(wreckID:)`；tap 非残骸给出简短状态提示。
6. SpriteKit 战场渲染：
   - 绘制残骸，能看出剩余金属比例。
   - 对 Reclaim 订单绘制独立命令线和 `$` 或类似回收标记。
7. 如范围可控，原生战术小地图也显示残骸小标记；若不做，文档中明确 v1.16 暂不覆盖小地图残骸。
8. 更新 README、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md`、`update_log.md`。

## 非目标

- 不迁移 Web 多选 Reclaim。
- 不迁移 Shift 队列、右键上下文、战术小地图下达 Reclaim、AI 自动回收残骸。
- 不迁移建造放置、沙盒残骸摆放/清理、粒子效果、战争迷雾或雷达残骸显示。
- 不引入第三方依赖，不使用 `WKWebView` 包装 Web 版。
- 不改变 Web `index.html` / `app.js` 的直接浏览器运行链路；除非确有必要，本轮不改 Web 代码。

## 测试要求

Swift tests 至少覆盖：

- `UnitOrder.reclaim` 和 `GameState.wrecks` JSON 往返。
- 旧 JSON 缺少 `wrecks` 时解码为 `[]`。
- 摧毁单位生成残骸，单位残骸金属值按定义计算。
- 摧毁建筑生成残骸，并释放 extractor 资源点占用。
- `issueReclaim` 拒绝无选择、敌方/非 Builder 选择、缺失/空残骸目标。
- Builder 对远处残骸下令后先靠近并保持订单。
- Builder 在范围内回收残骸时增加玩家金属、减少残骸金属，并在耗尽后清除订单和移除残骸。
- Stop 清除 Reclaim 订单。
- Reclaim 目标过期或被移除时订单自动清除。
