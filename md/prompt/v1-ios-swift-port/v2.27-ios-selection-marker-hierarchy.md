# v2.27 iOS selection marker hierarchy

## 目标

提高原生 iOS 战场选择反馈的可读性：多选时明确区分驱动详情和同类选择的 primary entity 与其余 group members，同时减少旧黄色近整圈标记对履带、炮塔、武器后坐和命中特效的遮挡。

## 参考

- 公开 YouTube `Rusted Warfare Guide / Buildings and Basics` 与 `Rusted Warfare Guide Units and Factories` 的高对比、低占用战场选择反馈。
- 只参考信息层级和可读性，不复制第三方图形或素材。

## 实现要求

- 只修改 `BattlefieldScene` 的只读选择 presentation。
- 使用 `state.selectedEntityID` 作为 primary selection；旧状态缺失时 fallback 到 `selectedEntityIDs.first`。
- 玩家 primary 单位使用青色短分段弧、轻 halo 和四向定位刻度；其他玩家已选单位使用绿色短弧。
- 敌方观察选择用橙色 primary、红色 secondary，不能伪装为己方。
- 建筑使用同一 primary/secondary 色彩层级的角标。
- 所有选择几何位于模型下、阴影上，不遮挡 hull、weapon mount、damage state 或 health bar。
- 不增加 timer、Task、SKAction、随机数、Core 状态或持久化字段。

## 非目标

- 不修改 tap、双击、双指框选、Replace/Add、控制编队、直接 Attack/Attack Move、长按上下文或等待命令。
- 不修改 Core、AI、经济、战斗数值、雾、雷达、存档、Web 或 Xcode 工程文件。

## 云端唯一验证

- 按人工要求禁止所有本地验证，不运行 `git diff --check`、Node/Swift check、Swift tests、Xcode、Simulator、Preview、截图或浏览器验证。
- 只在 `main` 提交本轮相关文件并 push 到 `origin/main`。
- GitHub Actions 必须通过 JUnit 8/0/1、至少 311 项 Core tests、arm64/x86_64 build、production/combat 双 launch、orientation 与像素探针。
- Agent C 下载最新 SHA 对应 artifact，核对 manifest、JUnit、主日志、failure summary、repo state、toolchain、Simulator 信息与双 PNG。
- `ios-home.png` 中选中的 Factory 必须使用清晰青色 primary corners，不能遮挡建筑模型。
- `ios-combat.png` 中 primary Heavy Tank 必须使用青色 marker，其余四个已选单位使用绿色 marker；模型轮廓、炮塔、后坐、弹道、爆点、HUD 和 Tactical Map 不得回退。
