## 问题与目标

`BattlefieldView.synchronizeTouchOwner(with:allowFreshSeed:)` 目前按 event ID 判断 fresh touch。若当前 frame 同时含有新 active ID 和没有被当前 owner quarantine 的旧 ended/cancelled ID，`beginFreshSequence` 可能在有歧义的 frame 直接交接 owner。SwiftUI 现有 callback 没有可依赖的跨 gesture generation token，不能宣称绝对识别旧触点；本轮只增加保守且可测试的 terminal barrier。

本轮目标：

1. `TouchSequenceOwner.beginFreshSequence` 接收可选的同帧 terminal IDs；只要其中存在未 quarantine 的 ID，就拒绝 fresh seed，保留当前 owner 和 sequence，不取消新 active ID。
2. `BattlefieldView` 在 fresh seed 时把同一 `SpatialEventCollection` 的 ended/cancelled touch IDs 传给 owner；混合旧 terminal + 新 active frame 不得直接播种。
3. 后续没有歧义 terminal 的 active frame 仍可正常 seed；既有 terminal-possible handoff、quarantine、pan/area selection、long press、pinch、多指框选和 tap suppression 保持。
4. 用 Core 单测覆盖未知 terminal barrier 与已 quarantine terminal 的允许路径；不改变 GameEngine、命令、战斗数值、生产、存档或 Web 版。

## 实现要求

- `beginFreshSequence(with:terminalEventIDs:)` 的默认参数必须保持既有调用兼容；未知 terminal ID 的拒绝发生在关闭旧 sequence 之前。
- 只有 `terminalEventIDs.subtracting(cancelledIDs)` 为空时，才允许 idle/cancelled/terminal-possible owner 交接；已 quarantine 的旧 ID 不阻塞下一次 seed。
- `BattlefieldView` 只传递当前 touch event collection 中 phase 为 `.ended` 或 `.cancelled` 的 ID；不得把 location、时间、HP、命令或 Core state 写入 owner。
- barrier 拒绝时不得调用 `cancel()`、递增 sequence、清理当前 owner 或把新 active ID 加入 cancelled quarantine；等待后续无歧义 frame 重试。
- 不改变 `TouchSequenceOwner.observe` 对未知 terminal 的既有忽略语义；不改变 replacement rejection、second-finger acceptance、pinch exclusivity、finish/reset 和 cancellation epoch。
- 不添加 timer、Task、延迟命令、随机数、UIKit/WKWebView、Core/GameEngine 字段或存档/JSON 字段。

## 非目标与证据边界

- 不声称能绝对区分 SwiftUI 迟到旧触点与真实新触点；如果旧 callback 在没有 terminal evidence 的 frame 里复用未知 ID，仍需真机/XCUITest 证据。
- 固定 PNG、Core tests 和云端 build 不能证明真实触控 callback 顺序、手指遮挡、VoiceOver、Dynamic Type、真机帧率或全部设备尺寸。
