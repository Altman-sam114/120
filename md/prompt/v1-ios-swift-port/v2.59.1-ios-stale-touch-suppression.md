# v2.59.1 iOS stale touch callback and suppression scope

## 版本与轮次

- 版本：`v2.59.1`
- 主题：以 touch ID/lease sequence 收紧多指结束回调，按序列清理 tap suppression
- 目标分支：`main`
- 实现提交信息：`v2.59.1: gate stale touch callbacks`
- 前置：v2.59 `6ce5127` 的云端 build、Core tests、双架构 iOS build、production/combat launch 与 PNG probe 已通过；代码复核发现 stale callback 与 suppression residual risk。

## 本轮目标

1. 多指结束回调同步失败时，只有当前 lease sequence 与结束帧 accepted touch ID 同时匹配，才允许取消当前 owner；旧回调不得抢占新 owner。
2. 将 tap suppression 与 touch sequence 绑定；多指取消、不同 sequence 或过期窗口不得吞掉下一次独立单指。

## 非目标与架构边界

- 不修改 `RustwarCore`、`TouchSequenceOwner`、GameState、UnitOrder、命中/伤害/冷却、AI、JSON/save schema 或 Web 版。
- 不改变有效双指框选、pinch、pan、long press、context、tap、camera、fog、visibility、生产或升级 action。
- 不添加随机数、定时器、第三方框架或新的输入 owner。
- 保留未跟踪 `.wp`，不提交、不删除。

## 实现契约

- `finishMultitouchSelection` 在同步前保存 terminal touch IDs；`synchronizeTouchOwner` 失败时只有 `multitouchLease`/`pinchLease` sequence 等于当前 owner sequence 且 terminal IDs 与 `acceptedIDs` 有交集，才调用 `cancelMultitouchSequence()`。该路径执行 `cancel()`、`finishCancelledMultitouch()` 和现有局部 teardown；无交集 stale callback 纯 no-op。
- `suppressTapUntil` 配套 `suppressTapSequence`；context、pan 和多指完成传入所属 sequence，`tapIsSuppressed(for:)` 对不同/过期 sequence 清理后放行，多指 cancel 清除两者。其它手势 callback generation、TouchSequenceOwner、preview 和 suppression 时长保持。

## 云端唯一验证

- 禁止本地 SwiftPM test、Swift typecheck、Xcode build/list、Simulator、Preview、浏览器、截图和 `git diff --check`；只做只读源码、状态和提交范围审查。
- 提交前确认当前分支为 `main`、目标为 `origin/main`，范围只包含本轮相关 iOS 源码、README、flow、flowchart、test、prompt 和 update log；`.wp` 不得进入提交。
- Agent C 只验收最新 `origin/main` SHA 对应未加密 Actions artifact 到 `/private/tmp/rustwar-c-review-<run_id>/`，核对 manifest、JUnit、主日志、失败摘要、双架构 build、production/combat PNG 和 pixel probe。
- 云端代码复核确认：stale terminal callback 不会清理新 owner；多指取消后下一次单指点选、拖动、长按可用；v2.59 的战斗视觉、生产摘要、Home/Combat 构图无回退。

## 已知风险

- CI 仍无真实多指/ID 重用/迟到 callback 注入、VoiceOver、Dynamic Type、Reduce Motion 自动化或性能矩阵；artifact 不能证明系统层回调不可区分窗口或真机手感。
