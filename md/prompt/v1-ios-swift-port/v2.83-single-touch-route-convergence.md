# v2.83 原生 iOS 单指触控路径收敛

## 轮次定位

- 版本：`v2.83`
- 基线：`origin/main` 的 v2.82 文档验收 commit `a526302df15cb6f33c08764455ed0bb4c3105738`
- 目标：消除主战场单指 travel 达到 pan 阈值时，`SpatialTapGesture`、零距离 `DragGesture` 和独立 12pt `DragGesture` 之间的 callback 竞争，优先改善 iOS RTS 的拖动平移与框选手感。
- 非目标：不改变 Core、`TouchSequenceOwner`、`SingleTouchTravelPolicy`、GameController 命令语义、生产、BattlefieldScene、模型、战斗特效、HUD、存档或 Web 版。

## 实现要求

1. `BattlefieldView` 只保留一个零距离 `contextLocationGesture` 作为单指 tap/preview/pan/area-selection 路由；移除独立 `tapGesture`（`SpatialTapGesture`）和独立 12pt `dragGesture`，不要复制另一套 threshold state machine。
2. context callback 在 travel `< SingleTouchTravelPolicy.panActivationDistance` 时继续调用已有 `updateBattlefieldTouchPreview`；结束且仍为 `.possible` 时调用现有 `commitSingleTouchTap`，保留直接敌方 Attack、空地 Move/Attack-Move、Builder 和 pending target 语义。
3. 同一 callback 首次达到当前 12pt policy 时：清理 preview，按 `controller.isAwaitingAreaSelection` 只 claim 一次 `.areaSelection` 或 `.pan`，保存 `panGestureLease` / start location / active flag，并用当前 `DragGesture.Value` 立即更新。不得让 tap 或 long press 在已 claim pan 后提交。
4. 阈值后的后续 callback 必须复用统一 helper：普通 pan 使用 `value.translation - lastDragTranslation` 增量调用 `controller.pan(by:)`；area selection 更新 `selectionDragStart/current`。结束时只提交一次 area selection，统一清除 pan lease、selection overlay、translation、preview、callback state；owner 已失效或起点不一致时安全取消，不留下下一次触点可见状态。
5. 保持 `SpatialEventGesture` 的双指 candidate/selection、`MagnifyGesture` 的 pinch、0.45s/18pt long press、tap suppression、fresh-touch terminal barrier 和已有 callback generation 保护。由于 context gesture 现在承载 pan，删除无用的 pan callback generation；pinch/multitouch generation 继续工作。
6. 只更新与本轮真实状态流相关的 README、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md`、本提示词和 `update_log.md`；不得修改 `.wp`、Core fixture、CI workflow、Production、BattlefieldScene 或无关 UI。
