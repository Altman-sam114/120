# v2.63 iOS production availability and accessibility

## 版本与轮次背景

- 版本：v2.63，延续 v2.62 的原生 iOS RTS UX 迭代。
- 总目标 X：让原生 iOS RTS 的生产、操作、UI、模型和战斗可读性超过 Rusted Warfare 的移动端可用性与精致度。
- 上一轮 v2.62：选中 combat unit 时，直接 tap / preview / context 优先解析可见敌方；Builder + combat 混选空地点按保留 Builder Move、combat Attack-Move。实现与收尾文档对应 origin/main 的 v2.62 artifact 已通过。
- 本轮问题：生产卡目前可在金属不足或人口已满时继续点击，只有 Core 返回 Need more metal / Need more pop 后才反馈；这让玩家无法像成熟 RTS 一样在打开建筑后立即判断可生产项。

## 轮次目标

1. 生产卡按 Core enqueueUnit 的同源规则派生只读可用性：
   - 当前玩家金属不足；
   - 当前单位人口加上所有己方生产建筑队列预留人口后超过人口上限；
   - 无效 producer 仍安全返回 unavailable。
2. 可用卡保持现有生产列表顺序、Shift+1-9 快捷键索引、44pt 触控高度、queue/repeat/rally/cancel action 和 Core 结果语义。
3. 不可用卡必须真正 disabled，但仍显示在列表中；卡片用锁图标与文字显示 NEED …M 或 POP …/…，不只依赖颜色。
4. VoiceOver label 保留单位名、metal、population、time；value/hint 朗读 Available 或具体不可用原因。
5. cloud visual production fixture 同时包含可用和金属不足卡片，让 ios-home.png 能证明入口可见、锁定态可读、卡片没有塌缩或裁切。

## 不变量与非目标

- 不修改 RustwarCore public API、GameEngine.enqueueUnit、生产扣款、人口计算、队列、升级、Repeat、Rally、取消退款、存档/JSON、战斗数值、AI 或 Web 版。
- UI projection 可以汇总所有己方 building queue，但不得只看当前 producer queue；不可用卡不得从数组过滤掉，否则会改变 Shift+1-9 映射。
- 不把不可用状态改成点击后才报错；Controller 的 queueUnit 仍保留 Core 结果反馈，防止状态在点击与渲染之间变化。
- 不引入第三方依赖、不重写 HUD 布局、不删除生产入口、不降低 44pt 命中区、不用颜色作为唯一不可用反馈。
- 本轮不处理 Tactical Map stale onEnded callback（留给下一轮），也不处理 SpriteKit 摧毁碎片视觉（留给后续视觉轮）。

## 本地与云端验证

- 本项目制度为云端唯一验证；禁止本地 SwiftPM test、Swift typecheck、Xcode build/list、Simulator、Preview、浏览器、截图和 git diff --check。
- Agent B 只做源码范围审查，确认 productionAvailability 使用当前 metal、当前 supply、所有己方 queued supply 与目标 unit supply；确认生产卡两个快捷键分支同步 disabled、VoiceOver 和 badge。
- Agent B 必须确认当前分支是 main、目标是 origin/main、只提交本轮相关文件，直接 push origin main；保留未跟踪 .wp。
- Agent C 只验收最新 origin/main commit 对应的未加密 Actions artifact：manifest 的 branch、完整 SHA、run id、attempt、v1.2、Xcode 26.5 / iOS Simulator SDK 26.5 / iPhone 17 Pro；JUnit 8 tests / 0 failures / 1 skipped；Swift Core tests、GameController/TacticalProductionSectionView/TacticalHUDTheme 双架构 build、production/combat 双场景启动和 PNG probe。
- Agent C 人工查看 ios-home.png：生产建筑、Factory Tech、队列、可用卡、至少一个 NEED …M 锁定卡和锁图标均在卡片边框内；卡片仍保留可读单位名、M/P/time 与 44pt 最小高度。ios-combat.png 的单位模型、弹道、Attack target、Tactical Map 和 command dock 不回退。
- artifact 不能证明真实资源 tick、VoiceOver 执行顺序、Dynamic Type 全档位、真实点击/键盘 shortcut 或真机触控手感；最终回复必须明确 residual risk。
