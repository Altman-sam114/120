# v1.4 / iOS native enemy AI combat MVP

## 1. Version

- Version: `v1.4`
- Stage: iOS / Swift migration, enemy AI loop.
- Reason: v1.3 added manual native attack orders. The next smallest RTS loop is letting the enemy side use existing production and attack rules so the native battlefield pushes back without Web code.

## 2. Agent X Round Context

- Total goal X: keep improving Rustwar toward a native Swift/iOS RTS while preserving the playable Web Canvas prototype.
- Previous accepted round: v1.3 latest `origin/main` commit `7de868a6c0e77bc145cce48e8bdbea83adcf9c08`, run `28702620574`, attempt `1`, artifact passed Agent C review.
- Current round goal: implement a deterministic minimal enemy AI in `RustwarCore` that queues enemy land units and orders idle enemy units to attack player targets.
- Remaining goals after this round: better target priority, attack-move, turret attacks, AI expansion/building, fog, save/sandbox parity, multi-select commands, richer iOS command panels and Web feature parity.

## 3. Background

Current native baseline:

- `GameEngine.update(deltaTime:)` advances income, production and unit orders.
- Production queues already work for any building once a queue item is present, but public `queueUnit(_:)` only queues for selected player factories.
- `UnitOrder.attack(targetID:)` and attack simulation already support any unit team once an order exists.
- iOS renders all units, HP bars and attack lines from `RustwarCore` state, so enemy attack orders will be visible without SpriteKit owning AI rules.

## 4. Goals

Agent B should implement:

1. Core enemy production AI.
   - Add a small deterministic enemy AI step inside `GameEngine.update(deltaTime:)`.
   - Enemy land factories should queue Scout / Light Tank from their existing `BuildingDefinition.produces` list when affordable, within supply cap, and when their queue is short enough.
   - Reuse or extract the existing production validation/enqueue logic so player production behavior remains unchanged.
   - Keep the AI simple; no difficulty levels, no expansion, no factory upgrades and no Web AI port.

2. Core enemy combat AI.
   - Idle enemy combat units should acquire a nearby or globally reasonable player target and receive `UnitOrder.attack(targetID:)`.
   - Reuse existing attack movement/damage/death cleanup.
   - Do not overwrite manual player orders or player selection.
   - If a target dies, existing cleanup should clear stale orders; improve cleanup only if needed.

3. Determinism and pacing.
   - Keep behavior deterministic across runs.
   - Avoid spawning or issuing orders every frame in a way that floods queues or causes test flakiness.
   - Prefer tiny helper methods over introducing a large AI subsystem.

4. iOS visibility.
   - It is acceptable if no iOS UI files change: SpriteKit already renders enemy units and attack lines.
   - If adding HUD text, keep it compact and do not turn the HUD into a large command panel.

5. Documentation.
   - Update `README.md`, `md/flow/flow.md`, `md/flow/flowchart.md`, `md/test/test.md` if needed, and `update_log.md`.

## 5. Non-goals

- No full Web AI parity.
- No AI base expansion, building placement, resource capture, upgrades, difficulty levels or nukes.
- No attack-move, patrol AI, target priority matrix, formation logic or pathfinding.
- No projectile visuals, sound, fog, save/sandbox migration or UI automation.
- No new third-party dependency, backend, build tool or `WKWebView`.
- Do not touch Web `index.html`, `styles.css` or `app.js` unless required by validation.

## 9. Acceptance Criteria

- Enemy factories can queue at least one supported unit through internal AI without using player selection.
- Enemy queued units consume enemy metal, respect enemy supply cap, and spawn through the existing production path.
- Idle enemy units can receive attack orders against player units or buildings and damage targets through the v1.3 combat path.
- Existing player Move, Attack and factory production behavior still works.
- Swift tests cover enemy AI production, supply/queue guard behavior, enemy attack order assignment and damage through AI.
- Latest `origin/main` GitHub Actions artifact passes Agent C review.
