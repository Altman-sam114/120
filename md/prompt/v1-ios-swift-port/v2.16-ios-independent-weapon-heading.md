# v2.16 iOS Independent Weapon Heading

## 目标

本轮由主线程直接执行，不调用子 Agent。继续参考 Rusted Warfare 官方俯视战斗截图中“底盘保持行进方向、炮塔独立瞄准目标”的机械层级，把原生 iOS 单位从单一整体旋转改为 scene-only hull heading 与 weapon heading 分离，并让现有云端 combat screenshot 直接证明该视觉差异。

## 实现要求

### Scene 朝向状态

- 保留 `unitHeadings` 作为 hull/船体方向：优先读取实际位置差；无位移时只有 Move、Attack Move 和 Patrol 可提供初始行进方向，Attack 不得强制整车转向。
- 新增按 unit id 保存的 weapon heading；只在当前可见攻击目标存在时更新，否则回落到当前 hull heading。
- 显式 Attack 可使用当前可见目标位置；自动火力继续使用既有射程与可见性 gate。不可见或仅雷达 contact 的敌方不得改变精确 weapon heading。
- 炮口焰、projectile 与 beam 必须读取 weapon heading，不再读取 hull heading。
- live id filter、map reset、Load/Restart、effect/decal 上限、fog、Reduce Motion 和 Core cooldown/HP diff 行为保持。

### 程序化模型

- `unitBody` 接收 weapon 相对 hull 的旋转，并创建独立 `weaponMount` 节点。
- Tank、AA Tank、Artillery、Gunboat 的炮塔环、炮塔装甲、炮管和炮口组件必须进入 weapon mount；履带/船体、装甲裙板和阵营标识保留在 hull。
- Hover 的能量发射器、Scout 的轻型炮管/传感器和 Builder 的防卫发射器进入 weapon mount；工程臂仍属于 hull。
- weapon mount 是固定节点，不增加 timer、随机源、texture、Core 字段或存档状态；每帧重绘仍由现有 entityNode 生命周期管理。

### 云端战斗证据

- `--rustwar-ci-combat-visual-smoke` fixture 为双方单位恢复交叉 Attack 目标，使各武器相对默认 hull 出现上/下偏角。
- combat fixture 的 Attack order 只为瞄准提供真实 Core target id；`BattlefieldScene` 在该专用 scenario 隐藏订单线，普通玩家对局仍按 v2.9 绘制全部订单线。
- frozen fire tableau 的 source/target 配对必须与 fixture Attack 目标一致，炮口焰和弹道从旋转后的武器方向射向目标。
- 保留 v2.15 构图、两种 CI launch 参数、双 PNG、双 ImageIO probe、manifest schema v1.2 与 JUnit 8 checks。
