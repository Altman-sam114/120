## 问题与目标

当前 `addUnitFactionMarking` 把 player 单横条或 enemy 双横条放在 hull 中心附近，且默认 zPosition 低于 `weaponMount.zPosition = 1`。炮塔朝向、后坐、projectile terminal 或 impact 与单位重叠时，阵营标记会被部分遮挡；颜色之外的单条/双条形状差异也不够稳定地暴露在 hull 边缘。

本轮目标：

1. 每个单位只增加一个确定性的 `SKShapeNode` 阵营标记，复用一个 compound `CGPath`。
2. Player 使用 hull 尾缘的单 rail / chevron；enemy 使用尾缘上下分离的双 tab。颜色与几何都能区分阵营。
3. 标记作为 `body` 子节点随 hull heading 旋转，不随独立 `weaponMount` 转动或后坐。
4. 标记位于 weapon mount 之上，但几何保持在 hull 尾缘，避免覆盖模型中心、炮口、传感器或关键轮廓。
5. 只改变 SpriteKit presentation；Core、单位半径/命中、目标、伤害、命令、AI、生产、存档和 Web 版全部保持。

## 实现要求

- `addUnitFactionMarking` 创建一个 `CGMutablePath`。Player path 为单个闭合 chevron rail；enemy path 为同一 path 内两个分离 rounded rect subpath。
- 最终只创建一个 `SKShapeNode(path:)`，统一设置接近不透明的 `teamColor(team)` fill、白色半透明 stroke、round join/cap 和刚高于 `weaponMount` 的固定 zPosition。
- 几何只按现有 `radius` 比例派生，不读取时间、随机数、cooldown、HP、选择或全局状态；不创建 `SKAction`、Task、timer、texture 或 per-frame cache。
- 标记继续由 `unitBody` 添加到 hull `body`；不得放入 `weaponMount`、`recoilMount`、world-space `node` 或 effect root。
- 七类单位与 Heavy Tank 必须继续复用同一阵营标记 helper；不得按单位类型复制标记节点。
- Hull/weapon heading 分离、炮塔旋转与后坐、模型几何、selection ring、HP bar、damage state、tracked grounding、fog/visibility、projectile/terminal/impact、64 effect / 32 decal 上限保持。
- `.wp` 保持未跟踪，不得编辑、暂存或提交。
