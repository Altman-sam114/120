# v2.44.3 iOS pan/tap cancellation hardening

## 目标

- 将单指 pan 记录为当前触摸序列的持久状态，SpatialTapGesture 不得在短 suppression 过期后把拖动误派为地图命令。
- 地图 reset/cancel 后，旧 context DragGesture 即使没有回调 `onEnded` 也不能重新激活旧 generation；使用现有 `SpatialEventGesture` 触点 ID 派生的触摸序列世代识别新触摸，下一次触摸即使从同一坐标开始也必须能恢复长按和 tap。
- 保持 v2.44.2 的 pan/long-press 互斥、无活动 reset 不吞首 tap、多指框选/捏合、pending command、建筑 dock 和既有 controller/Core 合同。

## 非目标与边界

- 只修改 `ios/RustwarIOS/RustwarIOS/BattlefieldView.swift` 与本提示词；不修改 Core、GameController、模型、HUD、命令数值、存档或生产升级。
- 不新增 UIKit recognizer、timer、Task、随机数、第三方依赖或新的业务状态。
- 不运行本地测试、格式检查、Swift/Xcode build、Simulator、Preview、截图或 `git diff --check`。

## 验证与交付

- 当前分支必须是 `main`，仅提交本轮文件并直接 push `origin/main`。
- GitHub Actions `Rustwar CI Results` 是唯一验证来源；Agent C 只验收实现 SHA 对应的最新 run/artifact，下载到 `/private/tmp/rustwar-c-review-<run_id>/`，并检查目录大小。
- 核对 `branch=main`、完整 `commitSha`、run/attempt、JUnit 8 checks、0 failures、1 个既定 browser skip、至少 327 个 RustwarCore tests、双架构 iOS build、Home/Combat 双启动、PNG 探针、manifest、主日志和失败摘要。
- 明确记录静态云端证据不能证明真机触控节奏、取消时序、VoiceOver、Dynamic Type、旋转或长期帧率。
