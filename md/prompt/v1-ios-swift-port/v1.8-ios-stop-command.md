# v1.8 / iOS native stop command

## Agent A brief

Version: `v1.8`

Goal: add a native iOS Stop command so the SwiftUI/SpriteKit app can cancel the selected player unit's current move or attack order through `RustwarCore`, matching a core RTS control from the Web prototype.

## Background

- Web Rustwar already supports Stop through keyboard and command buttons.
- The native iOS app has player Move, Attack, production, enemy AI, map switch/restart, pause/speed, and tactical minimap.
- Native move/attack state currently lives in `UnitSnapshot.order`; SpriteKit draws move/attack lines from that order.
- A Stop command should clear the current order in the core model. It should not create a new `UnitOrder.stop` state.

## Functional requirements

1. Add a public `GameEngine.issueStop()` command that:
   - requires an active selection;
   - only succeeds for selected player units;
   - clears `state.units[unitIndex].order`;
   - leaves `state.selectedEntityID` unchanged;
   - does not affect other units or enemy AI orders.
2. Add a precise command result for invalid Stop selection, such as `.selectedEntityCannotStop`, and update exhaustive switches.
3. Add Swift tests covering:
   - no selection rejection;
   - enemy or non-unit selection rejection;
   - clearing a move order without changing selection;
   - clearing an attack order and preventing the stopped unit from continuing that attack on the next tick.
4. Add native iOS controller support:
   - expose whether Stop can currently be issued;
   - implement a Stop action that calls `engine.issueStop()`;
   - clear pending Move/Attack target modes when Stop is tapped;
   - set a concise status message;
   - increment `renderRevision`.
5. Add a native HUD Stop button near Move/Attack with text and a system image, preserving 44 pt minimum tap target.
6. Preserve existing Move, Attack, production, map switch/restart, pause/speed, minimap, and camera controls.
7. Do not add SpriteKit rendering code for Stop; clearing `UnitSnapshot.order` should remove existing move/attack lines naturally.

## Non-goals

- No Web behavior change.
- No `WKWebView`.
- No multi-selection Stop, queue command cancellation, attack-move, patrol, guard, rally point, production cancel/refund, fog, save/load, or sandbox.
- No new third-party dependency or build system.
- No manual browser regression unless the human asks.

## SwiftUI guidance

- Keep shared state in `@MainActor @Observable GameController`.
- Use `Button("Stop", systemImage: "stop.fill", action: controller.issueStopCommand)` or equivalent text-labeled native button.
- Keep command logic in `GameController` / `RustwarCore`, not inline in `GameHUDView.body`.
- Keep 44 pt hit targets and accessible text labels.
