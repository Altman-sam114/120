# v1.48 / iOS native multi-unit Attack

## Agent A prompt for Agent B

### Goal

Move native iOS direct Attack from primary-unit semantics to selected player unit group semantics, matching the existing multi-unit Move, Attack-Move, Patrol, Guard, and Stop behavior:

- If at least one selected player unit is present, `issueAttack(targetID:)` must accept the command even when the primary selected entity is a building, enemy, missing id, or other invalid entity.
- The command must assign every selected player unit the same `.attack(targetID:)` order.
- Invalid selected ids, enemy selected units, and selected buildings must be ignored when at least one selected player unit exists.
- The command must still reject no selection, selections with no player units, missing targets, and friendly targets.
- iOS HUD availability and status text must reflect selected unit groups.

### Non-goals

- Do not modify Web runtime files (`index.html`, `styles.css`, `app.js`) except for required syntax checks.
- Do not change Attack-Move, Patrol, Guard, Stop, Builder commands, attack damage, range, reload, target scoring, turret fire, enemy AI, production, save schema, or target acquisition rules.
- Do not add new buttons, dependencies, build tools, backends, UIKit wrappers, or `WKWebView`.

### Implementation notes

- In `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`, use the same selection pattern as `issueAttackMove(to:)` and `issueGuard(targetID:)`:
  - Guard `!selectedCommandEntityIDs().isEmpty`, returning `.noSelection`.
  - Gather `selectedPlayerUnitIndices()`.
  - Return `.selectedEntityCannotAttack` if no selected player units exist.
  - Validate `combatTarget(id:)` once and require `target.team != .player`.
  - Assign `.attack(targetID: target.id)` to every selected player unit index.
- Keep existing `updateAttackOrder` movement, damage, target death cleanup, and order clearing behavior unchanged.
- In `ios/RustwarIOS/RustwarIOS/GameController.swift`:
  - Change `canIssueAttack` from primary selected unit semantics to `!selectedPlayerUnits.isEmpty`.
  - Change Attack pending text to `Attack target for N units` when multiple selected player units exist.
  - Change `statusText(forAttack:)` success text to `Attack order issued to N units` when multiple selected player units exist.
  - Main battlefield tap and tactical map entity target handling should naturally reuse the core command; no HUD layout changes should be required.

### Tests

Update `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift` with focused coverage:

- Multi-unit Attack assigns the same `.attack(targetID:)` order to every selected player unit.
- Mixed invalid selection with one selected player unit succeeds and only player units receive orders.
- Selection without any player units returns `.selectedEntityCannotAttack`.
- Invalid or friendly target does not replace existing selected unit orders.
- Multi-unit Attack progresses against the same target over updates and clears orders when the target is destroyed.
- Stop only clears selected attacking units and leaves an unselected attacking unit's order intact if that case is not already covered by existing Stop tests.
- Existing single-unit Attack tests must continue to pass.
