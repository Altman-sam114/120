## 版本与轮次

- 上一轮已验收记录提交：`0f95dec53489231b048b15c0d753e1ce333b2dd6`

## 真实证据

v2.54 最新云端 combat PNG（`/private/tmp/rustwar-c-review-32236908308/ios-combat.png`）已确认 `Attack Move` 不再断词，但 `Attack target` hint 的标题与详情最后一行越过内层边框；完整文字仍可读，说明是 outer SwiftUI sizing/proposal 问题，不是文案缺失。当前 compact trailing dock 约 204–224pt 宽，header 位于 ScrollView 外，必须由自身自然增高。

同时，当前 Tactical Map 在约 120×80pt compact map 中把敌方单位绘制为约 3–6pt marker；pending Attack 的 map tap 仍以 `minimumHitRadius=0` 调用既有可见目标筛选，触控容错小于视觉 marker 和手指目标，不符合“点开单位后再次点屏幕即可攻击”的可用性目标。

## 本轮目标

1. 让 battlefield hint 与 command status 的完整多行内容由外层边框/背景包住，保留 natural wrapping、`TARGET MODE`、黄色 attention、VoiceOver 和至少 44pt 触控下限。
2. 只在 Tactical Map `Attack` target pending 时，把地图 view 的约 16pt 屏幕直径换算为 world minimum hit radius，沿既有 `GameController` selection target path 处理最近可见敌人；空点仍保持 pending 以便重试。
3. 保持单点选择、Add/Replace、空地 Attack Move、直接敌人 Attack、多指框选、地图相机拖动、其它 pending 命令和 production/build 不变。

## 非目标与架构边界

- 不修改 `RustwarCore`、`GameStateSelection`、命令结果、命中排序规则、战争迷雾/雷达可见性、`TouchSequenceOwner`、`BattlefieldView`、战斗数值、模型、AI、存档/JSON 或 Web 版。
- 不为其它 target command 全局放大命中区；Guard、Repair、Reclaim、Extractor、Turret、Factory、Radar 和 Move/Attack Move/Patrol/Rally 仍使用原有 radius 参数。
- 不扩大 dock、不侵占 Battlefield、不用固定高度/负边距/透明覆盖掩盖文本、不恢复两行截断。

## 实现契约

- 在两个 outer view 的既有 `frame(maxWidth: .infinity, minHeight: 44, alignment: .leading)` 之后、background/overlay 之前增加垂直 intrinsic sizing 与 `layoutPriority(1)`；内容保持 `.lineLimit(nil)`、`.fixedSize(horizontal:false, vertical:true)` 和既有 accessibility element。
- `TacticalMapView.handleTap` 仅在 `controller.isAwaitingAttackTarget` 时使用 view size 把约 16pt screen diameter 转换为 x/y world radius 的较大值，调用 `handleTacticalMapTap(at:minimumHitRadius:)`；GameController 只把该值用于 pending Attack 的 `handleSelectionTargetCommand`，其它 selection target command 传 0。
- 异常/无效 enemy tap 必须仍保留 Attack pending，成功 Attack 仍清除 pending；目标必须经过既有 `selectionTargetVisibleToPlayer` visibility gate 与 nearest-distance ordering。

## 已知风险

- CI 静态 smoke 不包含 XCUITest、真实 marker 点按、多指/长按/拖拽排序、VoiceOver、Dynamic Type、Reduce Motion 或真机性能；16pt map hit area 只能由代码审查和固定 PNG 间接证明。
- compact trailing header 变高会压缩 dock 下方 ScrollView 的可见高度，但不应改变 dock 宽度或战场区域；需要人工查看双 PNG 确认首屏信息仍无覆盖。
