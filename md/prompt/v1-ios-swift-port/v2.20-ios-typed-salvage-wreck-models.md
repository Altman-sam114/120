# v2.20 iOS Typed Salvage Wreck Models

## 目标

本轮由 Agent X 主线程直接执行，不调用子 Agent。解决原生 iOS 所有可回收残骸都显示为同一个棕色菱形的问题：Core 向后兼容地记录残骸来源，SpriteKit 用原创程序化几何呈现不同单位与建筑的烧毁轮廓，并让云端 combat PNG 同时覆盖单位残骸和建筑残骸。

## Core 数据与兼容

- 新建独立 `WreckSource.swift`，enum 必须是 `Codable / Equatable / Sendable`，穷尽 `.unit(UnitType)` 与 `.building(BuildingType)`。
- `WreckSnapshot.source` 必须为 optional，公开 initializer 默认 nil；旧 JSON 缺少 source 时必须解码为 nil，既有所有手工 WreckSnapshot 调用不要求批量改写。
- `GameEngine.wreck(for unit:)` / `wreck(for building:)` 写入真实来源；salvage、size、team、TTL、资源点释放、Reclaim、AI、选择和订单完全不变。
- 增加 source JSON round-trip 与 legacy missing-field 测试，并扩展现有 destroyed Scout/Extractor 测试断言；预期 Core suite 从 303 增至至少 304 tests。

## SpriteKit 残骸

- `drawWreck` 保留 metal/TTL gate、TTL alpha 和黄色 metal progress bar；残骸主体改为 root node + 来源化固定节点模型，确定性小角度不得使用随机数。
- Tank / AA Tank / Artillery 显示烧毁双履带、破损 hull、炮塔环和对应单管/双管/长炮断管；Hover、Gunboat、Builder/Scout 必须拥有不同外轮廓。
- Command Center / Land Factory、Extractor、Turret、Radar 必须使用不同破损基座、环形或折断设施轮廓；颜色不可成为唯一差异。
- `source=nil` 使用通用不规则碎片堆，保证旧存档仍有可读模型。
- 不新增 timer、Task、SKAction、physics、纹理、网络资源、effect/decal container 或第三方依赖；避免每具残骸过多节点。
