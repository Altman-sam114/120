# v1.82 iOS Radar Station Upgrade MVP

## Agent A Prompt

Role: Agent B implements this prompt on `main`, then Agent C validates the latest `origin/main` GitHub Actions artifact.

## Goal

Add the first native Swift/iOS building-upgrade slice: completed player Radar Stations can start a Level 2 upgrade. The upgrade consumes metal, progresses over time, and on completion improves Radar Station hit points, vision, and radar range. iOS must expose the command from the native HUD without using WebView or web wrapping.

## Non-goals

- Do not add a generic multi-building upgrade tree beyond the data structures needed for Radar Station Level 2.
- Do not add enemy AI upgrade behavior.
- Do not add upgrade cancellation.
- Do not change Web Canvas behavior in `app.js`.
- Do not rewrite the production queue or mix upgrades into unit production.

## Required implementation

- Extend `BuildingSnapshot` with Codable-compatible `upgradeLevel` and `upgradeProgress` defaults so old saves decode as level 1 with no active upgrade.
- Add a `BuildingUpgradeDefinition` model and Radar Station Level 2 definition:
  - level: `2`
  - name: `Radar Station T2`
  - metal cost: `780`
  - build time: `22`
  - hit points: `520`
  - vision: `390`
  - radar range: `1360`
- Keep Radar Station Level 1 values unchanged.
- Add an effective building definition helper so visibility, radar coverage, radar contacts, and building weapon logic can read upgraded values consistently.
- Add a `BuildingUpgradeResult` and a `GameEngine.queueBuildingUpgrade()` command.
- The command must require exactly a selected, completed, living, player-owned Radar Station with an available upgrade, enough metal, and no active upgrade.
- Deduct metal when the upgrade is queued; progress in `update(deltaTime:)`; on completion set level 2, clear progress, increase max HP, and preserve damage taken while adding the new max-HP delta.
- Add native iOS HUD support:
  - Show an `Upgrade Radar` button only when the selected player Radar Station can start the upgrade.
  - Call the new engine command and show command status text.
  - Include accessible label/hint.
  - Reflect upgraded Radar count in the radar VoiceOver summary.
  - Main battlefield and tactical map should keep using Core `radarCoverage(for:)` rather than hard-coded iOS ranges.
- Update docs that describe native iOS status, architecture flow, testing rules, and version history.

## Required tests

Add Swift core tests for:

- Radar Station upgrade definition values.
- Old building JSON decodes with `upgradeLevel == 1` and `upgradeProgress == nil`.
- JSON round trip preserves active upgrade progress and completed level.
- Upgrade command rejects no selection, non-radar, incomplete, enemy, already upgrading, fully upgraded, and insufficient metal cases.
- Queued upgrade deducts metal and records progress.
- `update(deltaTime:)` completes Radar T2 and adjusts HP/max HP.
- Upgraded Radar Station expands `radarCoverage(for:)`, `visibility(for:)`, and `radarContacts(for:)`.
- Radar-only contacts still do not become selectable/attackable by visibility-only APIs.
