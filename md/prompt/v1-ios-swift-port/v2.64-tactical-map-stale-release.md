# v2.64 Tactical Map stale release 修复

## 版本背景

- 版本：`v2.64`。
- 主题：修复原生 iOS Tactical Map 的 stale `DragGesture` release 回调。
- 当前基线：`main` 与 `origin/main` 为 `6d5b308b21d0c63bfe909d62521b6f00e933af74`；未跟踪 `.wp` 必须保留。
- v2.60 已引入 `mapGestureCallbackGeneration` 并保护长按回调；v2.61 补充了 Tactical Map VoiceOver action。
- 当前残留问题是 `mapGesture(in:)` 的 `onChanged` / `onEnded` 没有完整校验 callback generation，且 `onEnded` 的 `defer { resetMapGestureState() }` 位于 stale 判断之前。迟到旧触点可能被当成新触点处理，或清理新触点状态。
- v2.63 生产可用性与锁定卡已经通过云端验收；本轮只处理 Tactical Map 输入生命周期，不回退生产、战斗或 HUD 改动。

## 用户价值

Tactical Map 是移动 RTS 的补充操作区域。迟到 release 可能造成：

- 用户已开始下一次拖动时，旧回调清理新拖动状态；
- 等待 Move、Attack、Attack-Move、Build Extractor 等目标时，旧坐标误提交命令；
- 无等待命令时，旧坐标错误触发相机居中；
- 长按上下文命令释放阶段串发普通 tap。

本轮要让小地图点按、拖动、长按和等待目标提交更接近成熟 RTS 的“每次触摸只产生一个明确意图”。

## 目标

1. 为 Tactical Map `DragGesture` 回调建立可靠的当前 callback generation 门控。
2. 当前触摸的 `onChanged` 才能修改 `mapGestureStartLocation`、`contextPressLocation`、`didRecognizeContextPress`、`isDraggingCamera`、generation 或相机拖动状态。
3. `onEnded` 必须先判断 callback generation 是否仍属于当前触摸。
4. stale `onEnded` 必须直接返回，不能执行 `defer`、`resetMapGestureState()`、`handleTap`、相机移动或 Controller 命令。
5. 有效 `onEnded` 保持以下顺序：

   ```swift
   guard callbackGenerationIsCurrent else {
       return
   }

   defer {
       resetMapGestureState()
   }

   guard !isDraggingCamera, !didRecognizeContextPress else {
       return
   }

   handleTap(at: value.location, in: size)
   ```

6. `onChanged` 在修改手势状态前也必须进行 generation 判断；同一有效触摸的后续 changed/end 必须使用同一 token，不能因 SwiftUI 重绘或首次起点初始化而误判 stale。
7. 保留现有长按 generation gate；长按成功消费后，释放阶段不能再次触发普通 map tap。
8. 保留取消、`@GestureState` 结束、地图重置和正常结束的清理行为，只使用现有 Tactical Map 手势与 Controller 入口。

## 已知 SwiftUI 风险

`DragGesture`、`.simultaneousGesture`、`.onLongPressGesture` 与 `@GestureState` 的结束回调可能乱序：旧触摸 A 先触发 reset，新触摸 B 建立状态，A 的迟到 `onEnded` 才到达。generation gate 可以阻断可区分的旧 callback，但不能绝对区分旧/新坐标完全相同、系统复用 gesture 生命周期或平台不可观测的回调窗口。文档和最终报告必须保留该 residual risk，不能声称已完成绝对时序证明。

## 本轮成功标准

- `onChanged` 与 `onEnded` 都有当前 generation gate。
- stale `onChanged` 不修改状态、不移动相机、不调用 Controller。
- stale `onEnded` 在任何 `defer` 或 reset 前直接返回。
- 有效 `onEnded` 仍只在非拖动、未消费长按时调用 `handleTap`。
- 有效长按只执行一次 context command，释放阶段不串发普通 tap。
- 取消、正常结束、地图 reset 和下一次独立触摸能正确清理并建立 generation。
- pending target、普通 map tap、相机拖动、VoiceOver、fog/radar、命令确认和 Tactical Map UI 无语义回退。
- Core、生产、战斗、存档、JSON、Web 和主战场输入完全不变。
- Agent B 已在 `main` 提交并 push；Agent C 已下载并核对最新 artifact。
- 最终报告明确未做本地测试/build，并保留真机/XCUITest residual risk。
