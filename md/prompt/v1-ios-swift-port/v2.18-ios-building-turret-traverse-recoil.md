# v2.18 iOS Building Turret Traverse And Recoil

## 目标

本轮由主线程直接执行，不调用子 Agent。把 v2.17 的单位 weapon traverse / recoil 机械层级扩展到完成状态建筑 Turret：固定防御基座不转动，炮座按最短角跟踪当前可见射程目标，炮管在开火后独立后坐，并让既有云端 combat screenshot 同时覆盖双方建筑炮塔。

本轮浏览器检索确认 Rusted Warfare Steam 官方页、Mobile Turret 单位视频和实机评测入口存在，但当前环境对 Steam/YouTube 媒体连接关闭，未能可靠读取视频帧；不得把搜索摘要或未加载媒体冒充视觉证据。实现只借鉴“固定底座、独立炮座、短促开火反馈、高对比弹道”的通用 RTS 层级，全部程序化几何保持 Rustwar 原创。

## 实现要求

### Scene 炮座方向

- 保留 `turretHeadings` 为 scene-only 显示方向，只让完成状态且有伤害的 Turret 使用当前可见、射程内的 `nearestBuildingWeaponTargetPosition` 作为期望方向。
- 复用 v2.17 的受限 `visualDeltaTime` 和最短角 `steppedHeading`，为固定 Turret 使用独立的较重转速；SwiftUI 手动 `renderNow()` 仍不得推进角度。
- 新建筑首次获得有效目标时可直接播种目标方向；后续目标切换必须最短角转向。失去可见目标后保留最后炮座朝向，不继续保存目标位置，也不回到任意队伍默认角。
- 雾外或仅 radar contact 的敌方不得刷新精确目标；live-id filter、map reset、Load/Restart 必须清理旧 building heading。
- `accessibilityReduceMotion` 开启时直接对齐当前有效期望方向，不执行连续扫转；不得新增 timer、Task、常驻 `SKAction`、Core heading 字段或 JSON 状态。

### Turret 程序化模型与后坐

- `buildingBody` 接收 turret recoil distance。固定层包含外装甲基座、内炮座环和四向锚固/结构细节；旋转层包含炮盾、中心枢轴和队伍轮廓。
- 在旋转炮座内增加局部 barrel/recoil mount，炮管套筒、内管和 muzzle brake 随 cooldown 回缩；基座、炮座装甲与枢轴不得后坐。
- 从 `BuildingSnapshot.weaponCooldown` 与有效 `BuildingDefinition.reloadTime` 只读推导约 0.14-0.24 秒恢复窗口；位移沿炮管本地负 x，幅度相对 48pt Turret 清楚但不过度。
- Reduce Motion 下 recoil distance 为零；现有 building fire effect、visibility/fog、effect/decal 上限、damage state、施工框架和 health bar 保持。

### Combat fixture 与冻结证据

- `combatVisualSmokeState` 在现有双方装甲阵型中增加玩家/敌方各一座完成状态 Turret；使用正常 `BuildingSnapshot`、有效 HP、rally 和 reload 起点附近 cooldown，不改变普通地图初始建筑。
- 两座 Turret 必须位于当前固定相机和玩家当前视野内，不遮挡既有主力单位、Tactical Map 或 command dock，并各自拥有射程内的可见敌方单位。
- `spawnBuildingFireEffect` 增加默认关闭的 `isFrozen` 参数；普通 cooldown diff 行为不变。combat frozen tableau 为两座 fixture Turret 追加与其实际最近目标一致的 building shot，并至少给一个目标追加既有 impact。
- 保留 v2.17 单位 shots、订单线隐藏、production/combat 两种 launch、双 PNG、双 ImageIO probe、manifest v1.2 和 JUnit 8 checks。
