# v1.41 / iOS native multi-unit Patrol

## Agent A 目标

把原生 iOS 迁移地基中的 Patrol 命令从 primary selection 单单位语义升级为多单位选择语义，使它与 v1.39 Move / Stop、v1.40 Attack-Move 的多选集合行为保持一致。

本轮只推进 Patrol parity，不改 Web 原型，不引入新架构，不扩大到 Guard / Repair / Reclaim / Build 等其它命令。

## 背景

当前 `GameEngine.issuePatrol(to:)` 只读取 `state.selectedEntityID`，因此 Idle Builders / Combat Units 批量选择后，iOS HUD 虽可通过 primary selection 下达 Patrol，但实际只会给一个单位写入巡逻路线。v1.38 已提供 `selectedEntityIDs` 多选集合，v1.39 / v1.40 已提供 `selectedCommandEntityIDs()` 和 `selectedPlayerUnitIndices()` 供 Move / Stop / Attack-Move 复用，本轮应沿用这些 helper。

## 实现范围

### Swift Core

修改 `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`：

- `issuePatrol(to:)` 必须先使用 `selectedCommandEntityIDs()` 判断是否存在可用选择，保持无选择时返回 `.noSelection`。
- 使用 `selectedPlayerUnitIndices()` 过滤当前选择中的己方单位。
- 只要选择集合里至少有一个己方单位，就对所有己方单位写入 `.patrol(...)` 并返回 `.issued`。
- 选择集合存在但没有己方单位时返回 `.selectedEntityCannotMove`。
- 所有被命令单位共享同一个 `destination.clampedToMap()`。
- 每个单位的 `origin` 必须使用该单位下令前自己的当前位置，而不是 primary unit 的位置。
- 不改变 `UnitOrder.patrol` 数据结构、巡逻移动、临时索敌、端点往返或 JSON 存档形状。

### iOS App

修改 `ios/RustwarIOS/RustwarIOS/GameController.swift`：

- `canIssuePatrol` 改为使用 `!selectedPlayerUnits.isEmpty`。
- `togglePatrolCommand()` 的等待态文案在多选时显示单位数量，例如 `Patrol target for 3 units`。
- `statusText(forPatrol:)` 在 `.issued` 时根据当前选中己方单位数量返回单/多单位反馈，例如 `Patrol route set for 3 units`。
- 不新增按钮、不重排 HUD、不改 SwiftUI / SpriteKit 架构。

### Tests

修改 `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift`：

- 增加多选 combat group 下达 Patrol 后，所有选中己方单位均获得 `.patrol` 的测试。
- 覆盖每个单位的 `origin` 等于自身下令前位置，`destination` 等于同一个 clamp 后端点。
- 覆盖混合选择中包含不存在 ID、敌方 ID 或建筑 ID 时，只命令有效己方单位并返回 `.issued`。
- 覆盖选择集合存在但没有己方单位时返回 `.selectedEntityCannotMove`。
- 保持既有单单位 Patrol、巡逻移动、巡逻临时索敌和 Stop 清除 Patrol 测试通过。
