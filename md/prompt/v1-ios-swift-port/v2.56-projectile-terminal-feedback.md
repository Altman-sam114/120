# v2.56 Projectile Terminal Feedback

## 版本与轮次

- 版本：`v2.56`
- 主题：原生 iOS 弹道终点可读性与冻结战斗截图落点反馈
- 目标分支：`main`
- 实现提交信息：`v2.56: sharpen projectile terminal feedback`
- 前置：先完成 v2.55 `v2.55: contain target feedback and improve map hit areas` 的 `main` 提交与最新 Actions artifact 验收，再提交本轮。

## 本轮目标

1. 在既有 `BattlefieldScene.addProjectileEffect` 的弹丸/尾迹之后，于同一目标点增加短暂白色核心、队伍色环和放射 burst，让移动弹道的到达位置比单一弹丸更容易辨识。
2. 冻结 `combat` visual smoke 仍显示静态终点反馈，使云端 `ios-combat.png` 能同时复核炮口方向、弹道路径和落点层级。
3. Reduce Motion 下只保留短透明度反馈，不执行终点层放大、旋转或跨屏移动；终点层必须在既有 bounded effect root 生命周期内完成。

## 非目标与架构边界

- 不修改 `RustwarCore`、`GameState`、命中/伤害/订单、AI、存档/JSON、Web 版或 CI workflow。
- 不新增 projectile event、定时器或持久玩法状态；不改变 Beam、水面命中、陆地焦痕、HP-diff 爆点和毁伤 smoke 的语义。
- 不替换现有程序化单位/建筑模型，不复制 Rusted Warfare 素材；参考只用于高可读战斗层级。

## 实现契约

- 新终点层必须以独立 `SKNode` 挂入当前 `container`，位置使用既有 `target`，并让普通运行在弹丸完成后才 reveal，避免在飞行中提前显示落点。
- 普通运行可使用短 fade/scale/rotation；`accessibilityReduceMotion` 分支只能 opacity fade。冻结 fixture 不运行动作但保留静态目标层。
- 延长既有 bounded root 的生命周期只到覆盖最长弹道及终点 fade 所需的最小值；保持最大 active effects、雾层/可见性门控、地图 reset 和 `effectNode` 层级不变。

## 云端唯一验证

- 本地禁止 SwiftPM test、Swift typecheck、Xcode build/list、Simulator、Preview、浏览器、截图和 `git diff --check`；提交前只做只读源码/状态/范围审查。
- Agent B 必须在 `main` 上确认前置 v2.55 已完成后提交本轮相关文件，并直接 `git push origin main`。
- Agent C 只验收最新 SHA 对应的未加密 artifact 到 `/private/tmp/rustwar-c-review-<run_id>/`，检查目录大小、manifest、JUnit、build log、failure summary、repo/toolchain/simulator 信息、`ios-home.png` 与 `ios-combat.png`。
- manifest 必须匹配 `branch=main`、完整 `commitSha`、run id、attempt、v1.2、Xcode 26.5、iOS Simulator SDK 26.5 和 iPhone 17 Pro；JUnit 目标为 `8 checks / 0 failures / 1 expected browser skip`，其余 Swift Core 数量以 artifact 为准。
- 人工复看 combat PNG：终点核心/环/burst 清晰但不覆盖单位、爆点、HUD 或 Tactical Map；home PNG 无生产与布局回退。失败时只在 `main` 追加最小修复 commit 后重新验收。

## 已知风险

- 固定 PNG 不能证明真实动画时序、HP-diff 爆点的同帧关系、连续战斗性能、真机 Reduce Motion 或触控手感；这些仍需后续云端 UI/性能自动化或真机复核。
