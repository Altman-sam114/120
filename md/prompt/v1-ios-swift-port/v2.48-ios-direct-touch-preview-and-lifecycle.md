# v2.48 iOS direct-touch intent preview and lifecycle

## 轮次定位

- 基线：`df5b5be` / v2.47，`main = origin/main`。
- 目标：继续降低原生 iOS RTS 的触控摩擦，接近 Rusted Warfare 的“按住即知道将执行什么，抬指才提交”的移动 RTS 回路。
- 本轮验证制度：云端唯一验证；禁止本机测试、Swift/Xcode build、Simulator、Preview、截图、浏览器验证和 `git diff --check`。

## 目标

1. 在普通单指尚未跨过 12pt pan 阈值时，根据与最终 tap 相同的命中优先级，显示 presentation-only 触控意图：己方单位/建筑选择、可见敌人 Attack、空地 Attack-Move。
2. 在 Move / Attack / Attack-Move / Rally 等 pending target 状态下显示对应的落点准星；无效 Attack 目标显示明确的不可用样式，但真正命令仍由现有结束事件提交。
3. 无效的 Attack / Guard / Repair / Build / Reclaim 目标提交后继续保留 pending target mode，并以红色准星提示用户重试；成功命令仍退出等待态。
4. 将预览清理接入 pan、第二/第三指、pinch、cancel、long press、地图重置和 tap end，不能让旧预览泄露到新触摸序列。
5. 保持 v2.47 的 touch owner、12pt pan、取消 epoch、context sequence、两指框选和 pinch-only zoom 语义。
6. 固定 combat cloud fixture 进入 Attack target pending，使攻击范围预览具有云端 PNG 证据；混合选择时攻击范围回退到第一个存活己方作战单位；不改变 Core、战斗数值或存档。

## 非目标

- 不修改 `swift/RustwarCore/`、命中半径、命令实现、AI、生产规则、Web 版或 JSON/save schema。
- 不新增 UIKit、WKWebView、第三方依赖、texture、随机数、timer、Task 或常驻 Core 状态。
- 不宣称静态 CI 证明真实 tap、长按、多指、pinch、回调顺序、VoiceOver、Dynamic Type 或真机手感；当前 workflow 没有 XCUITest。
- 不在本轮重排 Production dock；建筑点选的 Replace、Production、Factory Tech 和队列语义必须保持。
