# v2.9 / iOS order-line and health-bar contrast

## 版本

- 版本号：`v2.9`
- 分配依据：Agent A 自动递增；接续已通过云端验收的 v2.8，继续收紧原生 iOS 战场信息层级。本轮只处理选中单位订单线和单位/建筑生命条，不扩大为战斗、模型或 HUD 重构。

## 背景

- v2.8 已提高主战场与战术小地图的选择高亮对比，但复杂地形、雾层和战斗特效下，选中单位的订单线仍可能与背景混在一起。
- `BattlefieldScene.drawUnit` 当前按 `UnitOrder` 分派 Move、Attack、Attack Move、Patrol、Guard、Build、Repair、Reclaim 的只读订单可视化；这些线和端点标记只表达 Core 已有状态，不参与命令执行。
- `drawHealthBar` 同时服务可见单位与建筑。现有生命条较薄、底色和边界偏弱，需要在不新增玩法状态的前提下提高扫读性。

## 目标

1. 为选中单位的八类订单线提供统一的高对比绘制：增加深色 underlay，并提高前景线宽与不透明度，使路线在草地、水面、熔岩、战争迷雾和瞬态特效附近仍容易辨认。
2. 同步增强对应选中态端点标记的描边权重；Move、Attack、Attack Move、Patrol、Guard、Build、Repair、Reclaim 仍保留各自既有颜色、形状和字符语义，颜色不能成为唯一差异。
3. 提高单位与建筑共用生命条的对比：稍增高度，使用更深背景、清晰浅色边框和高不透明度生命值填充；继续保留当前绿/黄/红阈值语义。
4. 保持未选中订单线克制，避免多单位密集战斗时所有路线同时抢占视觉层级。
5. 只通过 `origin/main` 最新提交对应的 GitHub Actions `Rustwar CI Results` 与 artifact schema `v1.2` 验证；本轮禁止任何本地测试、构建、Simulator、Preview、浏览器验证或截图。

## 非目标

- 不修改选择逻辑、`selectedIDs` / 多选集合、选择手势、控制编队、等待命令状态、触觉反馈或命令确认事件。
- 不修改 Web 原型、SwiftUI HUD、Tactical Map、相机、地形、雾、雷达、单位/建筑模型、战斗 projectile/VFX 或音效。
- 不把本轮扩大为正式 sprite/VFX atlas、Core projectile/event 模型、路径队列、Shift 命令队列或完整 Rusted Warfare parity。
- 不增强生产建筑 Rally 线，不修改建造/升级进度条或残骸金属条；它们不属于本轮选中单位订单线与生命条范围。
- 不引入第三方依赖、新资源文件、计时器、随机数、持久视觉状态或存档字段。

## 实现边界

### `ios/RustwarIOS/RustwarIOS/BattlefieldScene.swift`

1. 抽取一个只负责订单线样式的私有 helper，由 Move、Attack Move、Patrol、Guard、Build、Repair、Reclaim、Attack 八条既有绘制路径复用。
2. helper 仅在 `isSelected == true` 时增加黑色或等效深色 underlay；前景线继续使用调用方传入的既有订单颜色。选中态可提高线宽和 alpha，未选中态维持接近旧值的细线与低干扰 alpha。
3. underlay 与前景线必须继续加入既有 `entityNode`，保持当前实体/特效/雾层顺序；不得绕过既有敌方目标可见性门控，也不得写回 Core。
4. 适度提高八类订单端点 marker 的选中态描边宽度，但保留：Move 圆环、Attack 圆环、Attack Move `A`、Patrol `P` 和双端点、Guard `G`、Build `B`、Repair `+`、Reclaim `$` 的既有结构。
5. `drawHealthBar` 继续作为单位和建筑的共享 helper。只调整高度、背景/边框、fill alpha/边框等视觉参数；fraction clamp、宽度、位置、`healthColor` 阈值和调用条件保持不变。
6. 避免为每条订单增加常驻动画、glow action 或逐帧状态。每条选中订单最多增加必要的 underlay 节点，不能引入无界 effect 容器或新的 render loop 工作。
7. 清理本轮触及区域的多余空行并遵守现有 Swift 格式；不要顺带重排整个文件。

## 必须保持的旧行为

- `drawUnit` 对八类 `UnitOrder` 的 switch、目标坐标来源和敌方实体可见性过滤完全不变；不可见敌方不得因订单线泄露精确位置。
- Stop 后 `order == nil` 时订单线自然消失；地图切换、Restart、Load、选择替换/追加、暂停和速度切换的语义不变。
- 选中与未选中单位仍显示各自订单；本轮只提升选中态层级，不能隐藏未选中订单或改变哪些订单会绘制。
- Rally、命令确认 marker、selection ring/corners、伤害烟火、建造/升级进度条、残骸金属条、雷达 contact 和雾层遮挡顺序保持不变。
- 单位与完成/施工中建筑的生命条调用条件、位置、宽度、HP fraction clamp 及绿/黄/红颜色阈值保持不变。
- 不改变 v2.8 selection highlight、v2.1 CI visual smoke 启动参数以及普通玩家启动默认继续运行的行为。

## 风险与控制

- **节点与性能**：选中订单增加 underlay 会增加 `SKShapeNode`。只允许选中订单产生一个额外线节点，不得增加 timer、无限动画或每帧累积节点；沿用每次实体重绘的既有生命周期。
- **视觉遮挡**：过粗订单线可能遮住小单位、目标 marker 或地形信息。underlay 只用于建立边缘分离，前景线和 marker 应保持克制，未选中态不得同步放大。
- **生命条几何**：较高的 bar 和浅色描边可能与 selection ring、建筑角标或相邻实体重叠。维持既有 yOffset/width，仅做小幅高度和描边调整。
- **雾中信息泄露**：Attack、Guard、Build、Repair、Reclaim 的目标线依赖既有 `targetPosition` 门控；不得为了视觉完整性绕开可见性判断。
- **截图覆盖不足**：固定暂停首屏通常能显示单位/建筑生命条，但不保证存在选中且已有订单的单位。Agent C 必须人工核对截图内容；若没有订单线，只能把订单线结论限定为代码路径已编译和 diff 审查通过，不能宣称其像素效果已被首屏截图证明。
- **共享工作区污染**：当前可能存在用户或其他 Agent 的未提交工程设置改动。提交前必须逐文件核对 staged 范围，只纳入 v2.9 相关实现和文档，禁止覆盖、回滚或夹带无关修改。
