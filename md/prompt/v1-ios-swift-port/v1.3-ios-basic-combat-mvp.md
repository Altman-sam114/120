# v1.3 / iOS native basic combat MVP

## 1. Version

- Version: `v1.3`
- Stage: iOS / Swift migration, combat loop.
- Reason: v1.2 added native production; the next smallest RTS loop is selecting a player unit, ordering it to attack an enemy, applying deterministic damage over time, and rendering health.

## 2. Agent X Round Context

- Total goal X: keep improving Rustwar toward a native Swift/iOS RTS while preserving the playable Web Canvas prototype.
- Previous accepted round: v1.2 latest `origin/main` commit `7d838f84a04e76dbb872be16daba5a6f233eb52d`, run `28701455302`, attempt `1`, artifact passed Agent C review.
- Current round goal: implement a minimal native attack / health / death loop for existing units and buildings.
- Remaining goals after this round: attack-move, auto-targeting, turret attacks, AI production/combat use, fog, save/sandbox parity, multi-select commands, richer iOS command panels and Web feature parity.

## 3. Background

Current native baseline:

- `UnitSnapshot` and `BuildingSnapshot` already carry `hitPoints` and `maxHitPoints`.
- `UnitOrder` currently only supports `.move(destination:)`.
- `GameEngine.update(deltaTime:)` advances economy, production and unit movement.
- iOS command flow already uses HUD mode buttons plus the next battlefield tap as a command target.
- `BattlefieldScene` redraws entities each frame and can render order markers without owning simulation rules.

## 4. Goals

Agent B should implement:

1. Core combat data.
   - Add minimal weapon stats to existing unit definitions: attack range, damage per shot and reload/cooldown.
   - Keep values static and intentionally small; do not port the full Web weapon table.
   - Building combat can be deferred unless the implementation can support it with little extra risk.

2. Core attack state and API.
   - Extend `UnitOrder` with an attack target that can refer to enemy units or buildings by ID.
   - Add a small command result enum or extend the existing result shape so invalid attack requests are explicit.
   - Add `GameEngine.issueAttack(targetID:)` or equivalent API that works only for the selected player unit and enemy targets.
   - Clear movement order when attack order is issued.

3. Core combat simulation.
   - Extend `GameEngine.update(deltaTime:)` to advance attack orders.
   - If target is outside weapon range, move toward it using existing unit speed.
   - If target is inside range and cooldown is ready, apply damage to the target.
   - Remove destroyed units/buildings from state and clear selection/order references that point to removed entities.
   - Keep this deterministic and testable; no projectile visuals, no area damage and no friendly fire in this round.

4. iOS command UI.
   - When a player unit is selected, show an Attack button next to Move.
   - Attack mode should use the next battlefield tap to select an enemy entity; tapping empty ground or a friendly entity should produce status feedback rather than mutating state.
   - Keep existing Move and production behavior intact.

5. iOS combat rendering.
   - Render compact HP bars for units and buildings.
   - Render a simple attack line or target marker for attack orders.
   - SpriteKit must remain a view of `RustwarCore` state, not the owner of combat rules.

6. Documentation.
   - Update `README.md`, `md/flow/flow.md`, `md/flow/flowchart.md`, `md/test/test.md` if needed, and `update_log.md`.

## 5. Non-goals

- No full Web combat parity.
- No attack-move, patrol combat, auto-targeting, target prioritization or AI tactical combat.
- No projectile, muzzle flash, explosion, wreckage or sound effects.
- No multi-select or formation combat.
- No fog-of-war, save/sandbox migration or replay system.
- No new third-party dependency, backend, build tool or `WKWebView`.
- Do not touch Web `index.html`, `styles.css` or `app.js` unless required by validation.

## 9. Acceptance Criteria

- Selecting a player unit in iOS exposes both Move and Attack commands.
- Attack mode can target an enemy unit or building by tapping it on the battlefield.
- The ordered unit moves into range if needed, damages the target over time, and destroyed targets are removed from state.
- HP bars reflect damage for units and buildings.
- Swift tests cover attack rejection, damage application, movement into range and destroyed target cleanup.
- v1.1 Move command and v1.2 production queue behavior still work.
- Latest `origin/main` GitHub Actions artifact passes Agent C review.

## 10. Risks and Forbidden Items

- Do not overbuild a complete Web combat subsystem.
- Do not bypass `GameEngine` from SwiftUI or SpriteKit.
- Do not leave orders pointing to removed entities.
- Do not let the selected entity ID reference a removed entity after combat.
- Do not claim local Xcode success if this machine still only has Command Line Tools.
