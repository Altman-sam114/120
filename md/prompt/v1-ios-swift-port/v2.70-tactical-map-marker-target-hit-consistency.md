# v2.70 Tactical Map marker-target hit consistency

## 版本与轮次

- 版本：`v2.70`
- 总目标 X：持续改善原生 iOS RTS 操作，使 Tactical Map 的实体目标点选达到成熟移动 RTS 的稳定、直接和可预期手感。
- 当前轮次：统一 Tactical Map 等待实体 marker 目标命令的触控容错；只处理 Attack、Guard、Repair、Reclaim 与 Build Extractor。
- 建议提交：`fix(ios): v2.70 align tactical map targets`

## 背景与问题

当前 Tactical Map 已把约 `16pt` 屏幕直径换算为 world-space 最小命中半径，但只有 pending Attack 与 pending Build Extractor 使用该容错。Guard、Repair 在 `GameController.handleTacticalMapTap` 中收到 `0`，Reclaim 则在 `handleBuilderTargetCommand` 中忽略传入半径并继续使用 `wreckTarget` 的默认 `95` world 距离。

小地图尺寸约为 `120x80` 到 `160x106`，覆盖 `4200x2800` world；因此直接按单位或建筑真实 world 半径命中 Guard/Repair marker，会形成明显小于可见 marker 的屏幕命中区。玩家看到 marker，却很难在 iPhone 上稳定点中。五类等待 marker 目标必须共享同一触控容错合同。

## 目标

1. 在 `GameController` 集中定义一个只读 predicate，作为 Tactical Map pending marker-target 是否需要最小命中半径的单一真源。
2. predicate 仅在以下等待态为 `true`：Attack、Guard、Repair、Reclaim、Build Extractor。
3. `TacticalMapView` 不再自行列举 Attack/Extractor；它只询问该 Controller predicate，并在为 `true` 时沿用现有约 `16pt` 屏幕直径到 world radius 的换算。
4. `GameController.handleTacticalMapTap` 把同一个 `minimumHitRadius` 转发给 Builder target resolver 和 Selection target resolver。
5. Attack、Guard、Repair、Reclaim、Build Extractor 都实际消费该半径，同时继续复用现有最近合法目标、目标资格、结果反馈和 pending 生命周期。
6. 不改变点位命令、普通小地图操作、Core、存档、Web 或主战场输入。

## 实现范围与要求

### `ios/RustwarIOS/RustwarIOS/GameController.swift`

- 新增一个内部只读 predicate，建议命名为 `usesTacticalMapPendingMarkerHitRadius`，精确表达以下集合：

  ```swift
  isAwaitingAttackTarget ||
      isAwaitingGuardTarget ||
      isAwaitingRepairTarget ||
      isAwaitingReclaimTarget ||
      isAwaitingBuildExtractorTarget
  ```

- predicate 不得直接复用宽泛的 `isAwaitingTargetCommand`，因为 Move、Attack Move、Patrol、Rally、Turret、Factory、Radar 与 Select Area 不是 marker-target snapping 命令。
- `handleTacticalMapTap(at:minimumHitRadius:)` 在 point command 与 area-selection 优先级不变的前提下，把收到的 `minimumHitRadius` 原样传给：
  - `handleBuilderTargetCommand(at:minimumHitRadius:)`；
  - `handleSelectionTargetCommand(at:minimumHitRadius:)`。
- 不再只为 Build Extractor 或 Attack 单独转发半径；resolver 自己根据当前 pending flag 选择合法路径。
- `handleBuilderTargetCommand` 的 Reclaim 分支必须调用：

  ```swift
  engine.state.wreckTarget(
      at: point,
      maxDistance: max(95, minimumHitRadius)
  )
  ```

  可以按项目命名冲突需要写成 `Swift.max`，但语义必须严格等价。默认 `minimumHitRadius == 0` 时仍保持旧 `95` world 半径。
- Build Extractor 继续调用 `resourceTarget(at:maxDistance:)`，并保持 `max(56, minimumHitRadius)`。
- Guard 与 Repair 继续调用 `selectionTargetsVisibleToPlayer`，先按现有距离与稳定顺序排序，再用既有资格 predicate 选择第一个合法目标；不得先选最近非法目标后直接失败。
- Attack 继续调用 `selectionTargetVisibleToPlayer(... targetTeam: .enemy)` 并消费同一 `minimumHitRadius`。
- 不新增第二套命令派发、目标类型或状态字段；最终命令仍调用现有 `issueAttack`、`issueGuard`、`issueRepair`、`issueReclaim`、`issueBuildExtractor`。

### `ios/RustwarIOS/RustwarIOS/TacticalMapView.swift`

- 保留现有 `pendingTargetTouchDiameter = 16` 与 `minimumWorldHitRadius(for:screenDiameter:)` 换算，不改变屏幕直径、world map 尺寸、横纵轴取大值或相机映射。
- `handleTap` 只根据 `controller.usesTacticalMapPendingMarkerHitRadius` 决定是否计算和传递 world-space 最小命中半径。
- View 不得继续重复列举 Attack、Guard、Repair、Reclaim 或 Extractor flags；命令集合由 `GameController` predicate 集中维护。
- 不改变 Canvas 绘制、marker 尺寸、fog/radar、pending badge、确认 marker、VoiceOver action/value/hint 或地图 accessibility button 语义。

## 必须保持的行为

- 最近合法目标规则保持：同一命中区内仍按距离排序，距离相同继续使用既有 units-first 与稳定实体顺序。
- Attack 只能命中当前真实可见的敌方单位或建筑；雾外敌方和 radar-only contact 仍不可被精确 Attack。
- Guard 只允许友方单位或建筑，并排除没有任何非目标选中单位可执行护航的情况；目标自身不能成为唯一执行者。
- Repair 只允许受损友方单位或建筑，并要求至少一个非目标选中 Builder 可维修；满血目标和自我维修非法。
- Reclaim 只允许 `metal > 0` 且 `ttl > 0` 的有效残骸；耗尽、过期或缺失残骸继续拒绝。
- Build Extractor 继续服从空闲资源点、claimed/occupied、资源、Builder 与 Core 最终校验。
- 成功命令退出对应 pending mode；无效目标与既有可重试结果继续保持 pending，并显示现有错误反馈。
- Move、Attack Move、Patrol、Rally、Turret、Factory、Radar 等点位命令不使用实体吸附或 marker hit radius。
- 普通 Tactical Map tap 仍居中相机；无 pending 时拖动相机仍以 `18pt` 激活，长按上下文、同次长按消费、callback generation 与 stale callback gate 不变。
- pending 状态仍禁止 Tactical Map 相机拖动；当前 context、generation 和 reset 生命周期不变。
- 主战场 44pt 命中、直接点按、触控预览、长按、单指 pan、双指框选、pinch、`TouchSequenceOwner` 和 sequence suppression 不变。
- Core `GameStateSelection` 的可见性、排序与默认半径不变；不修改 `RustwarCore`、GameState、订单、AI、战斗数值、存档/JSON schema 或 Web 版。
- VoiceOver、Differentiate Without Color、Reduce Motion 与现有 Tactical Map accessibility actions 不变。
