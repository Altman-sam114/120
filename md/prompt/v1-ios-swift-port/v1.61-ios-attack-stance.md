# v1.61 / iOS native attack stance

## 角色

你是 Agent B，负责在 `main` 上实现本轮 v1.61。开始前必须阅读 `README.md`、`AGENTS.md`、`update_log.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和本提示词，并先执行 `git fetch origin`、`git switch main`、`git pull --ff-only origin main`、`git status --short --branch`。

## 目标

补齐原生 iOS 的最小攻击姿态语义，对齐 Web 的 `Z / X / V` 作战单位控制：

- Web 三态为 `aggressive` / `defensive` / `holdFire`，热键分别是 `Z` / `X` / `V`。
- iOS 当前没有单位姿态状态、HUD 按钮或键盘入口。
- 本轮为 `RustwarCore` 的玩家作战单位增加姿态状态和设置 API，让 Attack-Move / Patrol / Guard 的临时自动索敌按姿态缩放范围：Aggressive 使用完整视野，Defensive 使用较短范围，Hold Fire 不自动获取临时目标。
- 手动 Attack 仍允许 Hold Fire 单位攻击点选目标，保持 Web “停火单位仍可执行手动攻击”语义。

## 非目标

- 不修改 Web `app.js`。
- 不实现完整 Web 空闲自动索敌；当前原生 core 只有 Attack-Move / Patrol / Guard 临时索敌，本轮只约束这些自动目标获取。
- 不新增弹道、攻击优先级 UI、目标列表、阵型、Shift 队列、敌方姿态 AI、存档迁移版本号或 iOS UI 自动化。
- 不改变 Move / Attack / Attack-Move / Patrol / Guard / Stop / Repair / Reclaim / Build 等已有命令合法性。
- 不改变炮塔自动开火；建筑没有单位姿态。

## 实现建议

- `swift/RustwarCore/Sources/RustwarCore/UnitAttackStance.swift`
  - 新增 `public enum UnitAttackStance: String, Codable, CaseIterable, Sendable`。
  - case 建议为 `.aggressive`、`.defensive`、`.holdFire`。
  - 提供 label / shortLabel / autoEngagementRangeMultiplier，分别对应完整视野、约 0.68 视野、0。
- `UnitSnapshot.swift`
  - 新增 `attackStance: UnitAttackStance`，默认 `.aggressive`。
  - 保持 Codable 旧存档兼容：旧 JSON 缺字段时默认 `.aggressive`。
- `GameEngine.swift`
  - 新增 `setAttackStance(_:) -> [String]` 或等价 API，只作用于当前选中存活己方作战单位。
  - 作战单位定义：玩家单位、存活、`GameDefinitions.unit(type).attackRange > 0`，可包含 Builder，因为当前 native Builder 有武器；不作用于建筑、敌方、死亡或缺失 id。
  - Attack-Move / Patrol / Guard 临时目标获取的 `maximumDistance` 应乘以姿态 multiplier；Hold Fire 为 0 时不自动获取临时目标。
  - 手动 `issueAttack(targetID:)` 和既有 `.attack(targetID:)` 推进不受姿态阻止。
  - 若设置 Hold Fire 时选中单位当前有因 Attack-Move / Patrol / Guard 临时获取而正在执行的普通 `.attack` 不易区分，可不清理已有手动 Attack；本轮不要重构 `UnitOrder` 为带 resume 的复杂结构。
- `GameController.swift`
  - 新增 `canSetAttackStance`、当前选中姿态摘要、`setAttackStance(_:)` wrapper 和状态文案。
  - HUD 文案能显示当前姿态或混合姿态，至少在 `commandStatus` / selected summary 附近可见。
- `GameHUDView.swift`
  - 当选择中有己方作战单位时显示 Aggressive / Defensive / Hold Fire 三个按钮。
  - 用 SF Symbols，不要用纯文本假图标；按钮保持现有 44pt 触摸目标、自适应网格。
  - 绑定外接键盘 `Z` / `X` / `V`，无 modifiers。
- `RootGameView.swift`
  - 如现有全屏 key handling 会吞掉字母，确保 `Z` / `X` / `V` 仍能由 HUD shortcut 或 controller 接收；不要破坏 WASD / 方向键相机平移。

## Swift tests

至少覆盖：

- 新 `UnitSnapshot` 旧 JSON 缺 `attackStance` 时解码为 `.aggressive`。
- 设置姿态只影响当前选中己方存活作战单位，不影响敌方、建筑、死亡或缺失 id。
- Defensive 的 Attack-Move 临时索敌范围短于 Aggressive。
- Hold Fire 的 Attack-Move / Patrol / Guard 不自动获取目标，但手动 `issueAttack` 仍会造成伤害。
- 多选混合无效 id 时，只要存在合法己方作战单位就设置合法单位。
