# v1.86 / iOS Extractor T3 economy upgrade parity

## 目标

在原生 Swift/iOS 迁移线上补齐玩家 Extractor T3 经济升级，使 iOS 版 Extractor 升级链从 T1 -> T2 延伸到 T3，并继续复用现有 `BuildingSnapshot.upgradeLevel`、`upgradeProgress`、`GameEngine.queueBuildingUpgrade()`、`cancelBuildingUpgrade()`、SpriteKit 升级进度条和 HUD `Upgrade Extractor` / `Cancel Upgrade` 控件。

Web 对齐数值来自 `app.js` 的 `buildingTypes.extractor.upgrades`：

- T2：650 metal、20 秒、18 income、760 HP、290 vision。
- T3：1250 metal、32 秒、32 income、1020 HP、340 vision。

## 非目标

- 不新增 Resource Fabricator。
- 不新增敌方 AI Extractor 升级。
- 不改 Web 原型、存档格式、升级取消公式或通用升级 UI。
- 不新增第三方依赖、构建工具、WKWebView 或后端。

## 实现要求

- `GameDefinitions.building(.extractor).upgrades` 增加 level 3 的 `Extractor T3`。
- `GameDefinitions.nextUpgrade(for:)` 现有多级逻辑应继续用于 T2 -> T3，不新增平行状态机。
- `GameDefinitions.building(for:)` 应在 `upgradeLevel == 3` 时返回 T3 HP、income 和 vision。
- iOS HUD 对已升级 Extractor 的摘要不能固定显示 `Extractor Level 2`，应显示实际等级。
- 现有 T2 升级、取消和无效选择行为必须保持。

本地轻量检查至少运行：

```sh
git diff --check
node --check app.js
swiftc -module-cache-path /private/tmp/rustwar-swift-module-cache-v186 -typecheck swift/RustwarCore/Sources/RustwarCore/*.swift
swiftc -parse swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift

```

修改 `swift/RustwarCore/` 时应尽量运行：

```sh
swift test --package-path swift/RustwarCore
```

若本机 SwiftPM / PackageDescription / SDK mismatch 阻塞，必须记录真实错误，并以上述直接 typecheck / parse 作为源码级轻量检查。

修改 `ios/RustwarIOS/` 时应尽量运行：

```sh
xcodebuild -list -project ios/RustwarIOS/RustwarIOS.xcodeproj
xcodebuild -project ios/RustwarIOS/RustwarIOS.xcodeproj -scheme RustwarIOS -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

若本机只有 Command Line Tools，必须记录真实错误，等待 GitHub Actions macOS runner 复判。

## main push 与 Agent C 验收

Agent B 完成后只提交本轮相关文件到 `main`，直接 `git push origin main` 触发 `.github/workflows/ci-results.yml`。

Agent C 必须只验收 `origin/main` 最新 commit 对应的 GitHub Actions run，下载未加密 artifact 到 `/private/tmp/rustwar-c-review-<run_id>/`，核对：

- manifest 的 `branch=main`。
- manifest 的 `commitSha` 等于 `origin/main` 最新 commit。
- run id、run attempt 与下载 artifact 一致。
- `junit.xml`、`build.log`、`ci-failure-summary.md` 一致。
- `git diff --check`、`node --check app.js`、`swift test --package-path swift/RustwarCore`、`xcodebuild -list` 和 iOS build 的真实结果。

若 CI 或 artifact 复判不通过，必须退回 Agent B 在 `main` 上追加修复 commit，不得伪装通过。
