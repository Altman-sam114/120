# v1.97 / pinned cloud Apple toolchain

## 目标

修复 `macos-latest` 在 Xcode 16.4 / iOS 18.5 与 Xcode 26.5 / iOS 26.5 之间漂移的问题，使用户要求的云端唯一验证具有可复判、可比较的 Apple 工具链证据。

## 实现范围

- `.github/workflows/ci-results.yml` 固定 `macos-26` runner 和 Xcode 26.5 `DEVELOPER_DIR`。
- 新增独立 toolchain gate、`toolchain-info.txt`、JUnit testcase 和 manifest 字段。
- CI artifact schema 从 v1.0 升到 v1.1。
- `actions/checkout` / `actions/upload-artifact` 升级到 Node 24 runtime 对应 major。
- 同步 README、flow、flowchart、test 和 update log。

## 必须满足

1. job 使用 `runs-on: macos-26`，`DEVELOPER_DIR=/Applications/Xcode_26.5.app/Contents/Developer`。
2. toolchain gate 必须检查目录存在、`xcodebuild -version`、Simulator SDK、macOS 和 Swift 版本；Xcode 不等于 26.5 或 SDK 不等于 26.5 时整体失败。
3. toolchain 失败时 `xcodebuild -list` / build 明确标为 skipped，不能回退到默认 Xcode 后伪装通过。
4. `toolchain-info.txt` 必须记录 runner OS/arch/name、macOS、DEVELOPER_DIR、Xcode、build version、Simulator SDK、Swift 和 gate exit。
5. manifest v1.1 必须增加同名结构化字段与 `toolchainOutcome`，并把 toolchain info 列为 project-specific report。
6. JUnit 增加 `pinned Xcode 26.5 toolchain`，总计 7 checks；browser smoke 仍是唯一预期 skipped。
7. toolchain gate 必须进入 failure summary 和 overall success 条件。
8. artifact 名称升级为 `rustwar-ci-v1.1-...`，旧 artifact 只保留历史意义。
9. 使用 `actions/checkout@v5` 和 `actions/upload-artifact@v5`，避免继续依赖被弃用的 Node 20 action runtime。
10. 不修改游戏代码、Core、Xcode project、部署目标、存档、素材或测试数量。

## 云端唯一验证

用户禁止本地测试，因此不得本地解析 YAML、运行 action、Swift、Xcode、Simulator 或浏览器测试。push 后以 GitHub 是否创建 run、run 是否完成、v1.1 artifact 是否可下载作为 workflow 语法和行为证据。

提交信息：

```text
ci(v1.97): pin Apple toolchain
```

Agent C 下载唯一 v1.1 artifact 到 `/private/tmp/rustwar-c-review-<run_id>/`，核对 manifest、7 项 JUnit、toolchain-info、主日志、失败摘要和 repo state。缺少 Xcode 26.5 时必须失败并保留 artifact，不得自动降级。
