## 目标

1. 在输入层建立唯一、可测试的 `TouchSequenceOwner` reducer，明确每个 touch sequence 的 owner、accepted IDs、cancelled IDs 和 sequence/epoch。
2. 迟到的 `SpatialEventGesture`、context drag、tap、long-press、pan 或 magnify callback 只能被丢弃或清理 presentation preview，不能夺取新 sequence，也不能重复提交 selection/command。
3. 禁止因一个 accepted touch 消失而自动把另一个未知 ID 继承为同一单指 owner；只有明确的 fresh-sequence seed 才能开始新 sequence。
4. 保留既有 Rusted Warfare-like 行为：
   - 单指点己方单位/建筑：Replace/Add、重复点按循环和生产/升级上下文不变。
   - 已选单位点空地：Builder-only 为 Move，含 combat unit 为 Attack-Move。
   - 已选 combat unit 点可见敌军：Attack。
   - 长按上下文：敌军 Attack、友军 Guard/Repair、资源/残骸/生产建筑既有语义不变。
   - 两指同向移动框选己方单位；明确张合 pinch 只缩放；第三指/取消安全终止。
5. reducer 只负责输入生命周期，不向 Core GameState、JSON、存档或玩法模拟增加状态。

## TouchSequenceOwner reducer 设计

### 状态

使用一个明确的 `TouchSequenceOwner<ID: Hashable>`（或等价纯 reducer），不得再让 `battlefieldTouchID` 单独承担 owner 身份。最少包含：

- `sequence` 或 `epoch`：每个新 sequence/cancel 边界单调递增一次。
- `phase`：`idle/possible/pan/areaSelection/longPress/multitouch/pinch/cancelled`，与现有 `BattlefieldTouchIntent` 对应。
- `acceptedIDs`：当前 sequence 已登记的全部 touch IDs；不能只保存一个 primary ID。
- `cancelledIDs`：当前 cancellation quarantine 中的旧 IDs；迟到事件不得重新接受。
- `primaryID`（可选）：仅供单指 context/drag 预览稳定使用，不能替换 accepted-ID 集合。
- 必要的 `hasFreshSeed`/`cancelReason` 标记，用于区分显式 fresh seed 与未知 active touch。

Reducer 不保存屏幕坐标、Core entity ID、命令或存档数据；坐标/分类输入由 `BattlefieldView` 提供，命令仍由 `GameController` 提交。

### 允许的事件/转移

1. `idle -> possible`：仅由明确 `begin/seed` 登记一个 fresh ID；`fresh ID` 不得出现在 `cancelledIDs`。
2. `possible + second fresh ID -> possible`：登记第二指；不要因不同步到达而立即取消。第二指出现后由现有 classifier 决定 selection 或 pinch。
3. `possible -> pan/areaSelection/longPress`：只有对应 gesture 已通过现有距离/时间和 Controller pending 条件后 claim；claim 后 owner 锁定，其他 gesture callback 不得提交动作。
4. `possible/multitouch -> multitouch`：两指 sequence 只能由 `SpatialEventGesture` owner 管理；selection preview 可更新，但 tap/long press/pan 必须被抑制。
5. `possible/multitouch -> pinch`：只有 classifier 返回 `.pinch` 后 claim；只有 pinch owner 能调用 `controller.zoom`。
6. `multitouch/selection/pinch` 收到第三个 active ID：转 `cancelled`，清除 preview，禁止自动挑选/替换 primary；不要把第三指当 replacement。
7. owner 已锁定后收到未知 ID、旧 ID 的迟到 changed/ended、或不匹配 sequence/epoch：返回 ignored/stale；最多 teardown preview，不得改变新 owner、selection、pending command 或 `battlefieldTouchSequence`。
8. accepted ID 结束：从 active bookkeeping 移除，但不能把未知 replacement ID 自动加入当前 sequence。多指 owner 可等待全部 accepted IDs terminal；若 SwiftUI callback 无法安全判断，终止该 sequence 并要求下一次明确 fresh seed。
9. `cancel(ids/reason)`：将当前 accepted IDs 合并进 `cancelledIDs`，phase=`cancelled`，递增 sequence/epoch 一次；tap/long-press/pan/context end 只能被拒绝或 teardown。
10. `reset/mapRenderRevision`：调用 cancel/reset boundary，清除 preview、selection drag、multitouch geometry 和 Controller tap cache；保留旧 ID quarantine，直到明确 fresh seed。不得用任意未知 active callback 清除 quarantine。
11. `finish` 必须幂等：同一 sequence 的迟到 end 不得再次递增 epoch、清空新 owner 或重复调用 `handleBattlefieldMultitouchAreaSelection`。
12. 普通单指 `SpatialEventGesture.onEnded` 不得独自完成/重置 Battlefield 单指 owner；只有真实多指 sequence 的 finish 才能提交一次框选并收尾，延续 v2.47 既有约束。

### BattlefieldView 集成要求

- `BattlefieldView.swift:89-94` 的并行手势可以保留，但每个 callback 必须先通过同一个 reducer owner/epoch gate。
- `tapGesture` 在 `:130-148` 只在 owner=`possible`、当前 sequence 匹配且未取消时调用 `controller.handleBattlefieldTap`。
- context/long press 在 `:151-310`、`:94-119` 只能使用当前 owner 的 primary/epoch；迟到 end 不得写回 `.possible`。
- pan/area selection 在 `:313-387` 只能由 pan/area owner 更新和提交；普通拖拽跨过 12pt 后继续抑制 tap/long press。
- pinch 在 `:389-409` 只能由 pinch owner 改 zoom；selection owner 不得触发 magnify。
- multitouch 在 `:412-634` 负责登记 IDs、调用既有 classifier、更新框选 preview，并且只在有效 owner finish 时调用 Controller 一次。
- `:712-770` 的地图 reset/cancel 必须经 reducer；清除 SwiftUI 局部 presentation state 不得解除旧 ID quarantine。
- 保留 `clearLastBattlefieldTap()` 在 pan/multitouch/pinch/命令成功路径上的既有调用，避免误触发 v2.48 重复点按循环。
