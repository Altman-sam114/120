# v1.66 / iOS native guard formation offsets

## 角色

你是 Agent B，负责在 `main` 上实现本轮 v1.66。开始前必须阅读 `README.md`、`AGENTS.md`、`update_log.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和本提示词，并先执行 `git fetch origin`、`git switch main`、`git pull --ff-only origin main`、`git status --short --branch`。

## 目标

把 v1.64-v1.65 已建立的稳定方阵思想扩展到原生 Swift core 的多单位 Guard 命令，减少多选部队护航同一友方目标时围到同一点导致的重叠。

- 单选 Guard 保持原行为：使用现有 `guardOffset(for:around:)` 算出的单位相对目标偏移。
- 多选 Guard 根据选中己方单位生成稳定护航偏移，每个单位仍使用 `UnitOrder.guardTarget(targetID:offset:)`。
- 多选 Guard 的偏移应该按单位当前位置稳定排序，并围绕被护航目标中心形成分散方阵；目标可以是友方单位或建筑。
- 目标移动时，现有 Guard 更新逻辑继续用保存的 offset 追随目标，不新增新订单类型。
- iOS 现有 Guard 按钮、主战场长按友方目标、战术小地图实体目标和外接键盘 H 入口都应通过 `GameEngine.issueGuard(targetID:)` 自动复用，不需要新增 UI。

## 非目标

- 不修改 Web `app.js`。
- 不实现完整寻路、碰撞避让、动态阵型朝向、队列命令、Shift 追加队列、攻击目标队形、Repair/Reclaim/Build 队形、运输语义或 UI 自动化。
- 不新增 Swift core 存档字段、命令类型、iOS target、第三方依赖或构建链。
- 不改变 Move、Attack-Move、Patrol、Attack、Repair、Reclaim、Build、Stop、生产、AI、选择、控制编队或小地图交互语义。
- 不用 `WKWebView` 或网页包装。

## 实现建议

- `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`
  - 保留 `issueGuard(targetID:)` 对外 API。
  - 增加 private helper，例如 `guardFormationOffsets(for:around:)`，输入选中单位 indices 和 `CombatTarget`，输出 `(unitIndex, offset)`。
  - 单位数 0：沿用旧错误结果。
  - 单位数 1：沿用旧 `guardOffset(for:around:)`，保持单选兼容。
  - 多个单位：按与 `formationTargets(for:around:)` 相同的单位排序语义和间距策略生成围绕目标中心的方阵 offset，而不是所有单位只用各自当前位置到目标的临时偏移。
  - offset 应以目标中心为原点，不需要 clamp；实际移动目标仍由现有 `target.point + offset` 和地图 clamp/移动逻辑处理。
  - 不改变 Guard 自动索敌、攻击姿态范围、目标销毁清理或返回护航点逻辑。
- `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift`
  - 更新旧的多单位 Guard 测试，不再只接受各单位原位置相对目标的偏移重叠语义。
  - 增加或调整测试覆盖：
    - 多选 Guard 给每个选中己方单位分配分散 offset，平均偏移接近目标中心周围的零点。
    - 多选 Guard 对友方单位目标和友方建筑目标都能分散 offset。
    - 单选 Guard 仍使用旧 `guardOffset` 行为。
    - Same Type、附近同类、控制编队或区域选择后复用 Guard 的旧覆盖若存在，应改为断言多单位护航 offset 分散。

## 验收标准

- 选择多个己方作战单位后 Guard 同一个友方目标，不再所有单位保存接近同一护航点的 offset。
- 单选 Guard、无选择、只选建筑、敌方目标、自我护航等旧结果保持不变。
- Guard 自动索敌、攻击姿态、目标销毁清理、Stop 清除和 iOS 现有入口无需新增按钮即可复用新 core 行为。
