# v1.74 / iOS tactical map context long press

## 角色

你是 Agent B，负责在 `main` 上实现本轮 v1.74。开始前必须阅读 `README.md`、`AGENTS.md`、`update_log.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和本提示词，并先执行 `git fetch origin`、`git switch main`、`git pull --ff-only origin main`、`git status --short --branch`。

## 目标

为原生 iOS 战术小地图增加无等待命令状态下的长按上下文命令入口，让它更接近 Web 小地图右键的高频语义，并复用 v1.63 主战场上下文派发和 v1.73 可见性过滤：

- 长按当前可见敌方单位或建筑：若当前选择可攻击，则直接下达 Attack。
- 长按友方单位或建筑：若当前选择包含 Builder 且目标受损，则 Repair；否则若当前选择可护航，则 Guard。
- 长按残骸：若当前选择包含 Builder，则 Reclaim。
- 长按空闲资源点：若当前选择包含 Builder，则 Build Extractor。
- 长按空地点：若当前选择是生产建筑，则 Rally；否则若当前选择有己方单位，则 Move。

普通点按小地图仍保持现有语义：有等待命令时下达等待命令；无等待命令时居中相机。

## 非目标

- 不修改 Web `app.js`。
- 不新增 Swift core 状态、命令类型、存档字段或测试-only API。
- 不实现完整 Web 小地图右键语义、运输装载/接载、Shift 队列、核弹、卸载、闪现、上下文菜单、目标吸附、放大镜、触觉反馈或 UI 自动化。
- 不改变主战场 tap / long press、Select Area、战术小地图等待态点按、外接键盘或 HUD 按钮行为。
- 不用 `WKWebView`、UIKit gesture overlay 或第三方依赖。

## 实现建议

- `ios/RustwarIOS/RustwarIOS/TacticalMapView.swift`
  - 在现有 `DragGesture(minimumDistance: 0, coordinateSpace: .local)` 中记录最近位置，用于长按结束时换算世界坐标。
  - 增加 SwiftUI 长按手势，触发时调用 controller 的 tactical context 方法。
  - 长按触发后必须避免同一次触摸在 `mapGesture.onEnded` 中继续执行普通点按居中或等待态命令；抑制状态应在同次触摸结束时清理，不能吞掉下一次正常点按。
  - 小地图长按只在无等待命令时执行上下文命令；如果正在等待 Move / Attack / Build / Rally / Select Area 等命令，应给出轻量状态文案或忽略，继续让现有点按等待态负责。
- `ios/RustwarIOS/RustwarIOS/GameController.swift`
  - 新增 `handleTacticalMapContextCommand(at:)` 或等价 public 方法。
  - 复用现有 `issueContextCommand(at:)`、`statusText(...)`、多选集合和合法性校验。
  - 不复制一套新的上下文派发逻辑。

## 验收标准

- 无等待命令时，长按小地图空地点能让当前选中己方单位 Move，或让当前选中生产建筑 Rally。
- 无等待命令时，长按小地图当前可见敌方单位或建筑能让当前选中己方单位 Attack；不可见敌方仍按 v1.73 过滤，不能被上下文命令精确攻击。
- 无等待命令时，长按小地图受损友方单位或建筑能让选中 Builder Repair；长按健康友方单位或建筑能让选中单位 Guard。
- 无等待命令时，长按小地图残骸能让选中 Builder Reclaim。
- 无等待命令时，长按小地图空闲资源点能让选中 Builder Build Extractor。
- 普通小地图点按、等待态小地图点按、主战场触控、战术小地图 VoiceOver 说明和外接键盘仍保持既有行为。
