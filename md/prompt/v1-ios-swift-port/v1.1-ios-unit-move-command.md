# v1.1 / iOS native unit move command MVP

## 1. Version

- Version: `v1.1`
- Stage: iOS / Swift migration, first command interaction.
- Reason: v1.0 added the native Swift core and iOS battlefield foundation. The next smallest user-visible step toward a real iOS RTS is a native move command loop, because it proves touch input can mutate Swift game state and SpriteKit can render simulation changes.

## 2. Agent X Round Context

- Total goal X: keep improving Rustwar toward a native Swift/iOS RTS, while preserving the playable Web Canvas prototype.
- Previous round: v0.5 Agent X workflow baseline passed CI artifact review on `origin/main` commit `14f966a6371e814a1be4f1c087a59444724bd1ca`, run `28681634116`, attempt `1`.
- Current round goal: implement a minimal native iOS unit move command.
- Remaining goal after this round: production queue, combat, AI, fog, save/sandbox parity, and richer iOS controls.

## 3. Background

Current native baseline:

- `swift/RustwarCore` has map presets, initial `GameState`, income tick, supply/economy helpers and point selection.
- `GameEngine.update(deltaTime:)` only advances metal income.
- `UnitSnapshot` has position and stats, but no order or destination.
- `ios/RustwarIOS` renders terrain/resources/entities with SpriteKit and supports tap select, drag pan and pinch zoom.
- `GameHUDView` only shows economy, reset and selected summary.

This round should add the first command path without trying to match the full Web command system.

## 4. Goals

Agent B should implement:

1. Core move order model.
   - Add a small `UnitOrder` or equivalent value type in `RustwarCore`.
   - Store optional order/destination on `UnitSnapshot`.
   - Add `GameEngine.issueMove(to:)` or a similarly named API that only affects the currently selected player-owned unit.
   - Return a useful success/failure value so the iOS layer can update command mode or status text.

2. Core movement simulation.
   - Extend `GameEngine.update(deltaTime:)` to move ordered units toward their destination using `UnitDefinition.speed`.
   - Clamp each tick as the current engine already does.
   - Stop and clear the order when the unit reaches the target.
   - Keep movement deterministic and covered by Swift tests.

3. iOS command UI.
   - Add a compact Move command control to the HUD when the selected entity is a player unit.
   - Track a simple command mode in `GameController`, for example idle vs awaiting move target.
   - When Move mode is active, the next battlefield tap should issue the move command instead of changing selection.
   - Provide visible HUD feedback while awaiting a target.
   - Keep pan and pinch zoom working.

4. SpriteKit feedback.
   - Render moving units at their updated positions automatically.
   - Draw a small destination marker or command line for active move orders if practical in this round.
   - Do not rewrite the renderer into a large new architecture.

5. Documentation.
   - Update `README.md` iOS section and operation notes to mention the native move command.
   - Update `md/flow/flow.md` and `md/flow/flowchart.md` if state/command flow changes.
   - Update `md/test/test.md` only if validation commands or scope change.
   - Append `v1.1 / iOS native unit move command MVP` to `update_log.md`.

## 5. Non-goals

- No full Web command parity.
- No pathfinding, obstacle avoidance, terrain passability, formations or multi-select movement.
- No attack move, patrol, guard, stop, repair, reclaim, transport, nuke or build placement.
- No production queue.
- No combat, weapons, projectiles, damage or AI.
- No fog/radar/save/sandbox migration.
- No changes to `index.html`, `styles.css` or `app.js` unless a validation-only compatibility issue is discovered.
- No third-party dependencies and no `WKWebView`.

## 6. Current Architecture Basis

- Web remains directly runnable via `index.html`.
- `RustwarCore` owns native game state and deterministic logic.
- `GameController` owns `GameEngine`, `CameraState`, render revision and iOS command state.
- `BattlefieldView` converts gestures into controller calls.
- `BattlefieldScene` reads `GameState` and renders; it should not own gameplay rules.
- `GameHUDView` exposes native command controls.

## 8. Implementation Steps

1. Start from synchronized `main`.
   - Run `git fetch origin`.
   - Run `git switch main`.
   - Run `git pull --ff-only origin main`.
   - Run `git status --short --branch`.
   - Stop and report if remote/auth/network blocks push or if unrelated dirty changes appear.

2. Add core move order support.
   - Keep the model small and Codable/Equatable/Sendable like existing snapshots.
   - Do not add broad command abstractions until needed.
   - Ensure only player units can receive this command from the public API.

3. Add iOS command mode.
   - HUD Move button should be shown only when it can do something.
   - Tapping Move should not immediately move; it should arm target selection.
   - Next battlefield tap issues the move and exits move mode.
   - Add a cancel path if simple, such as tapping Move again or selecting another unit.

4. Update renderer.
   - Continue redrawing from `controller.engine.state`.
   - Add destination marker/line only if it stays small and stable.

5. Update tests and docs.
   - Add Swift tests for issuing move to player unit, rejecting enemy/no selection, moving over time, and clearing order on arrival.
   - Document that v1.1 is a single-unit movement MVP, not full RTS command parity.

6. Commit and push.
   - Stage only related files.
   - Commit message: `v1.1: add native iOS unit move command`
   - Push directly to `origin/main`.

## 11. Acceptance Criteria

- A player unit can be selected in the iOS app and given a move target through native SwiftUI/SpriteKit interaction.
- The selected unit moves over time in Swift core state and rendered SpriteKit position follows.
- The move order clears when the target is reached.
- Enemy units and buildings cannot receive this MVP move command through the public controller path.
- Swift tests cover the new movement behavior.
- Web prototype remains untouched and directly runnable.
- Local checks are run or toolchain blockers are reported honestly.
- Latest `origin/main` GitHub Actions artifact passes Agent C review.

## 12. Risks and Forbidden Items

- Do not turn this into pathfinding or combat.
- Do not use a WebView.
- Do not bypass `GameEngine` by moving SpriteKit nodes directly as the source of truth.
- Do not leave command mode stuck after a target tap.
- Do not hide Swift/iOS build failures behind local-only statements.
