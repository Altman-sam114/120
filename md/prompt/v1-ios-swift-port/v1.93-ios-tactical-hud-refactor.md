# v1.93 / iOS tactical HUD component refactor

## 目标

在 v1.92 已通过云端验收的原生 SwiftUI HUD 基础上，重构布局和基础组件边界，降低 `RootGameView` 与 `GameHUDView` 的职责密度，并统一更清晰的战术视觉层级。保持现有玩法、操作、快捷键和响应式断点结果不变。

## 实现范围

- 新增 `TacticalHUDLayout.swift`：集中管理三档 layout role、dock 尺寸、bottom dock 高度和 Tactical Map 尺寸；`RootGameView` 只消费一次计算出的 metrics。
- 新增 `TacticalHUDComponents.swift`：集中管理资源指标、命令状态、带图标分区标题、eager 命令网格和统一按钮样式。
- 精简 `RootGameView.swift` 与 `GameHUDView.swift` 中已迁出的重复布局/样式代码。
- 更新 Xcode project，把两个新 Swift 文件加入 `RustwarIOS` target。
- 同步 README、flow、flowchart、test 和 update log。

## 必须保持

1. 390x844 compact bottom、650x390 / 844x390 / 874x402 compact trailing、700x520 / 1024x768 regular trailing 的分类和尺寸结果不变。
2. 短横屏仍优先于 700pt regular 判断；compact trailing 为 30%、224-260pt，短高 Tactical Map 为 120x80。
3. Commands、Build & Upgrade、Production、Selection、Groups、Session 的顺序、条件渲染、action、disabled 状态和 eager layout 不变。
4. 所有 keyboard shortcut、VoiceOver label/value/hint、Differentiate Without Color、Dynamic Type、Reduce Motion 和 44pt 最小触控目标保持。
5. 不修改 `GameController`、`BattlefieldScene`、`TacticalMapView`、`RustwarCore`、存档、战斗数值、Web 或素材。
6. 不引入 UIKit haptic generator、第三方依赖、WKWebView 或设备型号判断。

## 视觉要求

- 顶栏指标使用统一、低干扰的战术信息块，数值保持高对比和等宽数字。
- 六个命令分区用 SF Symbols、文字和细分隔线共同建立层级，不只依赖颜色。
- 普通 command status 与等待目标 command status 都具有明确边界；等待态继续用图标、文字、填充和描边组合。
- 按钮圆角不超过 8pt，文本最多两行，长标题不得重新截断。

## 云端唯一验证

用户明确禁止本地测试。本轮不得在本机运行 `git diff --check`、Node、Swift parse/typecheck、`swift test`、`xcodebuild`、Simulator、Preview 或浏览器测试。
