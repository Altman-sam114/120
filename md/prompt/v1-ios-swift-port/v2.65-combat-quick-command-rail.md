# v2.65 Combat Quick Command Rail

## 版本背景

- 版本：`v2.65`。
- 主题：把原生 iOS RTS 的核心 Combat 操作固定到 command dock header 下方，减少“选中单位后还要滚动才能 Move / Attack-Move / Attack / Stop”的操作摩擦。
- v2.62 已经修正 Core 与 `GameController` 的 direct-touch 意图：可见敌方优先 Attack，空地对作战单位 Attack-Move，Builder-only Move，空闲 Builder + combat 混选分流为 Move + Attack-Move；本轮不重写这些语义。
- v2.64 已经修正 Tactical Map stale release callback；本轮只新增 command dock presentation，不回退输入生命周期修复。

## 用户价值

移动 RTS 的高频操作应在选中单位后立即可见：

- `Move`：普通移动仍可直接进入落点模式；
- `Attack Move`：点地移动并自动攻击射程内敌人；
- `Attack`：选择可见敌方单位或建筑；
- `Stop`：立即取消订单或当前目标等待态。

当前这些 primary command 只在可滚动 command section 中出现；生产/建筑上下文或长 dock 内容会把它们推离首屏。本轮固定一个只读 presentation rail，复用同一 Controller action，令选中单位后无需先滚动。

## 目标

1. 在 `TacticalCommandDockView` 的固定 header 与 `ScrollView` 之间显示 `Quick Orders` rail；只有存在存活己方单位选择时显示。
2. Rail 依现有资格显示 `Move`、combat 可用时显示 `Attack Move` / `Attack`，以及 `Stop`；按钮直接复用 `toggleMoveCommand`、`toggleAttackMoveCommand`、`toggleAttackCommand`、`issueStopCommand`。
3. 当前命令等待态按钮继续显示 `Cancel` 语义；Stop 保持取消所有等待态和已选单位订单的现有路径。
4. Rail 出现时，滚动 `TacticalCommandsSectionView` 不重复渲染 primary Move / Attack-Move / Attack / Stop；Patrol、Guard、stance、Repair、Reclaim、Area、Same Type 等 secondary controls 仍位于滚动 section。
5. Rail 的 `Attack Move` 保留裸 `A` 快捷键，`Stop` 保留裸 `S` 快捷键；隐藏的 primary grid 不得造成快捷键丢失或重复注册。
6. Dynamic Type accessibility size 使用单列布局；默认字号使用两列；所有按钮继续消费 `tacticalControl()`，保持至少 44pt 触控高度。
7. VoiceOver 必须朗读 Quick Orders header、命令名称、Ready/Waiting for target、取消 hint 和动作目的；不以颜色作为唯一反馈。
8. `battlefieldInteractionHintTitle/detail` 明确说明 Quick Orders 的 Move / Attack-Move affordance；Builder-only 不能继续错误提示 Attack-Move。

## 必须保持的语义

- `BattlefieldView`、`TacticalMapView`、`TouchSequenceOwner`、RustwarCore、UnitOrder、命中半径、fog/radar、Replace/Add、双指框选、pinch、长按、生产、战斗数值、AI、存档/JSON 和 Web 版不变。
- Rail action 必须调用现有 Controller action，不能新增第二套 Move / Attack / Stop mutation，也不能把 UI 快捷操作直接写入 Core。
- `TacticalCommandsSectionView` 的 secondary command 顺序、production/build section、dock selection reset 和滚动行为保持。
- 混合 Builder + combat 的 Move / Attack-Move 分流仍由现有 `handleDirectTapCommand` / Core 路径负责；Rail 只进入既有 pending target toggle。

## 非目标

- 不重构 `GameController` 命令系统或 Core API。
- 不改变主战场 direct tap：空地、敌方、Builder-only 和混合选择继续使用 v2.62 已验收路径。
- 不新增 UIKit、第三方依赖、XCUITest、持久化字段、网络依赖或 Web 版 UI。
- 不把 `.wp` 或 CI artifact 加入提交。
- 不在本机运行测试、build、Simulator、Preview、浏览器或 `git diff --check`。

## 已知风险

固定 rail 会提高选中单位时 dock header 的高度；需要 Agent C 查看 combat PNG，确认它没有挤压战场、Tactical Map 或状态栏。若未来需要更高密度，可单独迭代为横向 icon+label compact 方案，但本轮不牺牲 44pt 和可读性。
