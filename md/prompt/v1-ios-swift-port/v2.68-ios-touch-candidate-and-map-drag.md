# v2.68 iOS touch candidate arbitration and Tactical Map drag threshold

## 版本与角色

- 版本：`v2.68`
- 执行者：Agent B；只在 `main` 上实现并直接 push `origin/main`，不创建 PR。
- 当前基线：`main=origin/main=114b7d4228f2b0faa4b261fcc85048b8ac10439e`。
- 目标：继续改善原生 iOS RTS 的双指/长按竞争和战术小地图轻拖手感，同时保持 Core 与既有命令语义不变。

## 现状证据

- `BattlefieldView` 同时挂载 `SpatialEventGesture`、零距离 context `DragGesture`、`SpatialTapGesture` 和 `onLongPressGesture`；Spatial 回调观察到第二个 active touch 后，需要先阻止同一 sequence 尚未提交的单指 commit。
- Tactical Map 的 camera drag activation 为 22pt，而 long press maximum distance 为 18pt；18–22pt 移动可能既取消长按又未进入相机拖动，释放时落入普通 map tap。
- `CameraState.worldPoint`、`BattlefieldScene.syncCamera` 与 `spritePoint` 已形成正确可逆的屏幕↔世界映射，本轮不因静态猜测修改 Y 轴。

## 本轮目标

1. 在 `BattlefieldView.updateMultitouchSelection` 中，当前 owner 为 `.possible` 且当前 Spatial 事件有至少两个未取消 active touch 时，按当前 `TouchSequenceOwner.sequence` 记录一个 candidate。
2. candidate 记录必须发生在 `synchronizeTouchOwner` 前；若同一帧由 fresh seed 建立 owner，则在同步后、claim `.multitouch` 前补记 candidate。
3. `onLongPressGesture` 与 `commitSingleTouchTap` 只能在当前 sequence 没有 candidate 时提交单指命令；candidate 只清除既有主战场 preview 与 `GameController.clearLastBattlefieldTap()`，不改变 Core 状态。
4. candidate 必须按 sequence 作用域化，并由既有多指 finish/cancel/reset 清理；不能污染下一次 fresh seed。
5. `TacticalMapView` 将 camera drag activation 与 long-press maximum distance 统一为 `18pt`，消除 18–22pt 灰区；保留 callback generation、等待态禁止相机拖动和所有现有 map action。

## 非目标与边界

- 不修改 `CameraState.swift`，除非云端编译暴露与本轮直接相关的 API 问题；不改变 `BattlefieldScene.syncCamera`、`spritePoint` 或世界坐标。
- 不修改 `TouchSequenceOwner`、`MultitouchIntentClassifier`、`GameController`、Core `GameState`、UnitOrder、命中半径、生产、战斗、AI、JSON、存档或 Web Canvas。
- 不改变 12pt 主战场 pan activation、0.45s 长按时长、双指 selection/pinch classifier、第三指/replacement/cancel 规则、pending target、VoiceOver 或 44pt command controls。
- 不使用 timer、Task、随机数、UIKit 私有触摸 API、第三方框架或新的持久化字段。
- 不宣称 candidate 能解决 Spatial callback 尚未到达或系统无法区分的旧/新触点窗口；这些仍是 XCUITest/真机风险。

## 精确实现契约

### BattlefieldView

- 新增 sequence-bound `multitouchCandidateSequence` presentation state。
- `markMultitouchCandidate(in:)` 只在 owner `.possible`、事件中至少两个未取消 active touch 时写入当前 sequence，并清理 touch preview 与 last battlefield tap cache。
- 在 `updateMultitouchSelection` 的 `synchronizeTouchOwner` 前调用该 helper；同步后再次确认 active touch 数量，确保 fresh seed 同帧也能在多指 claim 前记录 candidate。
- long press guard 与 `commitSingleTouchTap` guard 都要求 candidate 不匹配当前 sequence。
- 不让 candidate 自己 claim multitouch、不直接调用 Controller command、不绕过 TouchSequenceOwner；现有 classifier、claim、finish 和 teardown 仍是唯一多指命令路径。
- 既有 `resetMultitouchSelectionState()` 清掉 candidate；owner sequence 变化也必须让 stale candidate 自动失效。

### TacticalMapView

- 保留单一 `cameraDragActivationDistance` 常量，将其值设为 `18`。
- `onLongPressGesture` 使用该同一常量作为 `maximumDistance`；其它 onChanged/onEnded generation gate、defer reset、pending target 与 map tap path 不变。
