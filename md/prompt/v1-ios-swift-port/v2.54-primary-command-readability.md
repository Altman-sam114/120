## 本轮目标

1. 在 compact trailing dock 中消除 `Attack Move` 的视觉省略/错误断词；核心命令仍按 `Move`、`Attack Move`、`Attack`、`Stop` 的既有优先级显示。
2. 让 `Stance Aggressive`、`Stance Defensive`、`Stance Hold Fire` 在普通 Dynamic Type 下不依靠不可读的缩放或单行硬截断；可使用既有 `UnitAttackStance.shortLabel` 作为视觉短名，但 VoiceOver 必须保留完整 stance 名称。
3. 让 pending target status/hint 自然换行并保留命令身份，不覆盖 Battlefield 或 Tactical Map；无效目标重试和 Stop/Cancel 语义保持。
4. 保持所有按钮至少 44pt 触控区、Replace/Add、键盘快捷键、action、disabled 条件、Differentiate Without Color、Reduce Motion、VoiceOver label/value/hint 和 section 顺序。

## 实现契约

### Primary command tiles

- `Move`、`Attack Move`、`Attack`、`Stop` 的 can/awaiting 条件、controller action、快捷键和顺序不得改变。
- primary layout 必须真正消费父级 compact `columns` policy，或提供等价的宽度感知布局：`Attack Move` 不得出现 `At-tac...`、单字母残片或不可读缩写。
- 可以让 `Attack Move` 获得完整宽行、显式的 `Attack`/`Move` 两行排版，或在视觉上使用明确的短名；若使用短名，VoiceOver label/value 必须仍为完整 `Attack Move`。
- 不得把核心命令移回 secondary section；不通过降低字体到不可读大小解决问题。
- pending 时视觉上可继续显示 `Cancel` 以保持按钮紧凑，但必须通过 `accessibilityLabel` / `accessibilityValue` / `accessibilityHint` 表明 `Cancel Move target`、`Cancel Attack Move target`、`Cancel Attack target` 或等价完整语义。

### Stance and selection summary

- 视觉可使用 `shortLabel` 或自然换行；不得把 `Hold Fire` 误写成可改变玩法含义的 `Stop`。
- 完整 stance 名称必须在 VoiceOver value/hint 中保留，且 Aggressive / Defensive / Hold Fire 仍由图标、active 描边和文字共同表达。
- Selection summary、stance summary 和 upgrade summary 在普通及 accessibility Dynamic Type 下不得使用固定单行 + 过度 `minimumScaleFactor` 造成省略；允许自然增加高度并由 dock ScrollView 承担。

### Target status and hint

- pending status 必须至少包含当前命令身份和下一步动作；例如 `Attack target` + `Tap a visible enemy...`。
- 文字使用自然垂直尺寸；不要用透明、浮层、负边距或强制缩小隐藏内容。`TARGET MODE` 标签、黄色 attention 描边和图标继续保留。
- Hint/status 的完整内容必须通过 accessibility value 暴露；无效目标仍保留 pending mode 以便用户重试，成功命令仍退出 pending。

### Architecture and compatibility

- 本轮只改 SwiftUI/SpriteKit HUD presentation/accessibility；不得修改 `RustwarCore`、`UnitOrder`、命中半径、TouchSequenceOwner、BattlefieldView、BattlefieldScene、战斗数值、AI、存档/JSON、Web 版或 CI workflow。
- 不新增第二套 selection/command 状态，不把显示文本写入 GameState。
- 不新增第三方依赖或 WebView。
