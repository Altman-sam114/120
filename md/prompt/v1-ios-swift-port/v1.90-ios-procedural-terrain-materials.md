# v1.90 / iOS procedural terrain materials

## 基线与目标

本轮基于已经通过云端 artifact 验收的 v1.89 `main`，继续改善原生 iOS 战场表现。公开 Rusted Warfare 截图中的地形重点是清晰的大地貌、可辨识的海岸和熔岩边界，以及低噪声但不单调的地表细节。只借鉴这种视觉语言，不复制或提交原作素材。

当前 `BattlefieldScene.drawTerrain` 为每个 44pt tile 创建一个纯色 `SKShapeNode`，一张地图约 6,000 个节点，草地、水面、岩地和熔岩主要依靠单一色块区分。本轮在不修改 Core 地形或玩法的前提下，建立确定性、聚合式的程序化地形材质。

## 实现要求

1. `TerrainGrid` 仍是唯一地形事实来源，渲染代码只读 `TerrainKind`、column、row 和现有 tile size。
2. 基础填色按 `TerrainKind` 和 3 档确定性色差聚合为少量 compound `CGMutablePath`，不能继续为每个 tile 保留一个独立 SpriteKit node。
3. 色差必须由稳定整数 hash 生成；禁止使用 `Hasher`、随机数、时间或每帧变化，保证同一地图每次加载完全一致。
4. 每种地形保持独立可读：
   - grass / grass2：低对比草痕和轻微明暗变化；
   - dirt / sand：稀疏颗粒或短划痕；
   - rock：较硬的裂线/碎石点；
   - water / deep：短水平波纹，deep 更暗；
   - lava：暗底上的短亮裂隙，不使用全屏 glow/filter。
5. 只检查右侧和下侧相邻 tile，聚合绘制一次边界，避免重复线段：
   - water/deep 与陆地之间绘制深色岸脚和浅色泡沫线；
   - water 与 deep 之间绘制克制的深度分界；
   - lava 与非 lava 之间绘制深色焦岸和橙色热边。
6. 地图外边界不得借用 `TerrainGrid.terrain` 的 grass fallback 制造假海岸；相邻检查必须先验证 column/row bounds。
7. 所有细节路径在 `drawTerrain` 的地图重建时一次生成，不能在每帧 `renderNow` 重建、动画或增长。
8. terrain node 仍位于 resource/entity/effect/fog/radar 下方；浅雾和深雾必须继续覆盖所有地形细节。
9. 不改变 `TerrainKind`、可通行性、命中、资源点、相机、地图尺寸、雾、雷达和战斗逻辑。
10. 使用少量聚合节点，目标是从约 6,000 个基础 tile node 降到几十个基础/细节 node；不得以每 tile 多个 node 换取视觉提升。

## 视觉与性能边界

- 纹理对比度必须低于单位、建筑、选择环、HP 条和命令线，不得让地表抢夺战术信息。
- 颜色不使用装饰性渐变、模糊、Core Image filter、动态光照或无限粒子。
- 路径数量和节点数量应由地形类型/色阶/细节类别决定，而不是随 tile 数量线性增长。
- tile compound path 可轻微重叠以避免缩放时出现背景裂缝，但不能明显覆盖海岸或改变地图轮廓。
- helper 应明确区分基础色、稳定 hash、细节路径、相邻边界和聚合节点职责。

## 验收标准

1. `drawTerrain` 不再为每个 tile 添加独立 `SKShapeNode`。
2. 8 种 `TerrainKind` 都有确定性色差和符合类型的低噪声细节。
3. 海岸、深浅水和熔岩边界只绘制一次，地图边缘不产生 grass fallback 假边界。
4. 同一 `TerrainGrid` 重绘结果稳定，不依赖随机状态或时间。
5. 地形重建只在既有 map id / `mapRenderRevision` 变化时发生。
6. terrain 仍在 fog 下，敌方可见性、雷达和战斗特效层级不变。
7. Core、存档、玩法、HUD、Tactical Map、Web 和 Xcode project 无 diff。
8. Swift parse 和 iOS build 通过；若本机只有 Command Line Tools，记录原始阻塞并由最新 Actions artifact 复验。

本机有完整 Xcode/Simulator 时，额外检查三张地图：海岸线连续、深浅水可分、熔岩边界清晰、正常 zoom 无明显 tile 裂缝，且单位/建筑仍比地表更醒目。环境不可用时明确写未运行视觉 smoke。
