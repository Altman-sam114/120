# v2.50 iOS production focus bar

## 版本与分配依据

- 版本：`v2.50`。
- 当前基线：`origin/main` 的 v2.49 实现，当前读取到的 commit 为 `53de1e209623e965907b356df0abab4530fbcdee`；Agent B 实现前仍必须同步最新 `origin/main`。
- 分配依据：v2.49 已收敛 Builder / Combat 命令资格；本轮只处理生产建筑上下文的 presentation 层，是一个不改变 Core 语义的最小 UX 增量。

## 背景

当前原生 HUD 已经具备生产建筑优先级、Factory Tech、生产按钮、当前生产进度、完整队列、Cancel Last、Repeat、Rally 和升级/取消升级入口，但这些信息分布在固定 header 与可滚动 Production / Build & Upgrade section 中。玩家点 Command Center 或 Land Factory 后，应立即看到“能生产什么、现在造什么、后面排了什么、工厂/建筑升级处于什么状态”，不能依赖猜测滚动位置。

本轮参考公开 Rusted Warfare 的信息组织，不复制素材或界面资产：

- [App Store 公开页面](https://apps.apple.com/us/app/rusted-warfare-rts/id1514329124)：只提炼 minimap、multi-touch、unit groups、rally points、strategic zoom 和手机/平板适配所体现的“快速读状态、少走层级”原则。
- [Steam 公开页面](https://store.steampowered.com/app/647960/Rusted_Warfare__RTS/)及其公开媒体：只观察右侧生产面板中 producer/build options、当前项目进度、后续队列和管理动作的层级关系。

## 本轮目标

实现一个 `Production Focus Bar`，作为 command dock 的固定 presentation 摘要：

1. 选中己方 Command Center / Land Factory 后，固定 header 立即显示生产上下文；不新增 Core 状态、UnitOrder、队列字段、升级字段或存档 schema。
2. 由现有 `GameController` 派生值驱动焦点条：建筑名称、T1/T2、生产倍率、可生产列表、当前队首、真实进度/剩余时间、队列数量/后续类型、Factory Tech 升级状态。
3. 选中完成状态己方 Extractor / Radar Station 且没有 producer 时，可复用同一 presentation 容器显示等级、升级进度、下一等级费用和 disabled/ready 状态；具体 Upgrade / Cancel action 仍由既有 Build & Upgrade section 提供。
4. 保留现有 Production section 的可操作按钮、队列轨道和管理动作；焦点条是单一只读摘要，不建立第二套生产或升级状态。
5. 点建筑导致 selection identity 变化时，dock 继续无动画回到顶部；焦点条必须先于可滚动内容可见，避免旧滚动位置遮住生产入口。

## 非目标与禁止项

- 不修改 `swift/RustwarCore/` 的生产、队列、升级、退款、Repeat、Rally、人口或资源规则；不新增 Core API，除非只是现有只读 snapshot 缺少编译所需的最小访问入口，并须先报告理由。
- 不改变 Web 版、AI、战斗数值、地图、存档兼容、命令资格、直接点按、手势 owner 或 Tactical Map 语义。
- 不重写 `RootGameView` 的三档布局断点，不扩大 dock 宽/高，不引入第二套 scroll offset、selection identity、timer、Task 或 presentation state。
- 不把 summary chip 做成新的生产/升级按钮；所有真实 action 继续调用既有 controller action。
- 不复制 Rusted Warfare 的截图、sprite、像素、布局文件、商标素材或原作图标；使用当前 `TacticalHUDTheme`、现有 SF Symbols 和原创 SwiftUI 排版。
- 不引入第三方依赖、WKWebView、网络运行时依赖、UIKit 替代 SwiftUI 的新控制层或构建工具。

## 当前 Production / queue / Factory Tech 状态流

### 选择与 section 顺序

1. `GameEngine` 的 `GameState.selectedEntityIDs` / `selectedEntityID` 是选择事实来源。
2. `GameController.selectedPlayerProducer` 从当前存活、完成状态、己方 producer 派生；`productionOptions` 调用 `GameDefinitions.productionUnits(for:)`，必须继续使用同一 tech gate 和稳定顺序。
3. `TacticalCommandDockView` 根据当前 selection identity 让 Production 或 Build & Upgrade 置顶；不要在焦点条中复制一套 section visibility 判断。
4. `TacticalCommandDockHeaderView` 是固定 header；`TacticalProductionSectionView` 和 `TacticalBuildSectionView` 位于外层连续滚动内容中。焦点条应放在固定 header 的 Selection Summary 之后、会被滚动隐藏的 section 之前。

### Production queue

1. `GameController.productionQueueItems` 只读映射当前选中己方 producer 的 `BuildingSnapshot.productionQueue`。
2. 每个 `ProductionQueueItem` 的 `unitType`、捕获的 `buildTime`、`progress` / `progressFraction`、稳定 `id` 是显示事实；当前项的剩余时间必须由真实 progress/buildTime 派生，不得使用模拟帧估算或另存倒计时。
3. 生产按钮调用既有 queue action；`GameEngine.queueUnit` 负责完成度、tech、metal、population 和 queue 校验并扣资源。
4. `GameEngine.update` 推进队首，完成后按 rally 生成单位；`cancelLastProduction` 继续取消队尾并按未完成进度退款；`setRepeatProduction` 和 `setRally` 继续保持现有语义。
5. 焦点条只显示队列摘要，不能改变队列顺序、队列 id、Cancel Last 的队尾定义或快捷键映射。

### Factory Tech / building upgrade

1. `selectedCompletedPlayerFactory`、`selectedFactoryTechLevel`、`selectedFactoryUpgradeProgress`、`selectedFactoryProductionSpeedText` 和 `factoryUpgradeBenefitText` 是 Factory Tech 的现有派生入口。
2. `GameDefinitions.nextUpgrade(for:)` 提供下一等级费用/时间/收益；`queueBuildingUpgrade`、`cancelBuildingUpgrade` 和 `GameEngine.update` 负责升级进度、完成效果和剩余进度退款。
3. 已入队项目保留入队时的 buildTime；升级完成只影响未来新入队项目的 effective buildTime。焦点条不得暗示现有队列被回写加速。
4. Extractor / Radar 的 `upgradeLevel`、`upgradeProgress`、next upgrade、费用不足 disabled 和 Cancel Upgrade 继续由既有 Build & Upgrade action/条件控制。

## 固定焦点条布局要求

### 普通 regular trailing dock

- 固定 header 顺序：既有 Selection Summary -> `Production Focus Bar` -> 既有 command status / Replace-Add 等 header 内容；等待目标时 TARGET MODE 的 attention 层级不得被焦点条压低。
- 第一行：建筑 SF Symbol、建筑名称、不可拆分的 `T1`/`T2` badge、真实生产倍率；不要把 `Factory T2` 自动连字符断开。
- 第二行使用三个清晰语义区：`NOW` 当前单位 + 百分比/剩余秒、`QUEUE` 总数 + 最多三个后续类型、`UPGRADE` Ready / Upgrading 百分比 / Max / Metal不足 disabled。若宽度不足，按区块垂直 fallback，不缩小到低于可读字号。
- `BUILD` 可生产列表必须在焦点条中有紧凑摘要；完整生产按钮仍在 Production section 中按现有顺序呈现。列表太长时可用稳定的 `+N` 结尾，但 VoiceOver value 必须朗读完整列表。

### compact trailing / compact bottom

- 不使用三列密集矩阵，不新增横向滚动；采用单列或两行垂直堆叠：建筑/tech、Now/Queue、Build/Upgrade。
- 消费 `TacticalHUDLayoutMetrics` 当前 role 和可用宽度，不硬编码覆盖 v2.37/v1.92 的 dock clamp、Tactical Map 尺寸和 safe-area 规则。
- 焦点条的内容可以自然增高，但不得遮挡固定 header 的取消/等待状态，也不得把 Production section 的第一排按钮推到不可见且无法滚动的位置。

### accessibility Dynamic Type

- 使用现有 accessibility role/metrics；切换到辅助功能字号时改为单列完整标签，允许焦点条自然增高，不使用固定高度裁切、`minimumScaleFactor` 掩盖信息或强制省略号。
- `BUILD`、`NOW`、`QUEUE`、`UPGRADE` 使用完整文字；单位名、等级、费用、时间、百分比和队列位置不能只靠颜色或图标表达。
- 焦点条默认是一个可合并的只读 accessibility element，提供完整 label/value/hint，避免 VoiceOver 逐个朗读同一数据两次；实际生产/升级按钮仍按既有顺序单独朗读。

## 必须保持的交互合同

- 选中 Command Center / Land Factory 后，`dockSelectionIdentity` 变化触发 dock 无动画回顶；使用现有 `ScrollViewReader`/transaction 机制，不保存第二套 offset，不使用弹性滚动动画。
- 生产按钮、Cancel Last、Repeat、Rally、Upgrade Factory、Cancel Upgrade 的 action、disabled 条件、成功/失败反馈和 commandStatus 保持不变。
- 所有可操作按钮继续满足至少 `44pt` 屏幕触控目标；焦点条只读 chip 不得伪装成小于 44pt 的 action target。
- `Shift+1...9` 继续按当前 `productionOptions` 顺序生产，`Shift+C/P/R` 继续映射 Cancel Last / Repeat / Rally；焦点条不得改变 keyboard shortcut inventory。
- Replace/Add、选择循环、建筑 primary selection、Battlefield 命令、Tactical Map、Save/Load 和生产建筑 rally 线保持不变。
- 非 producer selection 不得显示旧的 producer 焦点；Builder 建造、Extractor/Radar 升级和普通单位 selection 必须显示正确上下文或完全隐藏焦点条，不留 stale snapshot。

## 验收标准

### 行为与代码

1. 点选完成状态己方 Land Factory / Command Center 后，Production context 立即进入固定 header；旧滚动位置不遮住 Production 首部，回顶无动画。
2. `ios-home` production fixture 使用现有暂停、T2 Land Factory、混合队列和 Radar context 时，焦点条能读出 Factory T2/倍率、完整可生产列表摘要、当前 Heavy Tank 真实百分比/剩余时间、队列数量/后续类型和 Factory Tech 状态。
3. T1/T2、资源不足、升级中、升级完成、队列为空、Repeat 开启/关闭、Command Center 无 Factory Tech 等分支不会显示错误或 stale 信息。
4. Production buttons、queue progress、Cancel Last、Repeat、Rally、Factory Upgrade/Cancel 的现有 action 和 Core state 流未被改写；未来新入队 buildTime 规则保持可解释。
5. regular trailing、short-height compact trailing、compact bottom、portrait 和至少一个 accessibility Dynamic Type 容器中无裁切、重叠、自动连字符破坏或不可滚动的焦点条。
6. 44pt 触控、VoiceOver label/value/hint、Shift shortcut、Replace/Add、等待目标 attention、Tactical Map 和 battlefield hint inventory 经代码审查保持。

### 非功能与视觉

- 使用现有深色 tactical chrome、高对比 text/status tokens 和 SF Symbols；颜色之外用 NOW/QUEUE/UPGRADE/BUILD 文字和结构表达信息。
- 固定焦点条不得复制整组生产按钮而造成 dock 高度爆炸；普通字号优先两行，compact/accessibility 才自然增高。
- 不添加截图、视频、sprite、纹理或版权素材到仓库；公开 Rusted Warfare 页面只作为信息层级与移动端操作原则参考。

## 风险

- 固定 header 增高会压缩战场和 dock 可滚动区域；通过 regular 两行、compact 垂直 fallback、accessibility 自然增高和不显示非 producer stale summary 控制风险。
- 多单位名称、T2/Heavy Tank 和 Dynamic Type 可能造成换行/截断；不得用缩小字体隐藏问题，必须让 compact/accessibility 使用完整标签并保留滚动可达性。
- 焦点条与现有 Production section 同时读取状态，若错误建立第二套派生缓存会出现 progress/queue stale；应只从当前 `GameController` / Core snapshot 计算。
- 云端 workflow 没有 XCUITest 或滚动脚本，最新 artifact 不能证明真实手指遮挡、滚动惯性、VoiceOver 顺序或设备触控舒适度；Agent C 必须明确列为未覆盖风险。
- Rusted Warfare 公开页面只提供交互和信息层级参考；不得复制原作 screenshot、像素素材、字体、图标组合或品牌视觉。
