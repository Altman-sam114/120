# v1.67 / iOS native repair formation approach

## 角色

你是 Agent B，负责在 `main` 上实现本轮 v1.67。开始前必须阅读 `README.md`、`AGENTS.md`、`update_log.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和本提示词，并先执行 `git fetch origin`、`git switch main`、`git pull --ff-only origin main`、`git status --short --branch`。

## 目标

把 v1.66 的“多单位围绕目标分散站位”思想扩展到原生 Swift core 的多 Builder Repair 执行阶段：多个 Builder 维修同一受损友方单位或建筑时，应分散靠近目标周边，而不是全部朝目标中心叠在一起。

- 保持 `UnitOrder.repair(targetID:)` 存档形状和 `GameEngine.issueRepair(targetID:)` 对外 API 不变。
- 单 Builder Repair 保持原行为：距离超过维修范围时朝目标中心靠近，进入范围后维修。
- 多 Builder Repair 同一目标时，在 `updateRepairOrder` 中动态计算每个 Builder 围绕目标的稳定接近点；Builder 进入维修范围后仍按原速率维修同一目标。
- 接近点应按 Builder 当前选择/状态中的稳定顺序生成，围绕目标中心分散，并 clamp 到地图内。
- iOS 现有 Repair 按钮、主战场 tap、长按受损友方目标、战术小地图实体目标和外接键盘入口都应自然复用，不新增 UI。

## 非目标

- 不修改 Web `app.js`。
- 不修改 `UnitOrder.repair` 的 Codable 形状，不新增存档字段或命令类型。
- 不改变 Repair 合法性、维修速率、维修资源消耗、满血/目标消失清理、多 Builder 是否可同时维修同一目标等既有语义。
- 不实现 Reclaim/Build 队形、完整寻路、碰撞避让、动态阵型朝向、Shift 队列、自动维修 AI 改造、Repair Tank/Repair Bay 或 UI 自动化。
- 不用 `WKWebView` 或网页包装。

## 实现建议

- `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`
  - 保留 `issueRepair(targetID:)` 和 `UnitOrder.repair(targetID:)` 不变。
  - 增加 private helper，例如 `repairApproachPoint(for:target:)` 或 `supportFormationPoint(for:target:range:)`。
  - helper 在更新时查找所有当前正在 `.repair(targetID:)` 且可维修同一目标的存活 Builder，按位置和 id 稳定排序；只有 1 个 Builder 时返回目标中心以保持旧行为。
  - 多个 Builder 时，复用或仿照 `formationTargets(for:around:)` 的排序/间距，生成目标周边分散点；点位应至少位于目标半径外，并在 `builderRepairRange` 内，使 Builder 到位后可以执行维修。
  - `updateRepairOrder` 距离判断仍以 Builder 到目标中心是否超过 `builderRepairRange` 为准；超过时向该 Builder 的分散接近点移动，进入范围后执行原维修逻辑。
  - 目标为友方单位和友方建筑都要支持。
- `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift`
  - 增加或调整测试覆盖：
    - 多 Builder Repair 同一受损建筑时，更新后多个 Builder 的移动方向/位置不再完全相同，且都更接近各自分散接近点或目标维修范围。
    - 多 Builder Repair 同一受损单位时也能分散靠近。
    - 单 Builder Repair 仍朝目标中心靠近，保持旧测试兼容。
    - Repair 满血清理、目标消失清理、Stop 清除、非法目标拒绝等旧语义保持不变。

## 验收标准

- 选择多个己方 Builder 维修同一受损友方目标时，远距 Builder 不再全部朝同一个目标中心点移动。
- 单 Builder Repair、无选择、非 Builder、敌方目标、满血目标、自我维修等旧结果保持不变。
- 不改变 `GameState` JSON / `UnitOrder` Codable 兼容性。
- iOS 现有 Repair 入口无需新增按钮即可复用新 core 行为。
