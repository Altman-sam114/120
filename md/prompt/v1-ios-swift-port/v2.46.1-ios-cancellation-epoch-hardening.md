# v2.46.1 iOS cancellation epoch hardening

## 版本分配依据

- `v2.46.1` 是 v2.46 touch intent owner 的修复轮，只收敛 context/Spatial 取消 epoch 的迟到回调边界，不扩展玩法或渲染范围。
- 上一轮 Agent C 已确认 v2.46 的编译、Core tests、双架构启动和 Home/Combat PNG 通过，但静态复核指出三处低概率手势竞态：`CGPoint` 精确比较、context/area end 乱序，以及 reset 时尚未登记 Spatial ID 的旧首帧。

## 总目标 X 与当前轮次

- 总目标 X：持续把原生 iOS RTS 的触控、战斗呈现和操作手感向 Rusted Warfare 风格收敛，同时保持 Web 原型和 Swift Core 合同稳定。
- 当前轮次：修复 v2.46 owner 的取消序列，不新增命令、不改变模型或战斗数值。
- 上一轮 Agent C 结论：v2.46 云端 artifact 通过，遗留风险集中在 SwiftUI 手势回调时序，需追加修复轮并重新走最新 commit 的云端 artifact 复判。

## 背景

`BattlefieldView` 同时挂载 `SpatialEventGesture`、context `DragGesture`、pan/Select Area `DragGesture`、`SpatialTapGesture`、`onLongPressGesture` 和 `MagnifyGesture`。v2.46 已用 `BattlefieldTouchIntent` owner、touch ID 集合和 `battlefieldTouchSequence` 取消 epoch 收敛行为，但 SwiftUI 仍可能以微小的 `startLocation` 差异或乱序回调结束旧 gesture。取消 end 如果把 owner 写回 `.possible`，迟到 drag/tap 会重新获得控制；reset 尚未记录 touch ID 时也必须防止旧 Spatial 首帧被当成 fresh。

## 目标

1. context `startLocation` 比较允许 1pt 浮点误差，使用显式 `Double` 距离计算。
2. context end 结束单指序列时，只有 `accepted && !wasCancelled` 才释放为 `.possible`；迟到/取消路径保留 `.cancelled`，不得重新放行旧 pan 或 touch ID。`DragGesture.onChanged` 只有当前 pan 已活动或本序列尚未发生 pan 才能 acquire，阻止 context end 后的迟到 drag callback。
3. Select Area 仍有 `.areaSelection` owner 和活动起点时，context end 不终结 area sequence；由 drag end 独占提交一次合法区域选择。
4. 地图 reset 没有登记 Spatial touch ID 时，unknown active touch 在 context seed 前必须拒绝；seed 后才接受并清除 cancellation epoch。已有取消 ID 时只接受不在集合中的 fresh ID。
5. 继续保持 v2.46 的单一 owner、12pt pan 阈值、pinch owner、第三指/取消/触点替换拒绝、pending target 门控和 Core/JSON/存档语义。

## 非目标与边界

- 只修改 `BattlefieldView.swift` 和本轮必要的 README/flow/flowchart/test/update log/prompt 文档。
- 不修改 `RustwarCore`、`GameController`、`BattlefieldScene`、HUD action、单位/建筑模型、战斗数值、命令优先级、生产、存档或 JSON 字段。
- 不引入 UIKit、第三方依赖、计时器、随机数、网络服务或新的触点数据源。
- 不在本机运行测试、build、Simulator、Preview、浏览器验证、格式检查或 `git diff --check`；本轮唯一验收来源是 GitHub Actions artifact。

## 实现步骤

1. 在 context end 保存 `accepted`、`wasCancelled` 和 `areaSelectionInFlight`；先清理 context 生命周期，再按 owner/时间结果决定保持 `.cancelled` 或释放 `.possible`。
2. 将起点距离的 `CGFloat` 分量显式转换为 `Double`，比较 1pt 容差。
3. 在 `updateMultitouchSelection` 中先捕获 `hadCancelledTouchIDs`，unknown-ID 分支只有 `battlefieldTouchCancellationContextSeeded` 且存在 active touch 时才构造 fresh 集合；调用 `acceptFreshBattlefieldTouchSequence()` 前完成所有判断。
4. 保持正常 Spatial finish、双指选择、pinch、area drag end、地图 reset 和 tap suppression 的既有状态流，不重写 classifier 或 controller。
5. 静态复查迟到 context/drag end、第二指抢占、地图 reset、pending target、Replace/Add 与普通新触摸的 owner 释放路径。
