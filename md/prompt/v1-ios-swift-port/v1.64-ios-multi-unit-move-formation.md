# v1.64 / iOS native multi-unit move formation

## 角色

你是 Agent B，负责在 `main` 上实现本轮 v1.64。开始前必须阅读 `README.md`、`AGENTS.md`、`update_log.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和本提示词，并先执行 `git fetch origin`、`git switch main`、`git pull --ff-only origin main`、`git status --short --branch`。

## 目标

为原生 iOS / Swift core 的多单位 Move 命令增加轻量队形落点，避免多选单位收到同一个目标点后重叠。

- 单选 Move 保持原行为：目标点只做地图边界 clamp。
- 多选 Move 根据选中己方可移动单位生成稳定的方阵落点。
- 方阵落点应参考 Web `app.js` 的轻量队形思想：按单位半径决定间距，按当前位置排序，围绕玩家点选的目标点展开。
- 所有落点必须 clamp 到地图边界。
- iOS 现有 Move 按钮、长按空地 Move、战术小地图 Move 都应通过 `GameEngine.issueMove(to:)` 自动复用，不需要新增 UI。

## 非目标

- 不修改 Web `app.js`。
- 不实现完整寻路、碰撞避让、队列命令、Shift 追加队列、阵型朝向、Attack-Move / Patrol 队形落点或运输语义。
- 不新增 Swift core 存档字段、命令类型、iOS target、第三方依赖或构建链。
- 不改变 Attack、Attack-Move、Patrol、Guard、Repair、Reclaim、Build、Stop、生产、AI、选择、控制编队或小地图交互语义。
- 不用 `WKWebView` 或网页包装。

## 实现建议

- `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`
  - 保留 `issueMove(to:)` 的对外 API。
  - 在 `issueMove(to:)` 内对 `selectedPlayerUnitIndices()` 结果分支：
    - 0 个：沿用 `.selectedEntityCannotMove`。
    - 1 个：沿用单点目标。
    - 多个：调用新的 private helper 生成 `(unitIndex, WorldPoint)`。
  - helper 可按当前单位 `position.y`、`position.x`、`id` 排序，保证确定性。
  - 间距可使用选中单位最大 `GameDefinitions.unit(type).radius * 2 + 18`，并 clamp 到约 `42...96`。
  - 列数使用 `ceil(sqrt(count))`，行列偏移围绕中心展开。
  - 每个落点都调用现有 `clampedToMap()`。
  - helper 保持 private，不暴露新 API。
- `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift`
  - 更新既有 `moveCommandAppliesToSelectedPlayerCombatGroup`，不再断言所有单位目标完全相同。
  - 新增或调整测试覆盖：
    - 多选 Move 会给每个选中己方单位分配唯一或至少分散的目标点。
    - 方阵中心仍围绕玩家指定目的地。
    - 单选 Move 仍使用精确目的地。
    - 边界附近多选 Move 的各落点被 clamp 到地图内。
- iOS 文件预计不需要修改；若为了状态文案微调必须修改，范围要保持极小。

## 验收标准

- 选择多个己方作战单位后执行 Move，不再所有单位共享同一 `WorldPoint`。
- 多选 Move 的平均落点接近玩家指定目的地，落点按稳定方阵分布。
- 单选 Move、无选择、只选建筑/敌军等旧结果保持不变。
- iOS 现有 Move 入口无需新增按钮即可复用新 core 行为。
