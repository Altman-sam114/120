## 问题与移动端参考

公开 Rusted Warfare 移动端截图和评测呈现的 HUD 重点不是大型面板，而是：资源与对局状态紧贴安全区边缘、战术命令贴近拇指区、上下文内容按当前选择出现、战场中心尽量保持无遮挡、小地图始终可见。

当前 `RootGameView` 把完整 `GameHUDView` 作为顶部全宽 overlay；`GameHUDView` 随历史功能增长已经包含大量纵向 `HStack` / `LazyVGrid`。在 iPhone、横屏短高度和较大 Dynamic Type 下容易产生以下问题：

- HUD 高度可能占据大部分战场，遮住单位与触摸区域。
- 资源、对局管理、选择工具、命令、生产和编队混在一条长纵向流中，移动端扫描成本高。
- 当前小地图固定在右下角，未来右侧/底部命令 dock 容易与它重叠。
- 顶部大量横向按钮在窄屏和大字体下可能溢出或被裁切。

本轮只借鉴“紧凑贴边、上下文优先、战场中心留白”的信息架构，不复制原作图标、logo、纹理、文案或其它受版权保护素材。

## 本轮目标

把现有单块 HUD 重排为原生 iOS 的紧凑战术布局，同时保持全部功能和操作语义：

1. 资源、雷达、Pause/Play 和速度收敛为尊重 safe area 的顶部状态栏。
2. 选中信息、上下文命令、建造/升级、生产、选择工具、控制编队和对局管理进入贴边可滚动 command dock。
3. 宽屏和可用横屏使用右侧 dock；窄屏竖屏使用底部 dock；布局按真实容器尺寸响应，不读取全局屏幕 bounds。
4. 小地图在所有布局中稳定可见、维持正确宽高比，不与顶栏或 command dock 相交。
5. 所有现有按钮、Picker、action、disabled 条件、等待命令取消语义、键盘快捷键、VoiceOver 信息和 44pt 触控面积完整保留。
6. 小屏、横屏、Split View 类窄宽、普通/辅助功能 Dynamic Type 都不出现文本/控件溢出或无法滚动到的命令。
7. 不增加大幅布局动画；Reduce Motion 开启时体验不退化。

- 不用 tabs、分页、`DisclosureGroup` 或默认折叠区把部分命令从视图层级移除；所有命令必须能在同一个连续 dock 中滚动到。

## 架构与数据流边界

- `GameController` 仍是 HUD 状态和所有 action 的唯一入口；新布局只读取现有派生属性并调用现有方法。
- `GameHUDView` 不保存玩法状态，不复制金属、选择、生产队列、等待命令或控制编队状态。
- 响应式 layout role 可以是 `RootGameView` / `GameHUDView` 的轻量 view-only enum 或参数，不写入 UserDefaults，也不进入存档。
- 使用 `GeometryReader` 的 `proxy.size` / `safeAreaInsets`、`ViewThatFits`、`safeAreaInset` 或等价容器 API；禁止使用 `UIScreen.main.bounds`、设备型号字符串或方向通知推测布局。
- Battlefield 仍是底层主要内容。只有顶栏、dock 和小地图自身 bounds 可以拦截触摸；透明的整屏 HUD 容器不得吞掉战场 tap、drag、long press 或 pinch。
- `RootGameView` 现有 `.focusable()`、`@FocusState`、`.onKeyPress(phases: .all)` 和 WASD / 方向键相机逻辑必须保持。

## 明确布局断点

以 `GeometryReader` 提供的可用容器宽高为准，至少实现以下三档。允许对数值做很小调整，但不得取消三档行为，调整时在 `update_log.md` 写清实际值。

### A. Regular trailing dock

触发：容器宽度 `>= 700pt`，不论 iPad 横竖屏。

- 顶部状态栏在 safe area 内横向排列，目标可见高度约 `52-64pt`，不得因普通 Dynamic Type 变成多百点高。
- command dock 贴 trailing edge，宽度按容器约 `28%` 计算并 clamp 在 `268...320pt`。
- dock 从顶栏下缘延伸到下方 safe area，上方固定选中/命令状态头，下面独立纵向滚动。
- Tactical Map 放在剩余战场区域的 bottom-leading，标准大小约 `176 x 118pt`，保持现有宽高比。

### B. Compact landscape trailing dock

触发：容器宽度 `< 700pt`、宽度大于高度，并且宽度 `>= 560pt`。

- 顶部状态栏使用紧凑单行或两条短行，Pause 和 Speed 始终在无需水平滚动的位置。
- command dock 仍贴 trailing edge，宽度按容器约 `34%` 计算并 clamp 在 `232...276pt`。
- dock 内使用较少列数并纵向滚动；不得因横屏高度短而截断底部命令。
- Tactical Map 放在剩余战场区域的 bottom-leading，约 `144 x 96pt`；若可用战场高度不足，可以缩至约 `120 x 80pt`，但不可隐藏。

### C. Compact bottom dock

触发：其余尺寸，主要是 iPhone 竖屏、窄 Split View 和宽度 `< 560pt` 的容器。

- 顶部状态栏可以使用两条紧凑行：资源/情报行可水平滚动，Pause 和 Speed 所在控制行固定可见。禁止让 Pause 或整个 Speed 控件滚出屏幕。
- command dock 贴 bottom safe area，目标高度按容器约 `34%` 计算并 clamp 在 `216...320pt`；极小高度下优先保留至少 `180pt` 可操作 dock 和可见战场，不允许两者互相覆盖。
- dock 顶部固定选中/待选状态，下面纵向滚动命令内容；宽度允许更多自适应列。
- Tactical Map 位于顶栏下方、剩余战场区域的 top-trailing，标准约 `144 x 96pt`；在极窄/极矮容器可缩至约 `120 x 80pt`，不可与 bottom dock 相交。

### 断点共同要求

- 顶栏、dock 和 Tactical Map 必须依据同一 geometry 预留区域，不得用一组只适配当前设备的绝对 padding 假装避让。
- 运行时旋转或容器 resize 后应自然切换布局，Battlefield viewport 和 Tactical Map 视口矩形随现有 `updateBattlefieldViewportSize` 路径更新。
- 不按 viewport 宽度缩放字体；使用 Dynamic Type 文本样式和容器重排。
- runtime 固定尺寸只用于 44pt hit target、合理 dock clamp 和 Tactical Map 宽高比；不得给整屏写死 iPhone 型号尺寸。

## 顶部状态栏规格

顶部状态栏只保留高频、需要持续扫读的状态：

- Metal：现有整数格式和 monospaced digits。
- Income：现有一位小数格式和 monospaced digits。
- Pop：`used/cap`。
- Radar：站点/contact 摘要及现有 `radarIntelAccessibilitySummary`。
- Pause / Play：继续调用 `controller.togglePause`，保留 P 快捷键、动态标题、图标和 prominent 状态。
- Speed：继续绑定 `$controller.simulationSpeed` 和现有 options / labels。

实现要求：

- 顶栏是贴边 material band，不是一个覆盖战场的大卡片；圆角不超过现有 8pt，贴屏幕边缘一侧可不圆角。
- 数值和短标签必须保持完整；小屏时资源 metrics 可以水平滚动，但每个 metric 作为完整 accessibility element，有明确 label/value。
- Pause 和 Speed 不得因为 metrics 滚动而离屏。
- 宽屏可继续用 segmented Speed；窄屏可用 `ViewThatFits` 选择更紧凑但语义等价的 `Picker` 表现。无论形式如何，VoiceOver label 仍是 “Simulation speed”。
- 不把 Map、Restart、Save、Load、Enemy AI、Reset、Base 继续堆在顶栏；这些移入 dock 的 Session 区。
- 顶栏背景必须保证在 grass、water、lava 和 v1.88 高亮特效上可读，不用单一颜色区分暂停状态。

## Command dock 信息架构

### 固定 dock header

以下内容放在 dock 顶部、滚动区之外，保证玩家滚到深处时仍知道当前上下文：

- `Selected: ...`，保留最多两行，不能被固定成单行省略到失去对象信息。
- `selectedAttackStanceSummary`、`selectedRadarUpgradeSummary`、`selectedExtractorUpgradeSummary` 中当前存在的摘要；空间紧张时可按现有优先级显示为紧凑副标题，但不能永久丢弃。
- `commandStatus`；等待目标时继续有非纯颜色的醒目标识，例如图标/描边/文字组合，并保留现有语义。
- Selection mode 的 Replace / Add segmented picker；至少在 dock header 下方第一屏可见，不埋到 Session 区末尾。

header 允许自身内容在 accessibility Dynamic Type 下增长，但不得覆盖下面滚动区；dock 总体仍受断点尺寸约束。

### 连续滚动区与分组顺序

使用一个纵向 `ScrollView`，显示滚动指示或其它清晰滚动 affordance。不要用 tabs、分页或折叠区。按以下顺序组织无嵌套卡片的 section，并使用短 section label / `Divider` 建立层级：

1. `Commands`：Select Area、Same Type、Move、Attack Move、Patrol、Guard、Aggressive、Defensive、Hold Fire、Attack、Repair、Reclaim、Stop。
2. `Build & Upgrade`：Build Extractor、Turret、Factory、Radar、Upgrade Radar、Upgrade Extractor、对应 Cancel Upgrade。
3. `Production`：当前 `productionOptions`、production summary、Cancel Production、Repeat、Rally。
4. `Selection`：Idle Builders、Combat Units、Screen Combat。
5. `Groups`：1-9 每个 slot 的 Save 和 Recall。
6. `Session`：Base、Reset、Map、Restart、Save、Load、Enemy AI。

只隐藏当前代码本来就按 `can...` / `isAwaiting...` 条件隐藏的上下文控件；不得额外按新 UI section 隐藏命令。

### 命令按钮和网格

- 每个可点控件的有效触摸区域至少 `44 x 44pt`，包括 icon-only 编队 Save/Recall 和 Picker。
- 普通 Dynamic Type 下右侧 dock 优先 2 列，特别窄的 compact landscape 或 accessibility Dynamic Type 回退 1 列；底部 dock 可依据实际宽度使用 2-3 列。
- 长标题允许两行并保持字间距 0；不得用过小固定字号、横向压扁或低于可读性的 `minimumScaleFactor` 把内容塞入。
- 使用现有 SF Symbols 和 `Label`；视觉 icon-only 的编队按钮仍必须由带文本的 Button label + `.labelStyle(.iconOnly)` 提供 VoiceOver 名称。
- active attack stance、waiting command、Repeat/AI 状态必须同时使用图标、文字或描边差异，不能只改变颜色；读取 `accessibilityDifferentiateWithoutColor` 时仍清楚。
- 不要在 dock section 外再包一层张张卡片；dock 是单一工具面板，各 section 使用间距和 Divider。

## 必须逐项保留的控件和语义

重排前后逐项核对，任何一项缺失都视为验收不通过：

- 状态/对局：Metal、Income、Pop、Radar、Pause/Play、Speed、Map、Restart、Save、Load、Enemy AI、Reset、Base。
- 选择：Idle Builders、Combat Units、Screen Combat、Replace/Add、Select Area、Same Type。
- 控制编队：1-9 每个 slot 的 Save 与 Recall；Control+1-9 保存、1-9 召回不变。
- 战术命令：Move、Attack、Attack Move、Patrol、Guard、Repair、Reclaim、Stop。
- 攻击姿态：Aggressive、Defensive、Hold Fire，当前 active value 和 Z/X/V 快捷键不变。
- 建造：Build Extractor、Turret、Factory、Radar，以及 Shift+E/T/F/D。
- 升级：Upgrade Radar、Upgrade Extractor、两类 Cancel Upgrade 和原有 accessibility hint。
- 生产：全部动态 `productionOptions`、Shift+1-9、queue summary、Cancel Production、Repeat、Rally 和 Shift+C/P/R。
- 信息：Selected summary、攻击姿态摘要、Radar/Extractor 升级摘要、commandStatus、productionSummary。

所有现有 action 方法、`keyboardShortcut`、`disabled` 条件、dynamic title/systemImage、accessibility label/value/hint 应直接迁移，不要重新实现规则。

## 滚动与键盘快捷键硬规则

- dock 的 ScrollView 只滚内容，不滚固定 header；顶栏和 Tactical Map 不跟随 dock 滚动。
- 条件变化后新增命令必须在滚动内容中可达；没有选择时不允许残留大片空 section。
- 不要因为使用 lazy container 导致离屏按钮从视图层级移除后键盘快捷键失效。快捷键按钮数量有限，优先使用能保持 action view 存活的 `VStack` / `Grid` / 等价布局；若保留 `LazyVGrid`，必须实际验证滚到别处时 P/R/E/F/A/G/H/C/S/Z/X/V、Shift 组合和 1-9 仍工作。
- 不把快捷键集中复制到另一套新 switch，也不绕过现有 Button action；避免 UI 与键盘形成两套规则。
- 旋转/resize 不得清空选择、等待命令或 control groups，也不应强制把 ScrollView 动画滚动到随机位置。

## Tactical Map 层级和避让

- `TacticalMapView` 始终是独立于 command dock 的战术控件，frame 由 Root 根据断点提供，并保持约 `176:118` 宽高比。
- 右侧 dock 布局中，小地图放在剩余战场 bottom-leading；底部 dock 布局中，小地图放在剩余战场 top-trailing。
- 通过安全区/布局容器真实预留空间，使小地图 frame 与 dock frame 的交集为空；禁止仅凭 z-index 让一个覆盖另一个。
- 小地图不得被顶栏、Dynamic Island、home indicator 或 dock 遮住；也不得把等待命令角标裁切到 frame 外。
- 保持当前 `.accessibilityLabel("Tactical map")`、value、hint、`.isButton` trait，以及点按/拖动/长按手势。
- 若修改 `TacticalMapView.swift`，只允许调整 material、边框、clip 或 pending label 的自适应表现；`worldPoint`、`mapGesture`、`handleTap`、`handleContextPress`、Canvas 数据与绘制规则不得变化。

## 安全区、层级和触摸

- 顶栏、右侧 dock、底部 dock 必须尊重容器 safe area；Battlefield 背景可以延伸到屏幕边缘，但交互控件不能落到 notch、Dynamic Island 或 home indicator 下。
- 推荐用 `.safeAreaInset(edge:)` 或等价分区让 BattlefieldView 获得真实剩余 viewport，而不是把所有面板浮在全屏 ZStack 上。
- 若 viewport 因 dock 改变，`BattlefieldView` 继续通过现有 geometry 更新 controller；Screen Combat 和 Tactical Map viewport frame 应自然反映玩家真实看到的区域。
- 顶栏层级最高，其次 command dock / Tactical Map，再下方 Battlefield；Tactical Map 和 dock 同级但 frame 不相交。
- 透明区域不能设置整屏 `contentShape`。只让真实控件区域接收触摸，战场剩余区域继续响应 tap、double-tap、long press、drag、pinch 和 area selection。

## Accessibility 与 Reduce Motion

- 继续使用 Dynamic Type 语义字体；不要按 viewport 宽度计算字号，不使用 `.caption2` 承载关键状态。
- accessibility Dynamic Type 下，顶栏允许变成两行、dock grid 允许回退一列，所有文字可以增长并通过滚动访问；不得裁切最长命令名或 production summary。
- VoiceOver 顺序应先读顶栏状态/控制，再读 Battlefield 与 Tactical Map，最后读 dock header 和连续命令 section；同一 metric 不要把 label/value 拆成无意义的多个焦点。
- 保留所有 icon-only 按钮的可读文本 label、现有 accessibility value/hint，以及 Radar、Enemy AI、Repeat、Selection mode、control group 的动态可访问值。
- 等待命令和 active stance 不只靠颜色；支持 Differentiate Without Color。
- 本轮不需要新增布局动画。若为 orientation/dock placement 添加过渡，Reduce Motion 开启时只允许无动画或短 opacity transition，不做 dock 滑入、弹性缩放或大范围位移。
- Voice Control 可继续用稳定的按钮名称触发；动态标题按钮可按需补稳定 `accessibilityInputLabels`，但不得改变可见含义。

## SwiftUI 代码质量与性能

- 不在 `GameHUDView.body` 继续堆成更长的 800 行条件树。按 status bar、dock header、命令/建造/生产/选择/编队/Session section 划清结构。
- 由于本轮文件范围明确，优先用同文件内小而专一的 private helper / nested view 组织同一 HUD concern；不要因此新增大量文件或新的 view model。若 helper 开始承载业务规则，应立即回退并复用 controller。
- Button 能直接传 action 方法时继续使用 `Button(..., action:)`；不要把布局逻辑混入 action closure。
- 避免 `AnyView`、`UIScreen.main.bounds`、手写方向通知、UIKit size class hack、escaping view-builder closure 和 GCD。
- 不在 body 内反复做昂贵排序/过滤。生产 options 的枚举若重排，可使用稳定 indices 或现有小集合，但不得改变原顺序和 Shift+1-9 映射。
