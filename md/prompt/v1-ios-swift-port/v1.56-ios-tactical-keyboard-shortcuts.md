# v1.56 / iOS native tactical keyboard shortcuts

## 目标

把 Web 版常用战术热键中已经有原生 iOS HUD 按钮和 `GameController` action 的部分迁移到外接键盘路径。v1.56 只声明 SwiftUI keyboard shortcuts，复用现有按钮 action、disabled 条件和等待态切换，不改变 `RustwarCore` 数据或命令语义。

## 热键范围

- `P`：Pause / Play。
- `R`：Restart 当前原生地图。
- `E`：选择空闲己方 Builder。
- `Control + A`：选择全部己方战斗单位，对齐 Web 的选择全部作战单位。
- `Option + A`：Same Type，全图选择当前己方单位同类型单位，对齐 Web 的 `Alt + A`。
- `A`：Attack Move 等待落点。
- `G`：Patrol 等待端点。
- `H`：Guard 等待友方目标。
- `C`：Reclaim 等待残骸目标。
- `S`：Stop 当前选中己方单位命令，并取消正在等待的目标或框选模式。

## 非目标

- 不迁移 WASD / 方向键相机平移。
- 不迁移 `Space` 回到己方指挥中心，因为 iOS 当前只有 Reset camera，没有 focus-base 语义。
- 不迁移 `F` 当前屏幕作战单位选择，因为 iOS 当前 Combat Units 是全图批量选择。
- 不迁移 `Z` / `X` / `V` 攻击姿态，因为原生 core 尚无姿态模型。
- 不迁移生产、建造、工厂升级、运输、核弹、卸载或实验单位热键。
- 不修改 Web `app.js`。
- 不新增 UIKit key command、自定义焦点系统、第三方依赖、后端、构建链或网络依赖。

## 实现边界

- 只修改 `ios/RustwarIOS/RustwarIOS/GameHUDView.swift` 中已有按钮。
- 快捷键必须挂在现有 `Button` 上，不能复制 action 逻辑到新的 command layer。
- 条件显示按钮只在现有 `if controller.can... || controller.isAwaiting...` 分支渲染时暴露快捷键。
- 保留现有 `.disabled(...)`、accessibility label/value/hint、44pt 触摸目标和 HUD 布局。
- 可新增一个私有 `commandKey(_:) -> KeyEquivalent` helper，避免重复构造单字符快捷键。
