# v1.36 / iOS native enemy AI target scoring MVP

## 角色

本提示词交给 Agent B 执行。Agent B 必须遵守 `AGENTS.md` 的 main 直推、轻量本地检查、GitHub Actions artifact 和 Agent C 复判流程。

## 背景

v1.35 已让红方 Artillery 在 AI 新分配攻击订单时优先玩家建筑，但红方其它 T1 单位仍只按最近距离选目标。Web 原型的自动索敌会考虑关键建筑、生产建筑、防御建筑、残血目标和目标威胁。本轮做一个更小的 Swift 原生 AI 步进：只让红方 AI 新攻击订单使用 Web-lite 目标评分，不改变玩家手动攻击、Attack-Move、Patrol、Guard 或炮塔防御开火的既有索敌语义。

## 目标

- 红方 AI 在 `updateEnemyAttackOrders()` 给空闲战斗单位新分配 `.attack(targetID:)` 时，使用专用目标评分选择玩家目标。
- 评分至少体现：
  - Command Center 比普通目标更优先。
  - Extractor / Land Factory / Turret 等建筑优先级高于普通近距离单位，但 Artillery 仍保持 v1.35 的建筑优先方向。
  - 残血单位或建筑比满血目标更优先。
  - 仍保留距离因素，避免完全无视近距离威胁。
- 玩家手动 `issueAttack`、Attack-Move、Patrol、Guard 的临时索敌、炮塔自动防御开火、生产和建造逻辑不变。
- 同步 README、flow、flowchart、test 和 update_log。

## 非目标

- 不修改 Web `index.html` / `styles.css` / `app.js`。
- 不新增 SwiftUI / SpriteKit UI 或战术小地图交互。
- 不引入完整 Web `targetPriorityScore`，不支持空军/海军/实验/T2/支援单位评分。
- 不新增 AI 进攻波状态、冷却时钟、阵型、集火、难度倍率或生产权重。
- 不修改 `nearestCombatTarget(for:)` 的全局语义，避免影响玩家 Attack-Move / Patrol / Guard。
- 不改变 `UnitSnapshot` Codable 结构或 iOS 存档格式。

## 建议实现

- 修改 `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`：
  - 保持 `updateEnemyAttackOrders()` 继续调用 `enemyAttackTarget(for:)`。
  - 把 `enemyAttackTarget(for:)` 扩展为红方 AI 专用评分选择，例如扫描玩家单位和建筑后用 `enemyAttackTargetScore(attacker:target:distanceSquared:)` 选择最低分。
  - 可以保留 Artillery 对建筑的强偏好，但不应只返回最近建筑；在建筑之间也应考虑 Command / 低血 / 距离等评分。
  - 对 `CombatTarget` 如需知道建筑类型或 HP，可新增私有评分候选结构；不要把不必要字段暴露到 public API。
  - 不修改 `nearestCombatTarget(for:)`、`nearestGuardCombatTarget(for:)` 或 `nearestBuildingWeaponTarget(for:)`。

## 测试要求

在 `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift` 增加或更新 Swift tests，至少覆盖：

- 红方非 Artillery T1 单位在近处玩家 Scout 和较远 Command Center 同时存在时，AI 新攻击订单选择 Command Center。
- 红方非 Artillery T1 单位在近处满血玩家单位和稍远低血玩家单位同时存在、没有玩家建筑时，AI 新攻击订单选择低血单位。
- 红方 Artillery 在多个玩家建筑中选择评分更高的关键建筑或低血建筑，而不是无条件最近建筑。
- 保留 Artillery 无玩家建筑时能回退选择玩家单位。

如果更新 v1.35 的 `enemyAINonArtilleryKeepsNearestTargetPriority`，测试名和断言必须反映新语义，不要留下与实现相反的“keeps nearest”描述。
