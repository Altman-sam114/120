# v2.81 原生 iOS 单位队伍色装甲识别

## 轮次定位

- 版本：`v2.81`
- 基线：`origin/main` 的 `f8b4f218a6fb5aa84a4b150b231b48091a217ff5`（v2.80 文档验收记录）
- 目标：在已有 hull 尾缘阵营标记之外，为原生 iOS 单位主体增加低饱和队伍色装甲层级，让双方在密集战斗和斜向朝向下更快区分，同时保持 Rusted Warfare 风格的深色钢灰轮廓和模型可读性。

## 目标

1. 仅调整 `ios/RustwarIOS/RustwarIOS/BattlefieldScene.swift` 的单位模型 presentation。
2. `unitBody(for:radius:weaponRotation:recoilDistance:)` 在自身作用域内为 `armorMidColor` 使用按 `unit.team` 派生的 muted team-tinted mid armor color：
   - 保留原钢灰基色的暗度和层级；
   - Player 只向现有绿色 `teamColor(.player)` 轻微偏移；
   - Enemy 只向现有红色 `teamColor(.enemy)` 轻微偏移；
   - 两种颜色必须低饱和、不可替代高亮轮廓或现有强阵营标记。
3. 通过一个纯 presentation helper 或等价的局部派生值集中定义颜色，避免在八类单位分支中复制 RGB 常量；不要使用时间、随机数、纹理或状态写入。
4. 让现有 `armorMidColor` 引用继续覆盖所有单位主体/炮塔中使用的中间装甲面，使 Tank、Heavy Tank、AA Tank、Artillery、Builder、Scout、Hover、Gunboat 都具有一致的队伍识别；`armorDarkColor`、`armorLightColor`、`highlightColor`、履带、传感器、炮口和现有 cyan/mint 设备色保持既有层级。
5. 保持 v2.78 的 `addUnitFactionMarking`：Player 单 chevron、Enemy 双 rounded tabs、单一 compound `SKShapeNode`、hull-local、`zPosition = 1.1`，不新增第二套中心标记或环形队色覆盖。

## 非目标与边界

- 不修改 `RustwarCore`、`GameController`、命令、选择、攻击/伤害、生产、AI、存档/JSON、fog/visibility、HUD、Tactical Map、Web 原型或建筑模型。
- 不修改 `weaponMount` / `recoilMount` 的 heading、后坐距离、炮口、projectile、terminal、impact、damage、selection ring、HP bar、grounding 或节点上限。
- 不用整单位纯绿/纯红填充，不改变单位几何尺寸、碰撞、朝向、绘制顺序或每单位 marker 节点合同。
- 不以静态 PNG 宣称已证明真实触控、动态转向、动画时序、色觉体验、任意 zoom 或真机帧率。

## 实现建议

- 在 `unitBody` 入口创建一个只在该函数生效的 `let armorMidColor = ...`，让既有各 unit case 的 `fill: armorMidColor` 自动消费队伍色版本；不要改变 `buildingBody` 读取的同名属性。
- muted 色可以按原 `armorMidColor` 与 `teamColor(unit.team)` 的小比例固定混合，建议约 `0.16`，并以固定 RGB 输出，避免 SpriteKit alpha 叠加造成背景依赖。实际 RGB 必须由实现保持可读、可复现。
- helper 应只依赖 `Team`，输出不透明颜色；模型的 outline、highlight 和已有 faction marking 继续提供边界与高对比识别。
