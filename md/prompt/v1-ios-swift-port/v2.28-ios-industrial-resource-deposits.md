# v2.28 iOS industrial resource deposits

## 目标

精修原生 iOS 主战场资源点模型：替换最新云端 `ios-home.png` 中占地过大、材质扁平的青色圆盘，让空闲资源点既容易定位和点选，又不遮挡地形、单位、建筑或命令反馈。

## 参考

- 公开 Rusted Warfare 建筑/基础教学画面中资源与建筑保持紧凑、高对比的战场信息组织。
- 只参考俯视 RTS 的可读性和信息密度，不复制第三方图形、贴图或素材。

## 实现要求

- 只修改 `BattlefieldScene.drawResources` 的程序化 presentation。
- 每个节点继续只读既有 `ResourceNode.position`、`radius` 和 `claimedBy`。
- 未占领节点使用暗色工业 plate/inset、低透明外场、八段青色能量环、四向导轨、六边形中心和多片确定性金属矿脉。
- 已占领节点保留黄色归属语义并整体降低透明度，确保 Extractor 是前景主体。
- 节点继续位于 `resourceNode`，在 entity、effect、fog 和 radar 下方。
- 使用固定几何；不得新增随机数、timer、Task、SKAction、Core 状态或持久化字段。

## 非目标

- 不修改资源坐标、逻辑半径、命中、Build Extractor、经济、AI、小地图、单位/建筑模型、选择、命令、战斗或存档。
- 不修改 Web、Swift Core、Xcode 工程或 CI schema。

## 云端唯一验证

- 按人工要求禁止所有本地验证，不运行 `git diff --check`、Node/Swift check、Swift tests、Xcode、Simulator、Preview、截图或浏览器验证。
- 只在 `main` 提交本轮相关文件并 push 到 `origin/main`。
- GitHub Actions 必须通过 JUnit 8/0/1、至少 311 项 Core tests、arm64/x86_64 build、production/combat 双 launch、orientation 与像素探针。
- Agent C 下载最新 SHA 对应 artifact，核对 manifest、JUnit、主日志、failure summary、repo state、toolchain、Simulator 信息与双 PNG。
- `ios-home.png` 中至少两个未占领资源点必须能看清工业环、中心核心和金属矿脉，占地显著小于旧实心圆盘，且不遮挡 Factory、Rally、HUD 或地形。
- `ios-combat.png` 的单位/建筑模型、选择层级、弹道、爆点、HUD 和 Tactical Map 不得回退。
