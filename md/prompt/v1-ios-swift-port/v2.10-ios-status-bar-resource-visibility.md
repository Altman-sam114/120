## 目标

1. 修复 trailing 横屏状态栏，使 Metal、Income、Pop、Radar、Pause/Play 与 Speed 同屏可见；四项资源指标不得被 Pause/Play 或 Speed 挤出首屏。
2. 让 `TacticalProminentButtonStyle` 显式支持“是否横向扩展”的配置；默认值必须继续保持现有 dock prominent control 的整行铺满行为。
3. `TacticalStatusBarView` 在 `regularTrailing` / `compactTrailing` 横屏角色中使用非横向扩展的 Pause/Play prominent style，使按钮保持合理 intrinsic width 与至少 44pt 触控高度。
4. 保持 `compactBottom` 的双行状态栏合理：metrics strip 与 controls 仍分行，不能因横屏修复变成拥挤、过窄或失去原有可用宽度；可让 compact-bottom 调用继续使用扩展样式，或采用等效的容器自适应布局，但不得硬编码设备尺寸。
5. 保持 Speed 的三个明确选项 `0.5x`、`1x`、`2.0x` 及其 binding；横向空间允许时继续显示 segmented picker，空间不足时只能按现有 `ViewThatFits` 语义降级为 menu，不能删除速度控制。
6. 保持 Dynamic Type、VoiceOver、Voice Control input labels、Differentiate Without Color、键盘快捷键与 44x44pt 最小触控目标。
7. 只通过最新 `origin/main` 精确 commit 对应的 GitHub Actions `Rustwar CI Results` 和 artifact schema `v1.2` 验证；本轮禁止全部本地测试、构建、Simulator、Preview、截图或浏览器验证。

## 实现方案与文件边界

### `ios/RustwarIOS/RustwarIOS/TacticalHUDComponents.swift`

1. 为现有 `TacticalProminentButtonStyle` 增加一个清晰命名的横向扩展参数，例如 `expandsHorizontally: Bool = true`。
2. 默认必须为 `true`，从而保持 `tacticalProminentControl()` 和 command dock 现有整行按钮行为；现有 dock 调用点不应被迫逐个传参，也不得出现第二套 prominent style。
3. `makeBody` 中根据该参数决定 horizontal padding / `maxWidth` / 必要 min-width 语义，做法可与现有 `TacticalBorderedButtonStyle(expandsHorizontally:)` 对齐，但不要牺牲 `TacticalHUDTheme.controlMinimumHeight` 的 44pt 最小高度。
4. 非扩展模式必须按 label 的合理 intrinsic width 布局，同时保留 theme foreground/background/stroke、pressed/disabled 状态、Dynamic Type 和 VoiceOver；不能通过透明 frame 或视觉缩放伪装。
5. `tacticalProminentControl()` 默认行为保持不变。若为了 API 一致性允许传参，默认也必须是横向扩展，且不要顺带改写所有 dock section。

### `ios/RustwarIOS/RustwarIOS/TacticalStatusBarView.swift`

1. 横屏 trailing role 的 Pause/Play 按钮显式使用非横向扩展的 `TacticalProminentButtonStyle`；`compactBottom` 应保持合理双行占位，可依据 `layoutRole` 选择是否扩展，不能写死设备宽度。
2. 保持 Pause/Play 的 `Button(title, systemImage:, action:)`、`.keyboardShortcut(commandKey("p"), modifiers: [])`、`.accessibilityInputLabels(["Pause", "Play"])` 和至少 44pt 触控目标。
3. 保持 `metricsStrip` 中 Metal / Income / Pop / Radar 四个 `TacticalMetricView` 的 label、value、SF Symbol、格式、Radar spoken label/value 和水平 strip 语义。
4. 重新审视 `metricsStrip` / `statusControls` 的 `layoutPriority`：资源条不能因 controls 的优先级和扩展 proposal 再次获得 0 可见宽度。若仅取消 prominent 扩展已足够，不要增加多余机制；若仍需调整，使用容器级 layout priority / fixed-size / `ViewThatFits` 的语义化组合，并确保 controls 自身不会截断或重叠。
5. 保持 Speed 的 `ViewThatFits(in: .horizontal)` 策略：宽度足够时首选显示带 `0.5x / 1x / 2.0x` 三项的 segmented picker；较窄容器可回退 menu。不能为了四项 metric 可见而让 Play 与 Speed 重叠、跑出 safe area 或互相覆盖。
6. 不要把四个 metric 各自强行压缩为不可读宽度。默认固定 iPhone 17 Pro 横屏首屏必须同时清楚看到四个 label/value、Play 和完整 segmented Speed 三档；更窄或更大 Dynamic Type 环境允许 metrics strip 横向滚动或 Speed menu 回退，但初始可见区域不得退化为完全没有资源指标。
7. `compactBottom` 继续由 `VStack` 先显示 metrics strip、再显示 status controls；状态栏高度、战场与 bottom dock 的区域关系不能明显回归。

## 风险与控制

- **修复过窄**：只改一处 frame 但保留 controls 过高 priority，仍可能让 metrics 获得接近 0 的 proposal。必须以云端 fixed-device PNG 的内容验收，而不是仅以编译成功判断布局修复。
- **修复过宽**：改变 prominent style 默认值会让 command dock 按钮退化为 intrinsic width。默认必须保持扩展，只有状态栏横屏调用显式 opt out。
- **compact-bottom 回归**：全局关闭状态栏 Pause 扩展可能造成 portrait controls 失衡。使用 `layoutRole` 或等效容器语义保留双行布局，不得写死 portrait 设备尺寸。
- **Dynamic Type**：不可通过固定字号或压缩文字换取同屏。更大字号可触发既有滚动/menu fallback；保留 VoiceOver，单一默认 PNG 不能证明所有 accessibility size。
- **截图误判**：CI 像素 metrics 只证明非空，不能证明 label 内容。Agent C 必须打开 PNG 并逐项人工确认文字与控件。
- **共享工作区污染**：当前用户已有修改的 `project.pbxproj` 与未跟踪 `.wp`。Agent B 不得覆盖、回滚、暂存或提交它们；提交前必须逐文件核对 staged diff。
