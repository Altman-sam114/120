# v1.7 / iOS native tactical minimap

## Agent A brief

Version: `v1.7`

Goal: add a native iOS tactical minimap overlay so the SwiftUI/SpriteKit app can inspect battlefield state and center the main camera by tapping the map, without using Web content.

## Background

- Web Rustwar already has a minimap that is central to RTS navigation.
- The native iOS app now has map switching, restart, pause/speed, player move/attack/production, and red enemy AI.
- `RustwarCore` already exposes `GameConstants.mapWidth`, `GameConstants.mapHeight`, resources, units, buildings, teams, and camera snapshots.
- This round should move the native iOS experience closer to the Web RTS navigation loop while keeping scope small.

## Scope

Expected code touch points:

- `ios/RustwarIOS/RustwarIOS/CameraState.swift`
- `ios/RustwarIOS/RustwarIOS/GameController.swift`
- `ios/RustwarIOS/RustwarIOS/RootGameView.swift`
- `ios/RustwarIOS/RustwarIOS/TacticalMapView.swift`

Do not modify `index.html`, `styles.css`, `app.js`, Swift core gameplay rules, or CI workflow.

## Functional requirements

1. Add a small native tactical map overlay in the iOS root view, preferably bottom trailing so it does not cover the top HUD.
2. Draw a stable top-down battlefield summary from `controller.engine.state`:
   - resource nodes;
   - player and enemy units;
   - player and enemy buildings;
   - the current camera center or viewport marker.
3. Use native SwiftUI drawing, such as `Canvas`; do not use `WKWebView`, Web canvas, screenshots, external images, or third-party dependencies.
4. Support tap/drag-end on the tactical map to center the main battlefield camera on the corresponding world coordinate.
5. Clamp camera centering to map bounds through `CameraState`, not by writing raw `camera.center` from the view.
6. Preserve existing battlefield gestures, HUD buttons, map switch, restart, pause/speed, Move, Attack, and production controls.
7. Ensure the minimap updates as units move, units/buildings die, production spawns units, map switches, and the camera changes.
8. Keep accessibility acceptable:
   - provide an accessibility label and hint;
   - treat the map as a button-like interactive control;
   - do not rely only on color when drawing different entity categories.

## Non-goals

- No Web behavior change.
- No `WKWebView`.
- No fog of war, radar signal rules, right-click minimap commands, attack-move/patrol/reclaim commands, viewport rectangle precision, mode parity, save/load, or sandbox.
- No new Swift core tests unless gameplay logic changes.
- No manual browser regression unless the human asks.
- No new external dependency or build system.

## SwiftUI guidance

- Keep shared state in `@MainActor @Observable GameController`.
- `TacticalMapView` may take `let controller: GameController`; use `@Bindable` only for controls that require bindings.
- Keep draw helpers value-based and avoid mutating gameplay state inside drawing code.
- Use a fixed, stable minimap frame with an 8 pt or smaller radius and at least a 44 pt interactive target.
- Do not place a card inside another card.

## Xcode project note

The iOS project uses explicit `PBXGroup` / `PBXSourcesBuildPhase` entries, not file-system synchronized groups. If `TacticalMapView.swift` is added as a new file, also add it to:

- `PBXBuildFile`
- `PBXFileReference`
- the `RustwarIOS` group children
- the target `PBXSourcesBuildPhase`
