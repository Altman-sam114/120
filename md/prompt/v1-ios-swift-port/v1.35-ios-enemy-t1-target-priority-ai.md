# v1.35 / iOS native enemy T1 target priority AI

## 角色

本提示词交给 Agent B 执行。Agent B 必须遵守 `AGENTS.md` 的 main 直推、轻量本地检查、GitHub Actions artifact 和 Agent C 复判流程。

## 背景

v1.33 已让红方 Land Factory 使用完整 T1 列表生产 Scout / Light Tank / Hover Tank / Artillery / AA Tank，v1.34 又恢复了 Command Center 生产 Builder。当前红方进攻 AI 仍只在 `updateEnemyAttackOrders()` 中给空闲战斗单位选择最近玩家目标，所有 T1 单位没有角色差异。Web 原型里自动索敌会考虑关键建筑、支援单位和武器适配；本轮只做一个小步：让红方 Artillery 在新获得 AI 攻击订单时更偏向打玩家建筑。

## 目标

- 红方空闲 Artillery 由 AI 新分配攻击订单时，优先选择存活的玩家建筑目标；若没有玩家建筑，则回退到现有最近目标逻辑。
- 红方其它 T1 战斗单位继续使用现有最近玩家单位/建筑目标逻辑。
- 玩家手动 `issueAttack`、Attack-Move、Patrol、Guard 的临时索敌行为不变。
- 同步 README、flow、flowchart、test 和 update_log。

## 非目标

- 不修改 Web `index.html` / `styles.css` / `app.js`。
- 不新增 SwiftUI / SpriteKit UI，不新增战术小地图交互。
- 不修改 `nearestCombatTarget(for:)` 的全局语义，避免影响 Attack-Move、Patrol、Guard。
- 不引入完整威胁评分、阵型、集火、难度倍率、进攻波编组、T2/空军/海军/实验单位策略。
- 不改变玩家手动命令和现有攻击推进、伤害、死亡清理规则。

## 建议实现

- 修改 `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`：
  - 在 `updateEnemyAttackOrders()` 中，把 `nearestCombatTarget(for:)` 替换为红方 AI 专用 helper，例如 `enemyAttackTarget(for:)`。
  - `enemyAttackTarget(for:)` 对 `.artillery` 先调用 `nearestEnemyArtilleryBuildingTarget(for:)`；找到玩家建筑时返回该建筑目标，找不到时回退 `nearestCombatTarget(for:)`。
  - `nearestEnemyArtilleryBuildingTarget(for:)` 只扫描 `state.buildings` 中 `team == .player && hitPoints > 0` 的建筑，按距离选择最近建筑，使用建筑 `size / 2` 作为 `CombatTarget.radius`。
  - 不扩展 `CombatTarget`，除非实现时确有必要。

## 测试要求

在 `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift` 增加 Swift tests，至少覆盖：

- 红方 Artillery 在玩家单位更近、玩家建筑更远时仍选择玩家建筑。
- 红方非 Artillery T1 单位在同样场景下仍选择最近玩家单位。
- 红方 Artillery 在没有玩家建筑时回退选择最近玩家单位。
- 玩家手动攻击测试不需要新增专门覆盖，但不得破坏已有 `attackCommand...` tests。
