# v1.77 / iOS explored fog memory

## 目标

为原生 Swift core 和 iOS App 增加玩家已探索 tile 记忆，让 fog 从“当前不可见全黑遮盖”进化为“当前可见 / 已探索但当前不可见 / 从未探索”的基础分层，更接近 Web/Rusted Warfare 的战争迷雾语义。

验收语义：

- `GameState` 应保存每队已探索 tile 集合，并兼容旧 JSON：旧存档缺字段时应正常解码为空集合，再由 `GameEngine(state:)` 用当前视野播种。
- 新建 `GameState` 应立即拥有双方当前视野对应的 explored tile，而不是等第一帧 update 后才有记忆。
- `GameEngine.update(deltaTime:)` 每 tick 应把当前可见 tile 合并进对应队伍的 explored 集合；单位移动后探索过的旧区域应保持 explored。
- `VisibilitySnapshot` 或相邻 helper 应支持 iOS 判断某 tile 是否当前可见、是否已探索。
- iOS 主战场雾层应把当前不可见但已探索区域绘制为较浅遮罩，把从未探索区域绘制为较深遮罩。
- iOS 战术小地图雾层也应按同样语义区分已探索和从未探索区域。
- 敌方单位/建筑当前仍只能在当前可见时显示；本轮不引入雷达信号或已探索实体残影。

## 非目标

- 不实现雷达建筑、雷达信号、已探索敌方残影、资源/残骸隐藏、AI 情报限制、目标记忆、Web `app.js` 迁移或完整 fog parity。
- 不修改 Web 原型，不引入第三方依赖，不使用 `WKWebView`。
- 不改变当前可见敌方过滤命中规则；雾外敌方仍不可被 iOS 精确选中或下达 Attack。

## 实现建议

- `VisibilitySnapshot.swift`
  - 让可见 tile 集合可以被 core helper 合并或读取，保持 `isVisible` API 不变。
- `GameState.swift` / `GameStateVisibility.swift`
  - 新增 `exploredTileIndicesByTeam: [Team: Set<Int>]` 或等价结构。
  - 新增 `exploredVisibility(for:) -> VisibilitySnapshot` 和 `revealVisibleTiles(for:)` / `updateExploredVisibility()` 之类 helper。
  - `init(mapID:)` 在单位和建筑完成初始化后播种双方 explored。
  - `init(from:)` 对旧 JSON 缺字段默认空集合。
- `GameEngine.swift`
  - `init(state:)` 对恢复状态补一次 explored 播种，避免旧存档或外部构造状态一进 iOS 就没有已探索记忆。
  - `update(deltaTime:)` 在单位移动和建造/死亡状态推进后合并各队当前视野。
- `BattlefieldScene.swift`
  - `drawFog` 同时接收当前可见和已探索快照。
  - 当前可见不遮盖，已探索但当前不可见使用较浅遮罩，从未探索使用较深遮罩。
- `TacticalMapView.swift`
  - Canvas snapshot 读取 `state.exploredVisibility(for: .player)`。
  - `drawFog` 同样绘制已探索/未探索分层。

## 测试

在 `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift` 增加覆盖：

- 新建状态的玩家 explored 至少包含初始当前视野。
- 单位移动并 `engine.update` 后，旧可见区域保持 explored，新位置也被 explored。
- 旧 JSON 缺少 explored 字段时可解码，恢复进 `GameEngine(state:)` 后会播种当前视野。
- JSON round trip 保留 explored 集合。
