# v1.25 / iOS native factory repeat production

## Agent B 任务

在 v1.10 原生生产取消/退款和 v1.11 Save/Load 基础上，补齐 Web 版“工厂支持重复生产开关”的 iOS 最小 parity：选中己方陆军工厂时可循环设置重复生产目标，生产队列清空后自动尝试续造该单位，资源或人口不足时保留 repeat 设置等待后续机会。

## 背景依据

- Web 原型 README 已列出“工厂支持重复生产开关，队列清空后会自动尝试续造指定单位”。
- 原生 iOS 当前已有 Scout / Light Tank 入队、Cancel Production、Rally、Save/Load 和生产完成出兵，但没有 repeat 状态。
- `BuildingSnapshot` 已保存 `productionQueue` 和 `weaponCooldown`，适合新增可持久化的 repeat 单位字段，并通过自定义 decode 兼容旧 JSON。
- `GameEngine.enqueueUnit(_:,at:)` 已封装可生产性、金属、人口和扣费逻辑，repeat 续造必须复用它，避免重复规则。

## 目标

1. Swift core 状态：
   - 在 `BuildingSnapshot` 增加可选 repeat 单位字段，默认 `nil`。
   - JSON 编码/解码保留 repeat 状态；旧 JSON 缺失字段时解码为 `nil`。
2. Swift core API：
   - 新增 repeat 专用结果类型，不扩展 `ProductionCommandResult` 或 `ProductionCancelResult`。
   - 新增公开方法让当前选中的己方生产建筑设置或清除 repeat 单位。
   - 只允许生产建筑设置其 `produces` 支持的单位；无选择、选中单位、敌方建筑、非生产建筑和不支持单位都要返回明确拒绝结果。
3. 生产推进：
   - `updateProduction(deltaTime:)` 在队首完成、出兵、队列为空后，若该玩家生产建筑设置了 repeat 单位，则调用现有 `enqueueUnit` 尝试自动续造。
   - 自动续造要在资源/人口不足时失败但保留 repeat 设置，不扣负资源、不清状态。
   - 队列仍有其它项时不插入 repeat；最后一项完成并清空后才尝试。
   - `cancelLastProduction()` 只取消队尾并退款，不清 repeat。
4. iOS HUD：
   - 选中己方生产建筑时，在现有命令 `LazyVGrid` 中加入一个 `Repeat` 循环按钮。
   - 按钮循环 `Off -> Scout -> Light Tank -> Off`，由当前工厂 `produces` 列表决定顺序。
   - 按钮必须有文字 label、系统图标、44pt 最小触控高度和 VoiceOver 的当前值说明；状态不能只靠颜色区分。
   - repeat 不是 pending target command，不接入 Stop 或 `clearPendingTargetCommands()`。
5. 测试和文档：
   - Swift tests 覆盖 JSON 往返、旧 JSON 兼容、API 拒绝、循环/覆盖、完成后续造、多队列不提前续造、资源/人口不足保留 repeat、取消生产不清 repeat。
   - 更新 README、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和 `update_log.md`。

## 非目标

- 不改变 Web `index.html` / `app.js` / `styles.css` 运行链路。
- 不新增多工厂生产面板、指定队列项取消、Shift 队列、生产优先级或自动暂停 repeat。
- 不把 repeat 状态存在 SwiftUI view 或 Controller 私有 UI 状态里。
- 不改变红方 AI 生产策略；敌方工厂默认 repeat 仍为 `nil`。
- 不新增 iOS UI 自动化、浏览器回归、第三方依赖或 `WKWebView`。
