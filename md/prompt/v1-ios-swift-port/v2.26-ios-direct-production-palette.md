# v2.26 iOS direct production palette

## 目标

让玩家点选已完成的 Command Center 或 Land Factory 后，无需先滚过队列即可立即看到并操作全部可生产单位。参考 Rusted Warfare 公开生产教学中紧凑、图标优先的侧栏动作矩阵，但不复制第三方素材。

## 实现要求

- 只调整 `TacticalProductionSectionView.swift` 的展示层级和生产按钮标签。
- 顺序固定为 Factory Tech、生产选项、Build Queue、Cancel/Repeat/Rally。
- 默认 Dynamic Type 使用三列生产矩阵；辅助功能字号使用一列。
- 三列按钮使用紧凑标签，一列按钮使用完整标签；两者都必须保留单位图标、名称、metal、population 和真实 build time。
- 每个按钮继续满足至少 44pt 触控目标，并保留 queue action、Shift+1-9、完整 VoiceOver label/hint。
- 队列继续显示当前项的真实百分比、剩余时间、进度条，以及后三项顺序和 buildTime。

## 非目标

- 不修改 RustwarCore、生产数值、科技解锁、队列、退款、Repeat、Rally、AI、战斗、存档或 Web 原型。
- 不新增第三方依赖、UIKit、sprite 资产或 Xcode 工程文件改动。
- 不把固定截图当作 Dynamic Type、VoiceOver、滚动或真机触摸完整回归。

## 验证与验收

- 按人工要求禁止所有本地验证，不运行 `git diff --check`、Swift/Node 检查、Swift tests、Xcode、Simulator、Preview、截图或浏览器验证。
- 在 `main` 仅提交本轮相关文件并 push 到 `origin/main`。
- GitHub Actions 必须在固定 Xcode 26.5 / iOS 26.5 Simulator 中通过 JUnit 8/0/1、至少 311 项 Core tests、arm64/x86_64 build、production/combat 双 launch、orientation 与像素探针。
- Agent C 必须下载最新 commit 对应的未加密 artifact，核对 manifest 的 branch、SHA、run id、attempt、JUnit、主日志和失败摘要。
- `ios-home.png` 必须同屏清楚显示 Factory Tech 与全部六个 T2 生产选项，按钮无文字溢出、裁切或重叠；队列位于选项之后且仍保留 v2.25 信息。
- `ios-combat.png` 不得出现战斗 tableau、HUD 或 Tactical Map 视觉回退。
