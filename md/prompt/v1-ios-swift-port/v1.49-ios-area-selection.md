# v1.49 / iOS native area selection

## Agent B 任务

在原生 Swift/iOS 迁移地基中新增玩家单位框选能力，使 iOS 版从已有 Idle Builders / Combat Units 批量按钮继续靠近 Web RTS 的拖拽框选操作。

本轮按 v1.49 执行，提交信息使用：

```text
v1.49: add iOS area selection
```

## 目标

- 在 `RustwarCore` 增加世界坐标矩形选择模型和 API。
- 在 iOS HUD 增加 `Select Area` 命令按钮。
- 点按 `Select Area` 后进入等待框选状态，下一次在主战场拖拽显示半透明选择框，松手后选择框内所有己方单位。
- 框选只选择己方单位，不选择敌方、建筑、残骸或资源点。
- 框选结果必须同步 `selectedEntityIDs` 和 `selectedEntityID`，继续复用现有多单位 Move / Stop / Attack / Attack Move / Patrol / Guard / Builder 命令。
- 普通一指拖拽仍然平移相机；只有 `Select Area` 等待态中的拖拽才执行框选。

## 非目标

- 不修改 Web `app.js` 框选逻辑。
- 不实现 Shift 追加/反选、多指手势、从空地自动区分平移/框选或控制编队。
- 不把 Web 版打包进 `WKWebView`。
- 不新增第三方依赖、后端、构建链或资源文件。
- 不把建筑框选纳入 v1.49；建筑多选和混编选择留给后续轮次。

## 建议实现方案

### Swift core

新增 `WorldRect`，建议放在 `swift/RustwarCore/Sources/RustwarCore/WorldRect.swift`：

- `Codable`
- `Equatable`
- `Sendable`
- `minX/minY/maxX/maxY`
- `init(_ a: WorldPoint, _ b: WorldPoint)` 自动归一化反向拖拽角点。
- `contains(_ point: WorldPoint) -> Bool`，边界点算命中。

在 `GameStateSelection.swift` 增加：

- `func playerUnitSelectionTargets(in rect: WorldRect) -> [SelectionTarget]`
- 按 `state.units` 顺序返回所有 `team == .player` 且 `hitPoints > 0` 且单位中心在矩形内的单位。

在 `GameEngine.swift` 增加：

- `@discardableResult public mutating func selectPlayerUnits(in rect: WorldRect) -> [String]`
- 将目标 ID 写入 `state.selectedEntityIDs`。
- 将 `state.selectedEntityID` 写成第一个 ID；空结果写 `nil` 并清空多选。
- 返回选中的 ID 列表。

### iOS controller

在 `GameController.swift` 增加：

- `var isAwaitingAreaSelection = false`
- `var canIssueAreaSelection: Bool`，只要存在己方单位即可显示或可用。
- `var areaSelectionCommandButtonTitle: String`，等待态显示 `Cancel`，普通态显示 `Select Area`。
- `toggleAreaSelectionCommand()`：进入时 `clearPendingTargetCommands()`，设置等待状态和 `commandStatus = "Drag area to select units"`；再次点按取消。
- `handleBattlefieldAreaSelection(from:to:viewportSize:)`：把屏幕起点/终点通过 `camera.worldPoint(for:viewportSize:)` 转成 `WorldRect`，调用 `engine.selectPlayerUnits(in:)`，退出等待态，设置 `commandStatus` 为 `"\(count) units selected"` 或 `"No units in area"`，并递增 `renderRevision`。
- `handleBattlefieldTap(...)` 在 `isAwaitingAreaSelection` 时不要执行普通点选，避免短拖或误 tap 破坏等待态。
- `clearPendingTargetCommands()` 必须清掉 `isAwaitingAreaSelection`。
- `isAwaitingTargetCommand`、Stop 按钮显示条件、`commandStatus` 颜色判断等需要把 area selection 等待态纳入统一待命状态。

### iOS view

在 `BattlefieldView.swift` 中保留现有 `SpriteView` 渲染，但用 `ZStack` 包裹：

- 新增私有 `@State` 存储选择框起点和当前点。
- 当 `controller.isAwaitingAreaSelection` 且拖拽进行中时显示 SwiftUI 屏幕空间选择框 overlay。
- 等待态拖拽时不调用 `controller.pan(by:)`。
- 非等待态拖拽完全沿用现有增量平移逻辑。
- 松手时调用 `controller.handleBattlefieldAreaSelection(from:to:viewportSize:)`，随后清空本地选择框状态。
- overlay 只负责视觉，不要写入 `BattlefieldScene`。

SwiftUI 注意事项：

- `@State` 保持 `private`。
- overlay 必须 `allowsHitTesting(false)`。
- 使用系统 Dynamic Type 风格，不引入固定文字说明浮层。
- 按钮使用 `Button("Select Area", systemImage: ..., action: ...)` 形式，保留 VoiceOver 文本。

### HUD

在 `GameHUDView.swift` 的批量选择区域或命令区加入 `Select Area`：

- 推荐放在 Idle Builders / Combat Units 同一行或附近。
- 等待态按钮显示取消图标。
- Stop 按钮也能取消等待框选。
- 为按钮增加 accessibility label/hint。
