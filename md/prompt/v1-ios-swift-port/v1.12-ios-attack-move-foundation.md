# v1.12 / iOS native attack-move foundation

## Agent A brief

Version: `v1.12`

Goal: add a native iOS single-unit attack-move command so the SwiftUI/SpriteKit app can issue an attack-move destination to the currently selected player unit. The unit should move toward that destination, acquire nearby enemy targets while moving, attack them with existing combat rules, and clear the order when it reaches the destination with no target in range.

## Background

- Web Rustwar already supports attack-move as part of its broader RTS command set.
- Native iOS currently supports single selected player unit Move, Attack and Stop, plus production, rally, save/load and enemy AI.
- `RustwarCore` already owns unit orders, combat movement, damage, death cleanup and deterministic Swift tests.
- The iOS app should remain native SwiftUI/SpriteKit. Do not use `WKWebView` or Web code wrapping.

## Functional requirements

1. Extend `UnitOrder` with a Codable/Equatable/Sendable attack-move order that stores only the destination.
2. Add `GameEngine.issueAttackMove(to:) -> UnitCommandResult`:
   - requires an active selection;
   - requires the selected entity to be a player unit;
   - clamps the destination to map bounds;
   - writes the attack-move order without changing selection.
3. Add attack-move simulation in `GameEngine.updateUnitOrders`:
   - each update, find the nearest living enemy unit or building within the selected unit definition's `vision` range;
   - if a target is in acquisition range, reuse existing attack-order behavior for range closing, cooldown, damage and destroyed target cleanup;
   - if no target is in acquisition range, move toward the stored destination with existing move behavior;
   - when the unit reaches the destination and no target is acquired, clear the order.
4. Keep full-map AI target acquisition behavior unchanged. Attack-move acquisition must be bounded to the moving unit's vision and must not make player units chase distant enemies across the whole map.
5. Keep `issueStop()` clearing attack-move naturally through `order = nil`.
6. Add Swift tests proving:
   - attack-move rejects missing selection and enemy/building selections using existing result semantics;
   - attack-move moves toward its destination and clears on arrival when no target enters vision;
   - attack-move acquires an enemy in vision and causes damage using existing combat rules;
   - Stop clears an active attack-move order;
   - JSON round-trip preserves an active attack-move order.
7. Add iOS controller state for a pending attack-move target:
   - Move, Attack, Attack-Move and Rally target modes must be mutually exclusive;
   - battlefield tap in attack-move mode calls `issueAttackMove(to:)`;
   - map switch, restart, load and Stop clear the pending attack-move mode;
   - status text should distinguish attack-move from plain Move/Attack.
8. Add a native HUD button for Attack Move near Move and Attack:
   - use a text-labeled SwiftUI `Button` with a system image;
   - maintain 44 pt minimum tap target;
   - keep existing Save/Load, Pause, Speed, Rally, Stop, production and cancel controls working.
9. Render attack-move orders in SpriteKit with a distinct line and destination marker, for example an amber line and an `A` marker. Rendering should show the destination even while the unit is eligible to acquire nearby targets.
10. Preserve existing Move, Attack, Stop, Rally, production, production cancel, enemy AI, map switch/restart, pause/speed, tactical minimap, camera and Save/Load behavior.

## Non-goals

- No Web behavior change.
- No multi-unit attack-move.
- No queued or Shift attack-move.
- No patrol, guard, reclaim or transport command migration.
- No pathfinding, formation movement, collision avoidance or target priority matrix.
- No minimap attack-move command.
- No fog/radar integration.
- No save migration beyond preserving Codable behavior for newly saved v1.12 states.
- No third-party dependency or new build system.

## SwiftUI guidance

- Keep command state and command actions in `GameController`; do not put game command logic in `GameHUDView.body`.
- Prefer text-labeled buttons such as `Button("Attack Move", systemImage: "...", action: controller.toggleAttackMoveCommand)` for VoiceOver.
- Keep the command row compact and consistent with existing Move, Attack, Stop and Rally controls.
- Do not introduce UIKit or third-party libraries.
