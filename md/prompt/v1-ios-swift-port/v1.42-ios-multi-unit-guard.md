# v1.42 / iOS native multi-unit Guard

## Agent A 目标

把原生 iOS 迁移地基中的 Guard 命令从 primary selection 单单位语义升级为多单位选择语义，使它与 v1.39 Move / Stop、v1.40 Attack-Move、v1.41 Patrol 的多选命令行为保持一致。

本轮只推进 Guard parity，不改 Web 原型，不引入新架构，不扩大到 Repair / Reclaim / Build / Attack 等其它命令。

## 背景

当前 `GameEngine.issueGuard(targetID:)` 只读取 `state.selectedEntityID`，因此 Idle Builders / Combat Units 批量选择后只能让 primary unit 护航目标。v1.38 已提供 `selectedEntityIDs` 多选集合，v1.39 到 v1.41 已提供并验证 `selectedCommandEntityIDs()` 和 `selectedPlayerUnitIndices()` 供多选命令复用，本轮应沿用这些 helper。

Guard 与点位命令不同：目标是友方单位或建筑。多选时应让所有选中己方单位护航同一友方目标；若目标本身也在选择集合中，目标自身不能护航自己，应被跳过，其它选中己方单位仍可护航该目标。

## 实现范围

### Swift Core

修改 `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`：

- `issueGuard(targetID:)` 必须先使用 `selectedCommandEntityIDs()` 判断是否存在可用选择，保持无选择时返回 `.noSelection`。
- 使用 `selectedPlayerUnitIndices()` 过滤当前选择中的己方单位。
- 选择集合存在但没有己方单位时返回 `.selectedEntityCannotMove`。
- 目标必须是存活友方单位或建筑；敌方、缺失目标、非法目标仍返回 `.invalidGuardTarget`。
- 多选时，对所有选中己方单位写入 `.guardTarget(targetID:offset:)`，目标 id 相同。
- 每个单位的 `offset` 必须使用该单位自身当前位置和目标位置计算，继续复用 `guardOffset(for:around:)`。
- 若目标单位本身也在选择集合中，跳过该单位，避免自我护航；若跳过后没有任何单位可下令，返回 `.invalidGuardTarget`。
- 不改变 `UnitOrder.guardTarget` 数据结构、Guard 推进逻辑、临时索敌、目标消失清理或 JSON 存档形状。

### iOS App

修改 `ios/RustwarIOS/RustwarIOS/GameController.swift`：

- `canIssueGuard` 改为使用 `!selectedPlayerUnits.isEmpty`。
- `toggleGuardCommand()` 的等待态文案在多选时显示单位数量，例如 `Guard target for 3 units`。
- `statusText(forGuard:)` 在 `.issued` 时根据当前选中己方单位数量返回单/多单位反馈，例如 `Guard order issued to 3 units`。
- 主战场 tap 和战术小地图实体命中继续复用现有 `handleSelectionTargetCommand(at:)` 和 `engine.issueGuard(targetID:)`，不新增 UI 分支。

### Tests

修改 `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift`：

- 增加多选 combat group 下达 Guard 后，所有选中己方单位均获得 `.guardTarget` 的测试。
- 覆盖每个单位的 `offset` 与自身位置相关，不能所有单位共用 primary unit offset。
- 覆盖混合选择中包含不存在 ID、敌方 ID 或建筑 ID 时，只命令有效己方单位并返回 `.issued`。
- 覆盖选择集合存在但没有己方单位时返回 `.selectedEntityCannotMove`。
- 覆盖多选中包含护航目标自身时跳过自我护航，但其它选中己方单位仍获得 Guard。
- 覆盖仅选中护航目标自身时返回 `.invalidGuardTarget`。
- 可补充 Stop 对多选 Guard 的清理测试，确保多选 Guard 订单被现有 `issueStop()` 清除。
- 保持既有单单位 Guard、Guard 临时索敌、目标摧毁清理和 JSON 往返测试通过。
