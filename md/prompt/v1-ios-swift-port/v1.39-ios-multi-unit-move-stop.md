# v1.39 / iOS native multi-unit Move and Stop

## 角色

本提示词交给 Agent B 执行。Agent B 必须遵守 `AGENTS.md` 的 main 直推、轻量本地检查、GitHub Actions artifact 和 Agent C 复判流程。

## 背景

v1.38 已在原生 core 中建立 `selectedEntityIDs` 多选集合，并在 iOS HUD 增加 Idle Builders / Combat Units 批量选择入口；但现有 Move / Stop 仍只作用于 primary `selectedEntityID`。Web 版的 RTS 操作核心是批量选中后对一组单位下令，本轮把最基础、风险最低的 Move 和 Stop 扩展到多选集合，让 v1.38 的多选地基开始具备实际命令价值。

## 目标

- `GameEngine.issueMove(to:)` 在 `selectedEntityIDs` 包含多个己方单位时，给所有可移动己方单位写入 `.move(destination:)`。
- `GameEngine.issueStop()` 在 `selectedEntityIDs` 包含多个己方单位时，清除所有选中己方单位的当前移动、攻击移动、巡逻、护航、维修、回收、建造或攻击订单。
- 单选行为保持兼容：只有 `selectedEntityID` 或 `selectedEntityIDs` 单元素时，结果与 v1.38 之前一致。
- 如果多选集合混入建筑、敌方单位或不存在 id，应忽略无效 id；只要至少一个己方单位可执行，就返回 `.issued`。
- 如果没有任何选中 id，仍返回 `.noSelection`；如果有选择但没有可移动/可停止己方单位，返回现有 `.selectedEntityCannotMove` / `.selectedEntityCannotStop`。
- iOS 现有 Move / Stop 按钮、主战场 tap、战术小地图 Move 点位命令自然复用新 core 语义；可更新状态文案为复数，但不新增 UI 面板。
- 同步 README、flow、flowchart、test 和 update_log。

## 非目标

- 不修改 Web `index.html` / `styles.css` / `app.js`。
- 不实现多单位 Attack、Attack Move、Patrol、Guard、Repair、Reclaim、Build、Rally 或生产命令。
- 不实现队形保持、自动方阵整理、路径规划、碰撞避让或 Shift 追加队列。
- 不改变 `selectedEntityIDs` Codable schema，不新增存档版本迁移。
- 不用 `WKWebView` 或网页包装。

## 建议实现

- 修改 `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`：
  - 新增私有 helper，例如 `selectedEntityIDsForCommand()`，优先使用非空 `state.selectedEntityIDs`，否则回退 `state.selectedEntityID`。
  - 新增 helper 返回选中己方单位 indices，保持 `state.units` 中的稳定顺序，避免 Set 打乱命令顺序。
  - `issueMove(to:)` 对所有选中己方单位写入同一个 `destination.clampedToMap()`。
  - `issueStop()` 清除所有选中己方单位 `order`。
  - 保持生产建筑、Builder 建造/维修等其它 API 仍按 primary selection 工作。

- 修改 `ios/RustwarIOS/RustwarIOS/GameController.swift`：
  - 可增加 `selectedPlayerUnitCount`，让 `statusText(for:)` / `statusText(forStop:)` 在多选成功时显示 `Move orders issued` / `Stop orders issued`。
  - `canIssueMove` / `canIssueStop` 应在多选集合中有任意己方单位时为 true。
  - 不要把 SwiftUI view 变成规则层。

## 测试要求

在 `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift` 增加 Swift tests，至少覆盖：

- 多选 Combat Units 后 `issueMove(to:)` 给所有选中己方非 Builder 单位写入 `.move`。
- 多选集合里混入敌方、建筑、缺失 id 时，`issueMove(to:)` 只作用于有效己方单位且返回 `.issued`。
- 多选 Stop 清除所有选中己方单位不同类型订单，且不影响未选中单位。
- 多选集合只有敌方或建筑时，Move / Stop 返回对应不能执行错误。
- 单选 Move / Stop 既有测试继续通过。
