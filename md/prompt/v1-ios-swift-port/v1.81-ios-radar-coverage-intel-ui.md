# v1.81 / iOS radar coverage intel UI

## Agent A 目标

本轮继续把 Web 版雷达体验向原生 Swift/iOS 迁移一步：在不改变视野、探索、命中或攻击规则的前提下，为完成状态 Radar Station 暴露只读雷达覆盖 snapshot，并在 iOS 主战场、战术小地图、HUD 和 VoiceOver 中显示玩家雷达覆盖与雷达 contact 摘要。

## 目标

- 在 `RustwarCore` 新增 `RadarCoverageSnapshot`，描述完成、存活、带 `radarRange` 的雷达来源。
- 在 `GameState` 新增 `radarCoverage(for:) -> [RadarCoverageSnapshot]`，只返回指定队伍自己的雷达覆盖来源。
- 重构 `radarContacts(for:)` 复用同一雷达来源过滤，保持既有 contact 语义不变。
- iOS 主战场选中完成状态己方 Radar Station 时绘制雷达覆盖范围圈。
- iOS 战术小地图绘制完成状态己方 Radar Station 覆盖圈，并继续显示现有雷达 contact 点。
- iOS HUD 显示轻量雷达情报摘要：玩家 Radar Station 数量和当前 radar-only contact 数量。
- 战术小地图 VoiceOver value 纳入雷达站和 contact 数量。
- 更新 README、flow、flowchart、test 和 update_log。

## 非目标

- 不增加 Radar Station 升级、雷达干扰、雷达目标记忆或雾内敌方残影。
- 不让 radar-only contact 变成可选择、可攻击、可 Guard/Repair 命中的真实实体。
- 不改变 `visibility(for:)`、`exploredVisibility(for:)` 和 explored tile 写入语义。
- 不改 Web `index.html`、`styles.css`、`app.js`。
- 不引入第三方依赖、WKWebView、后端或构建链。

## 建议实现

### Swift core

- 新增 `swift/RustwarCore/Sources/RustwarCore/RadarCoverageSnapshot.swift`：
  - `public struct RadarCoverageSnapshot: Equatable, Sendable`
  - 字段：`buildingID: String`、`team: Team`、`position: WorldPoint`、`visionRange: Double`、`radarRange: Double`
  - 提供 public init。
- 在 `GameStateVisibility.swift`：
  - 新增 `func radarCoverage(for team: Team) -> [RadarCoverageSnapshot]`。
  - 抽出私有雷达来源 helper，只包含 `building.team == team`、`hitPoints > 0`、`buildProgress >= 1`、`GameDefinitions.building(building.type).radarRange > 0` 的建筑。
  - 让 `radarContacts(for:)` 复用该 helper；contacts 仍只返回当前不可见且位于雷达范围内的敌方单位/建筑。

### iOS

- `BattlefieldScene.swift`：
  - `renderNow()` 读取 `state.radarCoverage(for: .player)`。
  - 在选中完成状态己方 Radar Station 时绘制覆盖圈；建议在实体下方或雷达层中以低 alpha 青色填充、较明显 stroke、虚线/双圈辅助区分。
  - 覆盖圈只用于反馈，不改变 fog、entity draw 或 hit-test。
- `TacticalMapView.swift`：
  - 读取 `playerRadarCoverage`，在 `drawFog` 后、`drawRadarContacts` 前或后绘制覆盖圈；保持 fog 仍能表达未探索/已探索状态。
  - 支持 `accessibilityDifferentiateWithoutColor` 时追加非纯颜色线型差异。
- `GameController.swift`：
  - 新增 `playerRadarStationCount` 和 `playerRadarContactCount` computed properties，来源分别为 `state.radarCoverage(for: .player).count` 和 `state.radarContacts(for: .player).count`。
  - `tacticalMapAccessibilityValue` 无 pending 命令时返回包含雷达站/contact 数量的字符串；有 pending 命令时保留 pending 信息并追加雷达摘要。
- `GameHUDView.swift`：
  - 顶部经济栏附近加入轻量 `Radar` 摘要，显示 `站点数/contact 数`，使用 Dynamic Type 友好的 Text，不做大型新面板。


若本机 SwiftPM 或 Xcode/SDK 阻塞，必须记录真实错误；至少保留 `swiftc` typecheck/parse 检查结果。修改 iOS 文件后必须尝试 `xcodebuild -list` 和 iOS build，失败时如实说明本机工具链限制。

新增 Swift tests 至少覆盖：

- 完成状态玩家 Radar Station 会出现在 `radarCoverage(for: .player)`，字段包含 `buildingID`、`team`、`position`、`visionRange=260`、`radarRange=920`。
- 未完成、死亡、非雷达、敌方 Radar Station 不会出现在玩家 coverage。
- Command Center 仍不会提供 coverage。
- `radarContacts(for:)` 语义不变：只返回不可见且在雷达范围内的敌方 contact，不写入 visibility/explored，不放宽玩家可见敌方命中。
- 红方 AI 建成的 completed Radar Station 会出现在 `radarCoverage(for: .enemy)`。
