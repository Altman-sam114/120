# v2.46 iOS touch intent owner and Rusted Warfare-style command feel

## 版本分配依据

- `v2.46` 延续 v2.45 presentation 收敛，优先解决 iOS 主战场最影响可玩性的单指/多指意图竞态。

## 目标

- 为 `BattlefieldView` 引入单一 `BattlefieldTouchIntent` owner，统一 tap、long press、pan、area selection、multitouch selection、pinch 和 cancelled 生命周期；同一触摸序列只有一个 owner 可以提交行为。
- 第二指/第三指或触点 ID 替换一旦被 `SpatialEventGesture` 观察到，立即夺取当前序列，取消 context/pan，禁止旧单指回调继续平移、长按或 tap；两指同向/静置仍复用既有框选分类，张合仍复用既有 pinch。
- 将普通拖拽激活阈值从 8pt 调整为 12pt，保留 18pt long-press tolerance，让自然轻微抖动不再抢走长按，同时真正平移仍持续抑制 tap/long press。
- context `DragGesture.onEnded` 无论回调时间是否迟到都必须清理活动生命周期；保留取消哨兵和时间门控，不能让旧回调卡死下一次触摸。
- 地图 reset/重建时清空 `battlefieldTouchID`，活动序列递增取消 epoch，旧 Spatial/context 回调不能重新获得 owner；下一次新触摸可正常 tap、长按或平移。

## 当前合同与必须保持的行为

- 无等待命令时：单指 tap 己方单位/建筑走 Replace/Add 选择；已有己方作战单位选择时，tap 可见敌人走 `Attack`，空地走 `Attack-Move` 自动接敌。
- 无等待命令时：长按上下文仍由 `GameController.handleBattlefieldContextCommand` 派发 Move / Attack / Guard / Repair / Reclaim / Build Extractor / Rally。
- 两指同向/静置框选、pinch、第三指/取消拒绝和 `MultitouchIntentClassifier` 阈值保持；pending target command 不被多指框选抢走。
- 直接 tap 存活己方建筑仍强制 Replace，dock 立即显示 Production / queue / rally / Upgrade context。
- `battlefieldTouchSequence`、`battlefieldGestureGeneration`、`DragGesture.Value.time` 迟到过滤和 map reset cancellation sentinel 继续可追踪；不以旧回调重置新 owner。

## 实现步骤

1. 在 `BattlefieldView` 增加私有 intent enum/state 与小型 helper，默认 owner 为 possible；tap/long-press/pan/context/magnify/Spatial handlers 先检查 owner。
2. `SpatialEventGesture` 看到 active touch 数达到 2 时先 claim multitouch，再执行现有 classifier；claim 时清理 context location、pan delta、active pan、long-press资格并建立现有 suppression。
3. classifier 返回 selection/pinch/rejected 时更新 owner；结束时只提交合法框选，并递增 touch sequence 后释放 owner。
4. pan 使用 12pt activation；area selection 只在 owner 获得后更新 overlay；long press 成功后锁定 long-press owner，tap 不再尾随触发。
5. context `onEnded` 先保存 `wasCancelled` 并无条件清理 started/location/time state，再按时间门控决定是否清除取消哨兵；迟到 end 不能留下卡死状态。
6. map reset 在活动序列上递增 cancellation epoch、清空 touch ID 和 overlay；旧回调只能被丢弃。
