# v1.38 / iOS native selection groups foundation

## 角色

本提示词交给 Agent B 执行。Agent B 必须遵守 `AGENTS.md` 的 main 直推、轻量本地检查、GitHub Actions artifact 和 Agent C 复判流程。

## 背景

Web 版已经支持框选、空闲工程单位、当前屏幕作战单位和全作战单位等批量选择入口。原生 iOS 版目前只通过 tap 写入单个 `selectedEntityID`，HUD 和战场也只显示一个选中目标。本轮先建立原生多选状态和两个轻量批量选择入口，让后续多单位 Move / Attack Move / Stop 等命令迭代有真实状态基础。

## 目标

- 在 `RustwarCore` 的 `GameState` 中新增可 Codable 的多选集合，例如 `selectedEntityIDs: [String]`，并保持旧 `selectedEntityID` 单选字段兼容。
- `GameEngine.select(at:)` 继续单选，但应同步清空/重建多选集合，保持 `selectedEntityID` 是 primary selection。
- 新增公开 core API：
  - 选择全部空闲己方 Builder。
  - 选择全部己方战斗单位。
- iOS HUD 新增两个有文字和系统图标的按钮：Idle Builders / Combat Units。
- 按钮点按后更新 core 多选集合、HUD 选择摘要和战场/战术小地图选中高亮，不重置地图、相机、暂停、速度、AI 开关、生产队列或待选命令以外的状态。
- 多选摘要应清楚显示数量，例如 `3 idle Builders selected`、`5 combat units selected` 或无匹配时 `No idle Builders`。
- Save / Load 继续保存并恢复多选集合。
- 同步 README、flow、flowchart、test 和 update_log。

## 非目标

- 不修改 Web `index.html` / `styles.css` / `app.js`。
- 不实现拖拽框选、双击同类选择、控制编队、屏幕内选择或 Ctrl+A。
- 不在本轮实现多单位命令派发；现有 Move / Attack / Build / Production 等命令仍可按 primary `selectedEntityID` 语义工作。
- 不改变现有单位订单、AI、生产、存档版本号或地图预设。
- 不用 `WKWebView` 或网页包装。

## 建议实现

- 修改 `swift/RustwarCore/Sources/RustwarCore/GameState.swift`：
  - 新增 `public var selectedEntityIDs: [String]`。
  - 新存档编码该字段；旧存档缺失时 decode 为 `selectedEntityID.map { [$0] } ?? []` 或空数组。
  - 初始状态为空数组。

- 修改 `swift/RustwarCore/Sources/RustwarCore/GameStateSelection.swift`：
  - `selectionSummary()` 使用当前有效多选集合生成摘要。
  - 单选时保持旧摘要，例如 `Green Command Center`。
  - 多选同类 Builder / combat units 时显示数量；混合选择可显示通用数量。

- 修改 `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`：
  - `select(at:)` 单选后同步 `selectedEntityIDs`。
  - 增加 `selectIdlePlayerBuilders()` 和 `selectPlayerCombatUnits()`，返回选中数量或选中 ids。
  - 批量选择只接受存活己方单位；idle Builder 需 `type == .builder && order == nil`；combat units 需己方非 Builder 单位。
  - `updateCombatTargetHealth()` 或目标清理处移除已死亡 id 后同步 primary selection。
  - 保持所有现有命令继续使用 primary `selectedEntityID`。

- 修改 `ios/RustwarIOS/RustwarIOS/GameController.swift`：
  - 增加按钮标题/可用性或 action：`selectIdleBuilders()`、`selectCombatUnits()`。
  - action 调用 core API，设置明确 `commandStatus`，并刷新 `renderRevision`。
  - 不清空待选命令，除非现有交互语义明确要求；如为避免点位命令误触，可只清 pending target commands 并在文档中说明。

- 修改 `ios/RustwarIOS/RustwarIOS/GameHUDView.swift`：
  - 在命令区或 Save/Load/Enemy AI 附近新增两个 text + systemImage 按钮。
  - 保持 44pt 以上点击高度，提供 VoiceOver label / hint。

- 修改 `ios/RustwarIOS/RustwarIOS/BattlefieldScene.swift` 和 `TacticalMapView.swift`：
  - 选中判断应包含 `state.selectedEntityIDs` 和 primary `selectedEntityID`，让多选目标都有高亮。

## 测试要求

在 `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift` 增加 Swift tests，至少覆盖：

- `select(at:)` 仍设置单个 primary selection，并同步 `selectedEntityIDs == [id]`。
- `selectIdlePlayerBuilders()` 只选择己方空闲 Builder，排除已有订单 Builder、敌方 Builder 和非 Builder。
- `selectPlayerCombatUnits()` 只选择己方非 Builder 单位，排除 Builder 和敌方单位。
- 多选集合 JSON round-trip 后保持。
- 批量选择后 `selectedEntityID` 是集合第一个 id，旧 primary command 语义仍有可用目标。
- 目标死亡清理会从 `selectedEntityIDs` 移除消失 id；若 primary 死亡，应切到剩余第一个或 nil。
