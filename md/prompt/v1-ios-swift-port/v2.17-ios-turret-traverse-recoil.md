# v2.17 iOS Turret Traverse And Recoil

## 目标

本轮由主线程直接执行，不调用子 Agent。在 v2.16 hull/weapon heading 分离基础上，把单位武器从每帧瞬移瞄准改为有单位类型差异的最短角转向，并用现有 cooldown 快照驱动短促炮管后坐。继续保持 Rusted Warfare 式俯视 RTS 的清晰机械层级，但所有几何和动态均为 Rustwar 原创实现。

## 实现要求

### Scene 动态时间与最短角转向

- `BattlefieldScene.update(_:)` 计算只供视觉使用的受限帧间 delta；外部手动 `renderNow()` 不得重复推进动画或因 SwiftUI 多次刷新改变转速。
- `unitWeaponHeadings` 保存当前显示方向。当前可见攻击目标提供期望方向后，按 `atan2(sin(delta), cos(delta))` 得到最短角，并按单位类型转速限制单帧角度变化。
- Artillery / Tank / Gunboat 使用较重的慢转速，AA / Scout / Hover 使用较快转速，Builder 介于两者；新增单位首次出现可直接播种期望方向，避免从无意义默认角度长时间扫转。
- 目标消失后短时保持最后 weapon heading，保持时间结束才最短角回归 hull；当前不可见或仅 radar contact 的敌方不得刷新保持时间或提供精确方向。
- map reset、Load/Restart 和 live id filter 必须同步清理保持状态；不得向 `RustwarCore`、JSON 或存档增加 heading/timer 字段。
- `accessibilityReduceMotion` 开启时直接对齐期望方向，不执行连续扫转；不得给每个单位创建常驻 timer、Task 或长期 `SKAction`。

### 炮管后坐与模型层级

- 从 `weaponCooldown` 与单位 `reloadTime` 推导发射后的短后坐窗口；只在 cooldown 接近 reload 起点时产生位移，随后在约 0.2 秒内平滑回位，不改变 Core 冷却或伤害时序。
- `unitBody` 在旋转的 `weaponMount` 内增加 `recoilMount`。炮塔座、炮塔装甲、传感器座保持固定，Tank / AA / Artillery / Gunboat 炮管以及 Builder / Scout / Hover 发射组件进入 recoil mount。
- 后坐沿武器本地负 x 方向，幅度按单位类型和 radius 控制；Artillery 最大、Tank / Gunboat 次之、AA 双管和轻型发射器较小。
- Reduce Motion 不禁用静态机械层级，但后坐必须直接回到零位；现有炮口焰、projectile、beam、impact、烟尘、灼痕、effect/decal 上限和 fog 层级保持。

### 云端战斗证据

- `--rustwar-ci-combat-visual-smoke` 继续使用 v2.16 交叉 Attack 目标和隐藏订单线的固定构图。

- frozen fire tableau 的 source/target 配对继续与 Attack target 一致；炮口、projectile、beam 和 weapon mount 必须保持同一目标方向。
