# v1.45 / iOS native multi-Builder Build Extractor

## Agent A 目标

把原生 iOS 迁移地基中的 Build Extractor 命令从 primary selection 单 Builder 语义升级为多 Builder 协同建造语义，使 Idle Builders 批量选择后可以让所有选中己方 Builder 一起建造同一个新 Extractor。

本轮只推进 Build Extractor，不改 Web 原型，不扩大到 Build Turret / Build Land Factory / 建造队列 / Shift queue / 拖拽框选 / 完整 Web 建造菜单。

## 背景

当前 `GameEngine.issueBuildExtractor(on:)` 只读取 `state.selectedEntityID`，因此多选 Builder 后只有 primary Builder 会创建并建造 Extractor。v1.38 已提供 `selectedEntityIDs` 多选集合，v1.43/v1.44 已经用 `selectedPlayerBuilderIndices()` 扩展 Repair 和 Reclaim。本轮应沿用同一 helper。

`UnitOrder.build(targetID:)` 和 `updateBuildOrder(unitIndex:targetID:deltaTime:)` 已经能让多个 Builder 对同一个未完成建筑推进建造进度；因此本轮重点是下令语义、UI 状态文案和测试覆盖。

## 实现范围

### Swift Core

修改 `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`：

- `issueBuildExtractor(on:)` 必须先使用 `selectedCommandEntityIDs()` 判断是否存在可用选择，保持无选择时返回 `.noSelection`。
- 使用 `selectedPlayerBuilderIndices()` 过滤当前选择中的己方 Builder。
- 选择集合存在但没有己方 Builder 时返回 `.selectedEntityCannotBuild`。
- 资源点目标仍按现有规则校验：缺失返回 `.invalidBuildTarget`，已占用或已有存活 Extractor 返回 `.occupiedResourceNode`。
- 金属只扣一次，只创建一个未完成 Extractor，只 claim 一个资源点。
- 新建 Extractor 后，对所有选中己方 Builder 写入同一个 `.build(targetID:)`，目标 id 是新建 Extractor id。
- 保持旧单选 primary fallback 兼容。
- 不改变 `UnitOrder.build` 数据结构、Build 推进逻辑、125 范围、建造速率、资源点 claim/release、存档形状、红方 AI 建造或 point-building 建造。

### iOS App

修改 `ios/RustwarIOS/RustwarIOS/GameController.swift`：

- `canIssueBuildExtractor` 改为使用当前多选集合中的己方 Builder。
- `toggleBuildExtractorCommand()` 的等待态文案在多选时显示 Builder 数量，例如 `Extractor resource for 3 builders`。
- `statusText(forBuildExtractor:)` 在 `.issued` 时根据实际收到 `.build(targetID:)` 的选中己方 Builder 数量返回单/多 Builder 反馈，例如 `Extractor build started by 3 builders`。
- 主战场 tap 和战术小地图资源点命中继续复用现有 `handleBuilderTargetCommand(at:)` 和 `engine.issueBuildExtractor(on:)`，不新增 UI 分支。

### Tests

修改 `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift`：

- 增加多选 Builder group 下达 Build Extractor 后，只创建一个 Extractor、只扣一次金属、所有选中己方 Builder 均获得同一个 `.build(targetID:)` 的测试。
- 覆盖混合选择中包含不存在 ID、敌方 Builder、非 Builder 单位或建筑 ID 时，只命令有效己方 Builder 并返回 `.issued`。
- 覆盖选择集合存在但没有己方 Builder 时返回 `.selectedEntityCannotBuild`。
- 覆盖多 Builder 协同推进同一个 Extractor 的建造进度，确认进度比单 Builder 更快、完成后所有参与 Builder 的 build order 清除。
- 补充 Stop 对多选 Build Extractor 的清理测试，确保 `issueStop()` 只清除选中 Builder 的 Build 订单，不影响未选中 Builder。
- 保持既有单 Builder Build Extractor、资源点 claim、收入门控、移动入范围、建筑被摧毁释放资源点和 JSON 往返测试通过。
