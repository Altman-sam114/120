# v1.85 iOS Extractor T2 Upgrade

## Agent A Prompt

Role: Agent B implements this prompt on `main`, then Agent C validates the latest `origin/main` GitHub Actions artifact.

## Goal

Add the next native Swift/iOS building-upgrade slice: player-owned Extractors can start, progress, complete, and cancel a T2 economy upgrade. This moves native iOS closer to the Web prototype, where Extractors support upgrades that increase income, HP, and vision.

## Non-goals

- Do not change Web Canvas behavior in `app.js`.
- Do not add Extractor T3.
- Do not add Resource Fabricator, factory upgrades, turret upgrades, or generic upgrade picker UI.
- Do not add enemy AI Extractor upgrades.
- Do not change Radar Station upgrade/cancel behavior except where generic upgrade text or shared helpers require it.
- Do not use `WKWebView` or web wrapping.

## Required implementation

- Extend the Swift building upgrade definition so an upgrade can override building income.
- Add Extractor T2 definition using the Web T2 values:
  - 650 metal
  - 20 seconds
  - 760 HP
  - 290 vision
  - 18 income
- Make economy income read the effective upgraded building definition for completed buildings.
- Reuse existing `GameEngine.queueBuildingUpgrade()` and `GameEngine.cancelBuildingUpgrade()` semantics:
  - exactly one selected, completed, living, player-owned Extractor can queue T2 if affordable
  - queued upgrade deducts metal and sets `upgradeProgress`
  - update completes the upgrade and raises `upgradeLevel`, max HP, current HP by gained max HP, vision, and income
  - cancel clears `upgradeProgress` and refunds remaining upgrade metal
  - invalid, enemy, incomplete, multi-selection, already queued, fully upgraded, and insufficient-metal paths reject correctly
- Add iOS HUD support:
  - Show `Upgrade Extractor` only when a selected completed player Extractor has an available upgrade and enough metal.
  - Show `Cancel Upgrade` only when the selected completed player Extractor has active upgrade progress.
  - Show a concise Extractor upgrade summary for cost, progress, and completed level.
  - Use existing SwiftUI button patterns, labels, and VoiceOver label/hint.
  - Do not add a keyboard shortcut that conflicts with existing production/build shortcuts.
- Existing SpriteKit upgrade progress bar should continue to render from `BuildingSnapshot.upgradeProgress`.

## Required tests

Add Swift core tests for:

- Extractor T2 definition values and effective definition before/after upgrade.
- `GameState.income(for:)` uses upgraded Extractor income after completion.
- Active Extractor upgrade queues, consumes metal, progresses, completes, clears progress, updates HP/max HP, vision, and income.
- Cancelling an Extractor upgrade refunds remaining metal, clears progress, preserves `upgradeLevel`, HP, max HP, rally, node id, selection, selected ids, and control groups, and does not complete after later updates.
- Missing selection, multiple selection, enemy building, incomplete building, non-upgradeable building, fully upgraded Extractor, already queued upgrade, and insufficient metal reject correctly.
