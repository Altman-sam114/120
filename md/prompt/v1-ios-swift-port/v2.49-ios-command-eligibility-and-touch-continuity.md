# v2.49 iOS command eligibility and touch continuity

## 版本与基线

- 版本：`v2.49`
- 基线：`70df9017849f9bf44e9afb748a8586aae16d236f`（`origin/main`）
- 上一轮：v2.48 已通过 `Rustwar CI Results` artifact，直触控预览、无效目标重试和 combat smoke 已验收。

## 本轮目标

把“可执行命令资格”统一到原生 iOS RTS 的 Core、GameController、直接点按和 HUD：

1. Builder 只能参与移动/建造/维修/回收等自身支持的命令，不能被错误地当作攻击单位派发 Attack 或 Attack-Move。
2. 混合选择中的作战单位仍可攻击或 Attack-Move；Builder 不应收到攻击订单，也不应让攻击预览被 Builder 的 primary selection 隐藏。
3. Builder-only 的直接空地操作应呈现并提交普通 Move；combat selection 才呈现并提交 Attack-Move；敌方目标只有存在作战单位时才进入直接 Attack。
4. HUD 的按钮可见性、pending 状态文案、BattlefieldTouchPreview 与最终 Core 命令结果保持一致。
5. 保持 v2.48 的触控取消/多指/地图 reset 生命周期；只吸收本轮触控审计中明确、最小且不改变既有手势 owner 的修复。

## 非目标

- 不改变 Web 版、Swift 存档 schema、AI、经济、武器伤害/射程、地图或生产规则。
- 不引入 WKWebView、第三方依赖、构建工具或网络运行时依赖。
- 不重写 BattlefieldView 手势体系，不把静态 smoke 截图描述成真实触控自动化证据。
- 不扩大生产 UI 或战斗素材重做；若审计建议与本轮命令资格无关，记录为下一轮候选。

## 建议实现边界

- Core：`swift/RustwarCore/Sources/RustwarCore/GameEngine.swift` 使用已有的 combat-unit 资格辅助函数限制 `issueAttack` / `issueAttackMove`；保留 `issueMove` 对 Builder 的支持；在 `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift` 覆盖 Builder-only 拒绝与 Builder+combat 混合选择隔离。
- iOS：`ios/RustwarIOS/RustwarIOS/GameController.swift` 让 `canIssueAttack`、`canIssueAttackMove`、直接点按分支、预览 intent 和文案使用同一 combat selection 资格；Builder-only 空地直触控走 Move。只在必要处调整 `BattlefieldView.swift` 的生命周期清理，不改变 owner 转移规则。
- 文档：同步 `README.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和 `update_log.md`，说明 Builder/Combat 命令边界与本轮验收限制。

## 必须保持的旧行为

- `Move`、`Stop`、建造、Repair、Reclaim、Rally、选择/框选、控制编队和 v2.48 目标重试继续可用。
- 选择、迷雾可见性、命中半径、重复点按和多指取消语义不能被命令资格修复破坏。
- 混合选择仍可用 Move；攻击命令只影响有攻击射程的存活己方单位。
