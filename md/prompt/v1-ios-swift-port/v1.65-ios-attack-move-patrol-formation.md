# v1.65 / iOS native attack-move and patrol formation targets

## 角色

你是 Agent B，负责在 `main` 上实现本轮 v1.65。开始前必须阅读 `README.md`、`AGENTS.md`、`update_log.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和本提示词，并先执行 `git fetch origin`、`git switch main`、`git pull --ff-only origin main`、`git status --short --branch`。

## 目标

把 v1.64 的多单位 Move 方阵落点扩展到原生 Swift core 的多单位 Attack-Move 和 Patrol 命令，减少多选部队在行军攻击或巡逻端点处重叠。

- 单选 Attack-Move / Patrol 保持原行为：目标点只做地图边界 clamp。
- 多选 Attack-Move 根据选中己方单位生成稳定方阵目的地，每个单位仍使用 `UnitOrder.attackMove(destination:)`。
- 多选 Patrol 根据选中己方单位生成稳定方阵巡逻端点，每个单位仍以各自当前位置作为 `origin`。
- 方阵落点应复用 v1.64 `moveFormationTargets` 的排序、间距和地图 clamp 语义，避免复制两套算法。
- iOS 现有 Attack Move / Patrol 按钮、战术小地图点位命令和外接键盘 A/G 入口都应通过 `GameEngine.issueAttackMove(to:)` / `GameEngine.issuePatrol(to:)` 自动复用，不需要新增 UI。

## 非目标

- 不修改 Web `app.js`。
- 不实现完整寻路、碰撞避让、队列命令、Shift 追加队列、阵型朝向、Guard/Repair/Reclaim/Build 队形、运输语义或 UI 自动化。
- 不新增 Swift core 存档字段、命令类型、iOS target、第三方依赖或构建链。
- 不改变 Attack、Move、Guard、Repair、Reclaim、Build、Stop、生产、AI、选择、控制编队或小地图交互语义。
- 不用 `WKWebView` 或网页包装。

## 实现建议

- `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`
  - 保留 `issueAttackMove(to:)` 和 `issuePatrol(to:)` 的对外 API。
  - 复用 v1.64 的 private `moveFormationTargets(for:around:)` helper，必要时改名为更通用的 `formationTargets(for:around:)`。
  - `issueAttackMove(to:)`：
    - 0 个合法单位：沿用旧错误结果。
    - 1 个合法单位：写入精确 clamp 目标。
    - 多个合法单位：逐个写入方阵目标。
  - `issuePatrol(to:)`：
    - 0 个合法单位：沿用旧错误结果。
    - 1 个合法单位：写入精确 clamp 端点。
    - 多个合法单位：逐个写入方阵端点，`origin` 继续使用该单位当前 `position`。
  - 不改变 Attack-Move / Patrol 自动索敌、攻击姿态、抵达清除或巡逻往返逻辑。
- `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift`
  - 更新旧的多单位 Attack-Move / Patrol 测试，不再断言所有单位目标完全相同。
  - 增加或调整测试覆盖：
    - 多选 Attack-Move 会给每个选中己方单位分配分散目的地，平均落点接近玩家目标点。
    - 多选 Patrol 会给每个选中己方单位分配分散端点，origin 仍等于各自当前位置。
    - 单选 Attack-Move / Patrol 仍使用精确目的地。
    - 地图边缘多选 Attack-Move / Patrol 的落点被 clamp 到地图内。
    - Same Type、附近同类、控制编队或区域选择后复用 Attack-Move / Patrol 的旧覆盖若存在，应改为断言队形分散。

## 验收标准

- 选择多个己方作战单位后执行 Attack-Move，不再所有单位共享同一 `WorldPoint`。
- 选择多个己方作战单位后执行 Patrol，不再所有单位共享同一端点，且每个巡逻订单 origin 仍是单位各自当前位置。
- 单选 Attack-Move、单选 Patrol、无选择、只选建筑/敌军等旧结果保持不变。
- iOS 现有 Attack Move / Patrol 入口无需新增按钮即可复用新 core 行为。
