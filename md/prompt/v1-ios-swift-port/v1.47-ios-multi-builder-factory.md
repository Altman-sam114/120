# v1.47 / iOS native multi-Builder Build Land Factory

## Agent A prompt for Agent B

### Goal

Move native iOS Land Factory construction from primary Builder semantics to selected Builder group semantics, matching the v1.45 Build Extractor and v1.46 Build Turret behavior:

- If at least one selected player Builder is present, `issueBuildLandFactory(at:)` must accept the command even when the primary selected entity is a building, enemy, missing id, or non-Builder unit.
- The command must create exactly one incomplete Land Factory, deduct the Land Factory metal cost exactly once, and assign every selected player Builder the same `.build(targetID:)` order.
- Multiple selected Builders must cooperatively advance that one Land Factory's build progress faster, and completion must clear all Builders assigned to the completed target.
- iOS HUD availability and status text must reflect selected Builder groups.

### Non-goals

- Do not modify Web runtime files (`index.html`, `styles.css`, `app.js`) except for required syntax checks.
- Do not change Extractor or Turret semantics from v1.45 / v1.46.
- Do not change Land Factory cost, build time, production list, rally, repeat, queue, enemy AI construction, save schema, or terrain/overlap validation.
- Do not add new dependencies, build tools, backends, UIKit wrappers, or `WKWebView`.

### Implementation notes

- In `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`, use the v1.46 `issueBuildTurret(at:)` pattern:
  - Guard `!selectedCommandEntityIDs().isEmpty`.
  - Gather `selectedPlayerBuilderIndices()`.
  - Reject with `.selectedEntityCannotBuild` if no selected player Builder exists.
  - Validate `canPlaceBuilding(.landFactory, at:)` and metal before mutating state.
  - Call `startPointBuildingBuild(.landFactory, builderIndex: builderIndices[0], position: position)` once, then assign `.build(targetID:)` to every selected player Builder.
- Keep `startPointBuildingBuild` returning the new building id, preserving existing enemy AI callers.
- Keep `clearBuildOrders(targetID:)` as the completion cleanup mechanism.
- In `ios/RustwarIOS/RustwarIOS/GameController.swift`:
  - Change `canIssueBuildFactory` to use `!selectedPlayerBuilders.isEmpty`.
  - Mirror Turret pending text style: `Factory position for N builders` when N > 1.
  - On success, report `Factory build started by N builders` when more than one selected Builder actually received a Land Factory build order.
  - Reuse `pointBuildOrderIssuedCount(type:position:)` and `clampedMapPoint(_:)` from v1.46.
- `GameHUDView.swift` should only need changes if the existing `controller.canIssueBuildFactory` binding is insufficient.

### Tests

Update `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift` with focused coverage:

- Multi-Builder Land Factory command creates one Factory, deducts one Factory cost, and gives both selected Builders the same target id.
- Mixed invalid selection with one selected player Builder succeeds and only that Builder receives the order.
- Selection without any player Builder returns `.selectedEntityCannotBuild`.
- Invalid placement or insufficient metal does not overwrite an existing selected Builder order.
- Multiple Builders near the Factory progress build faster than one Builder and all shared build orders clear on completion.
- Stop only clears selected Builders in a shared Factory build order and leaves an unselected Builder's order intact.
- Existing completion behavior still enables production only after `buildProgress == 1`.
