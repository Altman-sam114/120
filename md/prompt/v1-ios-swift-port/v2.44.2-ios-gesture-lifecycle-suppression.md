# v2.44.2 iOS gesture lifecycle suppression fix

## 背景

v2.44 增加了单指 pan、长按上下文和地图重置之间的手势互斥，但 SwiftUI 手势结束/取消顺序可能留下旧的 pan 或 long-press 状态。若取消回调在没有活动手势时重新写入 tap suppression，也会吞掉之后一次合法 tap；若活动手势未完整清理，则可能误发长按或短 tap。

## 目标

1. 让 BattlefieldView 的单指 pan、context location/long-press 和地图重置拥有一致的开始、结束、取消生命周期；任一结束或取消都清理对应位置、generation 和 active 标志。
2. 保持 pan 与 long-press 互斥：已确认 pan 时不得触发上下文命令，静止单指 tap 仍可触发长按或普通选择。
3. 调整取消路径的 tap suppression：只有在取消时确实存在活动 pan、框选、多指序列或 context 手势时才建立短 suppression；没有活动手势时不得凭空延长或残留 suppression。
4. 保持多指框选/捏合、pending command、Replace/Add、建筑聚焦和已有 controller/Core 合同不变。

## 非目标

- 不修改 `RustwarCore`、`GameController` 的选择/命令 API、状态模型、JSON、存档、生产、升级、AI 或战斗数值。
- 不改变多指意图分类规则、触控目标半径、地图相机速度、长按时长或 pan 阈值，除非为清理生命周期所必需。
- 不新增 UIKit recognizer、timer、Task、随机数、texture、shader、第三方依赖、教程 UI 或新的手势状态源。
- 不运行本地测试、格式检查、Swift/Xcode build、Simulator、Preview、截图或 `git diff --check`。

## 修改边界

- 首选只修改 `ios/RustwarIOS/RustwarIOS/BattlefieldView.swift`，复用现有状态和 helper；若编译所需确实超出该文件，先报告 `needs-confirm`，不得自行扩大范围。
- 保留现有 `cancelSelectionGestures()`、多指 reset、map render revision 取消入口和 `controller` 命令调用，不复制第二套手势状态。
- 不修改已有视觉模型、HUD、Tactical Map、Core tests 或文档（本提示词除外）。
