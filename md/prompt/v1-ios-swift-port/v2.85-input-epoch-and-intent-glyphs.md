# v2.85 原生 iOS 输入 epoch 隔离与意图 glyph

## 轮次定位

- 版本：`v2.85`
- 基线：`origin/main` 的 v2.84 最终文档 commit `afbfda7da70dcdb842e149fd8704b9b66c94af16`
- 目标：继续改善 Rusted Warfare 风格的 iOS RTS 直接点选/发令手感，优先阻断命令或视口变化后迟到的旧触控 callback 串入新状态，并让 pending touch preview 通过几何表达意图。
- 云端规则：本轮只认 `origin/main` 最新完整 SHA 对应的 Actions artifact；本机禁止完整测试、build、typecheck、Simulator、Preview、截图生成、Node/browser smoke、测试脚本和 `git diff --check`。

## 背景与问题

`BattlefieldView` 已在 v2.83 把单指 tap、preview、pan 和 Select Area 收敛到一条零距离 `DragGesture`，TouchSequenceOwner 也有旧 ID quarantine 与 terminal barrier。但 SwiftUI 的旧 gesture callback 不携带本项目自定义的 epoch：当用户切换 Replace/Add、进入/取消 pending command、改变 viewport 或离开战场时，旧 release/changed callback 可能在新的 pending state 下继续执行。已知 seed 后只凭未知触点 ID 不能绝对区分旧 callback 与新触点，因此本轮目标是增加可证明的状态边界，不伪造绝对识别能力。

## 目标

1. 在 `GameController` 增加只读 `private(set)` 的 `battlefieldInputEpoch`，它只属于 iOS 输入生命周期，不进入 `GameState`、Core、save payload 或 JSON。
2. 以下状态变化必须推进 epoch：
   - `clearPendingTargetCommands()` 执行前清理全部等待命令；
   - Replace/Add `selectionMutation` 发生变化；
   - `updateBattlefieldViewportSize(_:)` 接收到有效且不同的尺寸。
   所有等待命令 toggle 的取消路径必须复用统一清理方法，不能只写单个 boolean。
3. `BattlefieldView` 在 fresh touch seed 时保存当前 epoch；context preview/tap、单指 12pt 后 pan/Select Area、long press、pinch、多指框选结束和最终 semantic commit 必须拒绝 epoch 不匹配的 callback。尺寸变化、epoch 变化、view disappear 和既有 map/render cleanup 要清理 owner/lease/preview/overlay/callback 状态。
4. `TacticalMapView` 使用同一个 epoch 门控 map tap、18pt camera drag 和长按 context；保留现有 callback generation、pending marker hit radius、fog/radar、相机和 target 命令语义。
5. `BattlefieldScene.drawTouchPreview` 保留既有固定屏幕尺寸 halo/reticle、颜色和 invalid slash，但将中心 glyph 按 intent 映射为已有 `commandConfirmationPath`：
   - `.move`、`.attackMove`、`.attack`、`.rally`、`.guardTarget`、`.repair`、`.build`、`.reclaim` 使用对应 command geometry；
   - `.select` 与 `.invalid` 使用 corner brackets；`.invalid` 仍额外显示红色 slash。
   glyph 不得写回 Core，也不得改变正式 command confirmation 生命周期。

## 非目标与证据边界

- 不在本轮处理 `TacticalCommandDock` 的高频二级操作首屏可达性、compact production card 两行 metrics 或 Tactical Map marker 绘制层级；这些由只读审查列为下一轮独立视觉验收项。
- 不声称 epoch 可以识别所有旧 SwiftUI callback。若旧 callback seed 时没有可用的本项目 epoch，仍需依靠 owner/generation/quarantine，真实设备顺序需后续 XCUITest/真机证据。
- 固定 production/combat PNG 预计看不到 pending touch preview glyph；它只能证明静态 HUD、模型、武器、selection/HP、阵营标记、terminal/impact、Tactical Map 和状态栏没有回退，不能证明动态 preview、触控手感、手指遮挡、VoiceOver、Dynamic Type 或长局帧率。
