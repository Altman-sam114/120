# v1.6 / iOS native map switch and restart

## Agent A brief

Version: `v1.6`

Goal: add native iOS map switching and current-map restart controls so the SwiftUI/SpriteKit app can load Coast, Islands, or Lava from the existing `RustwarCore` map presets without using Web content.

## Background

- Web Rustwar already supports Coast / Islands / Lava map switching.
- `RustwarCore` already exposes `MapID: CaseIterable, Identifiable` and `MapPreset.preset(for:)` with labels, camera snapshots, resources, and initial unit/building layouts.
- `BattlefieldScene` already tracks `renderedMapID` and redraws terrain/resources when `engine.state.map.id` changes.
- v1.5 added native pause/speed controls; v1.6 should preserve them while adding map selection and restart.

## Scope

Expected code touch points:

- `ios/RustwarIOS/RustwarIOS/GameController.swift`
- `ios/RustwarIOS/RustwarIOS/GameHUDView.swift`
- `ios/RustwarIOS/RustwarIOS/BattlefieldScene.swift`

Expected docs:

- `README.md`
- `md/flow/flow.md`
- `md/flow/flowchart.md`
- `md/test/test.md`
- `update_log.md`

Do not modify `index.html`, `styles.css`, `app.js`, or CI workflow. Avoid Swift core changes unless a compile blocker proves one is necessary.

## Functional requirements

1. Add current map state to `GameController`, initialized from the constructor `mapID`.
2. Add a native `loadMap(_:)` or equivalent method that:
   - rebuilds `GameEngine(mapID:)`;
   - resets `CameraState` from the selected map preset camera;
   - clears pending Move/Attack targeting modes;
   - clears transient command status or sets a concise loaded-map status;
   - increments `renderRevision`.
3. Add `restartBattle()` or equivalent that reloads the currently selected map with the same state reset behavior.
4. Preserve v1.5 pause/speed settings across map loads unless there is a concrete reason not to; document the chosen behavior in code/docs.
5. Add HUD controls:
   - a native map picker/menu using the existing `MapID.allCases` and `MapPreset.preset(for:).label`;
   - a Restart button with a system image and accessible text label;
   - controls must maintain 44 pt minimum tap targets and avoid overlapping existing Pause/Reset/Move/Attack/production controls.
6. Ensure switching to each map updates:
   - terrain and resource rendering;
   - initial player/enemy units and buildings;
   - resource/economy HUD;
   - selected summary and command modes.

## Non-goals

- No Web behavior change.
- No `WKWebView`.
- No save/load, minimap, campaign mode, sandbox, fog, stop command, rally command, production cancel, or extra units.
- No manual browser regression unless the human asks.
- No new external dependency or build system.

## SwiftUI guidance

- Keep shared state in `@MainActor @Observable GameController`.
- Use `@Bindable` only where the view needs to bind controls to controller state.
- Prefer native `Picker` / `Menu` / `Button(_:systemImage:action:)` controls with text labels for VoiceOver.
- Preserve 44 pt hit targets.
- Keep view logic light; map loading rules belong in `GameController`.
