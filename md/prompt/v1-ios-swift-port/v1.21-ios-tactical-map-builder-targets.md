# v1.21 / iOS tactical map builder targets

## Agent B 任务

在 v1.20 战术小地图点位命令基础上，继续补一个小步 Web 迷你地图 parity：当 iOS 正在等待 Reclaim 或 Build Extractor 目标时，允许点按战术小地图，通过现有 `GameState` 命中 API 寻找残骸或资源点并调用既有 `RustwarCore` 命令。

## 背景依据

- v1.20 已让小地图在 Move / Attack Move / Patrol / Rally 等待态下直接下达点位命令。
- `GameState.wreckTarget(at:)` 和 `GameState.resourceTarget(at:)` 已存在，主战场 tap 已用它们处理 Reclaim / Build Extractor。
- Web 版迷你地图可作为回收、建造等远距离 RTS 操作入口；原生 iOS 可先补最安全的 Builder 目标类命令。

## 目标

1. 在 `GameController.handleTacticalMapTap(at:)` 中新增小地图目标命令分派：
   - Reclaim 等待态：用 `engine.state.wreckTarget(at:)` 命中残骸；命中则 `engine.issueReclaim(wreckID:)`，否则返回现有 invalid 状态。
   - Build Extractor 等待态：用 `engine.state.resourceTarget(at:)` 命中资源点；命中则 `engine.issueBuildExtractor(on:)`，否则返回现有 invalid 状态。
2. 命令执行后清除对应等待态并刷新 `renderRevision`。
3. 没有可消费命令时，小地图仍保持 v1.20 行为：无 pending 则居中相机，Move / Attack Move / Patrol / Rally 等点位命令仍优先处理。
4. 不修改 `RustwarCore` 命中半径、经济规则、建造规则或残骸规则。
5. 更新 README、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和 `update_log.md`。

## 非目标

- 不让小地图处理 Attack / Guard / Repair 这类单位/建筑精确实体命令。
- 不新增小地图放大镜、目标吸附 UI 或二次确认。
- 不新增 iOS test target。
- 不改变 Web `index.html` / `app.js` 直接浏览器运行链路。
- 不引入第三方依赖，不使用 `WKWebView`。
