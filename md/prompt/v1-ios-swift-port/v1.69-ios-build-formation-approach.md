# v1.69 / iOS native build formation approach

## 角色

你是 Agent B，负责在 `main` 上实现本轮 v1.69。开始前必须阅读 `README.md`、`AGENTS.md`、`update_log.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和本提示词，并先执行 `git fetch origin`、`git switch main`、`git pull --ff-only origin main`、`git status --short --branch`。

## 目标

把 v1.67 Repair、v1.68 Reclaim 的“多 Builder 围绕目标分散接近”继续扩展到原生 Swift core 的多 Builder Build 执行阶段：多个 Builder 协同建造同一个未完成建筑且仍在建造范围外时，应分散靠近建筑周边，而不是全部朝建筑中心叠在一起。

- 保持 `UnitOrder.build(targetID:)` 存档形状和 `GameEngine.issueBuildExtractor(on:)` / `issueBuildTurret(at:)` / `issueBuildLandFactory(at:)` 对外 API 不变。
- 单 Builder Build 保持原行为：距离超过建造范围时朝建筑中心靠近，进入范围后推进建造。
- 多 Builder Build 同一建筑时，在 `updateBuildOrder` 中动态计算每个 Builder 围绕建筑的稳定接近点；Builder 进入建造范围后仍按既有协同建造速率推进同一目标。
- 接近点应按 Builder 当前状态中的稳定顺序生成，围绕建筑中心分散，并 clamp 到地图内。
- iOS 现有 Build Extractor / Turret / Factory 按钮、主战场 tap、长按资源点或空地点、战术小地图点位/资源点目标和外接键盘入口都应自然复用，不新增 UI。

## 非目标

- 不修改 Web `app.js`。
- 不修改 `UnitOrder.build` 的 Codable 形状，不新增存档字段或命令类型。
- 不改变 Build Extractor / Turret / Land Factory 的合法性、资源扣除、目标创建、资源点认领、建造范围、建造速度、完成回血、订单清理、Stop、失败不覆盖旧订单等既有语义。
- 不实现完整寻路、碰撞避让、动态阵型朝向、Shift 队列、建筑取消/退款、沙盒建造编辑或完整 Web parity。
- 不用 `WKWebView` 或网页包装。

## 实现建议

- `swift/RustwarCore/Sources/RustwarCore/GameEngine.swift`
  - 保留现有三个 Build 下令 API 和 `UnitOrder.build(targetID:)` 不变。
  - 增加 private helper，例如 `buildApproachPoint(for:building:)`，或抽出 Repair / Reclaim / Build 共用 support formation helper；只在真实降低重复且不扩大范围时抽象。
  - helper 在更新时查找所有当前正在 `.build(targetID:)` 且可建造同一未完成建筑的存活己方 Builder。只有 1 个 Builder 时返回建筑中心以保持旧行为。
  - 多个 Builder 时，复用或仿照 `formationTargets(for:around:)` 的排序/间距，生成建筑周边分散点；点位应至少位于建筑边缘外，并在 `builderBuildRange` 内，使 Builder 到位后可以执行建造。
  - `updateBuildOrder` 距离判断仍以 Builder 到建筑中心是否超过 `builderBuildRange` 为准；超过时向该 Builder 的分散接近点移动，进入范围后执行原建造进度逻辑。
- `swift/RustwarCore/Tests/RustwarCoreTests/RustwarCoreTests.swift`
  - 增加测试覆盖：多 Builder Build Extractor / Turret / Land Factory 同一未完成建筑时，远距更新后多个 Builder 的位置不再完全相同。
  - 保留或补充单 Builder Build 仍朝建筑中心靠近的断言。
  - 旧语义仍应通过：单次扣费、协同加速、完成订单清理、非法地形/资源不足/无 Builder 拒绝、混合选择跳过无效对象、Stop 清除选中建造订单等。

## 验收标准

- 选择多个己方 Builder 建造同一个 Extractor / Turret / Land Factory 时，远距 Builder 不再全部朝同一个建筑中心点移动。
- 单 Builder Build、无选择、非 Builder、敌方或建筑选择、资源不足、非法位置、资源点已占用、完成清理等旧结果保持不变。
- 不改变 `GameState` JSON / `UnitOrder` Codable 兼容性。
- iOS 现有建造入口无需新增按钮即可复用新 core 行为。
