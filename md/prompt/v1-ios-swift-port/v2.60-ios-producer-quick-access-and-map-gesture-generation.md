# v2.60 iOS producer quick access and Tactical Map gesture generation

## 轮次目标

基于 v2.59.1 云端 artifact 的真实 `ios-home.png`，继续把原生 iOS RTS 的建筑操作向 Rusted Warfare 的“点开建筑就能马上生产/升级”靠拢，并收紧战术小地图长按在取消或迟到回调时的触控生命周期。当前最高优先级是：横屏 compact dock 选中 Land Factory 后，`FACTORY TECH` 不再占满首屏高度，首排生产单位按钮完整可见；其次是旧长按回调不能抑制下一次独立 tap、拖动或等待目标命令。

## 实现要求

### 1. compact producer quick access

- `TacticalProductionSectionView` 保持既有 section 顺序和所有 action/disabled gate，但给 `TacticalFactoryTechView` 增加 compact presentation 分支。
- 在 `columns == 1` 且不是 accessibility Dynamic Type 时，Factory Tech 使用单行或近似单行的高密度卡：图标、`T2`/倍率、`T2 READY`/`UPGRADING`/`MAX TECH` 状态和可用的升级/取消控制仍可读；卡片不再使用完整 regular 版的大块纵向布局。
- 升级按钮、progress、cancel、快捷键、VoiceOver label/value/hint 和 `TacticalHUDTheme.controlMinimumHeight` 的 44pt 最小触控面积必须保留。Accessibility Dynamic Type 继续使用完整自然换行布局。
- `NOW / QUEUE / UPGRADE` 摘要、生产按钮、队列、Cancel/Repeat/Rally action 不得改变。首排至少两个生产按钮应在云端横屏 production fixture 首屏完整可见且不与底部裁切重叠。
- 遵循现代 SwiftUI：不用 `AnyView`、UIKit color、无值 `.animation`、`onTapGesture` 或固定屏幕尺寸；使用 `foregroundStyle`、`clipShape` 和现有 design tokens。

### 2. Tactical Map stale context generation

- `TacticalMapView` 为地图 DragGesture/long-press callback 引入视图捕获的 generation gate，仿照 `BattlefieldView` 的 callback generation 思路。
- 新独立触摸开始时使旧 long-press callback 失效；gesture state 取消、map gesture end 和正常长按处理后清理当前 context location/recognition 状态。
- 迟到旧 long-press callback 不得设置当前序列的 context suppression，也不得阻断下一次单指普通 tap、相机拖动或 pending target tap。
- 保持无等待态 map tap 居中、无等待态拖动相机、pending target 命中半径、context 命令派发、visibility/fog、VoiceOver 与 Core/command owner 不变。

## 非目标与风险边界

- 不新增 XCUITest，不改变 Core 订单、战斗数值、生产队列或存档 schema。
- 云端静态 smoke 不能证明真实 SwiftUI 回调排序、VoiceOver、Dynamic Type 全档位或真机手感；artifact 中必须保留这些 residual risks。
- 当前仓库制度禁止本机 test/build/Simulator/Preview/浏览器/截图和 `git diff --check`；只能读取状态、编辑、commit、push，并以最新 Actions artifact 验收。

## 云端验收

Agent B 必须确认 `main`、`origin/main`、提交范围只含本轮文件，提交信息以 `v2.60` 开头并直接 `git push origin main`。禁止本地测试和 build。

Agent C 只能下载最新 `origin/main` SHA 对应的 `Rustwar CI Results` artifact 到 `/private/tmp/rustwar-c-review-<run_id>/`，核对 manifest 的 `branch=main`、完整 `commitSha`、run id、attempt、v1.2、Xcode 26.5/iOS SDK 26.5/iPhone 17 Pro、JUnit、主日志、失败摘要、repo state、toolchain、双架构 build、production/combat 双启动、横屏归一化和两份 PNG probe。

人工查看 `ios-home.png` 时必须确认：选中 Land Factory 后 `Production`、NOW/QUEUE/UPGRADE、紧凑 `FACTORY TECH`、至少首排两个生产入口均在边框内，生产卡不被底部裁切；`ios-combat.png` 的战场、单位模型、弹道、攻击等待状态、Tactical Map 和 command dock 无结构性回退。通过后再进入下一轮；失败则在 `main` 追加最小修复 commit 并重新验收。
