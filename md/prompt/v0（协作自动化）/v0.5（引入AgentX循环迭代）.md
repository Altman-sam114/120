# v0.5 / 引入 Agent X 循环迭代文档基线

## 版本分配依据

v0.5 属于协作自动化文档阶段，目标是在既有 Agent A/B/C、`main` 直推、GitHub Actions artifact 和 Agent C 复判制度之上，为未来 Agent X 主控循环建立文档基线。

## 背景

当前项目已经具备单轮 Agent A -> Agent B -> Agent C 工作流：

- Agent A 负责分析目标并写版本化提示词。
- Agent B 负责实现、本地轻量检查、提交并 push 到 `origin/main`。
- Agent C 负责下载最新 GitHub Actions artifact，核对 manifest、JUnit、日志和失败摘要。

未来需要新增 Agent X，用于接收人工总目标 X，拆分多个轮次，并循环调度 A/B/C。v0.5 只做文档和流程准备，不启动真实循环。

## 目标

- 在 `AGENTS.md` 增加 Agent X 召唤、职责、循环边界、停止条件和最终回复格式。
- 在 `md/flow/flow.md` 增加 Agent X 主控循环说明。
- 在 `md/flow/flowchart.md` 更新 Mermaid 图，表达人工总目标、Agent X 拆轮、Agent A 写提示词、Agent B 实现并 push、GitHub Actions artifact、Agent C 验收和 Agent X 判断。
- 在 `md/test/test.md` 增加 Agent X 循环验证规则和测试数据 / 下载容量限制。
- 在 `md/prompt/README.md` 增加 Agent X 轮次提示词管理规则。
- 在 `README.md` 简短补充 `agentx:` 协作说明。
- 在 `update_log.md` 记录 v0.5。

## 非目标

- 不启动真实 Agent X 循环。
- 不修改 Web、Swift、iOS 源码或 Xcode project。
- 不修改 `.github/workflows/ci-results.yml`。
- 不新增测试 target。
- 不创建 PR。
- 不切换分支。
- 不 push，除非人工明确要求。

## 当前架构依据

- Web 原型仍以 `index.html`、`styles.css`、`app.js` 为运行入口和核心。
- 原生迁移路径仍集中在 `swift/RustwarCore/` 和 `ios/RustwarIOS/`。
- 协作验证仍以 Agent B 本地轻量检查、`origin/main` push、GitHub Actions artifact、Agent C 下载复判为准。
- Agent X 只负责未来调度和循环判断，不直接替代 A/B/C。

## 后续 Agent X 使用方式

后续人工可以用 `agentx:`、`x:` 或 `X:` 提供总目标 X。Agent X 必须：

- 拆分轮次目标。
- 要求 Agent A 为每轮写版本化提示词。
- 要求 Agent B 实现、轻量检查、提交并 push 到 `origin/main`。
- 等待 GitHub Actions 生成最新 artifact。
- 要求 Agent C 下载并核对最新 artifact。
- 根据 Agent C 结果判断继续、退回、暂停或完成。

Agent X 不得跳过 Agent C artifact 验收，不得用旧 run、旧 artifact 或本地输出冒充最新云端结果。

## 验收标准

- 所有目标文档都明确支持 Agent X 未来主控循环。
- Mermaid 图代码块闭合，流程包含 Agent X -> A -> B -> C -> Agent X 判断。
- 测试文档明确每轮仍以 Agent B 本地轻量检查 + GitHub Actions artifact + Agent C 下载复判为准。
- `git diff --check` 通过。

## 风险和禁止项

- 禁止把本轮写成已启动 Agent X 自动循环。
- 禁止扩大到源码、App 行为、Swift/iOS 或 workflow 修改。
- 禁止伪造云端 run、artifact、manifest 或 Agent C 验收。
- 禁止默认下载大体积测试数据、模型、历史 artifact 或无关产物。
